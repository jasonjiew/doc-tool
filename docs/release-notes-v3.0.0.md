# 康尚文档工具 v3.0.0

本版把「导入 → 编辑 → 检查 → 出稿 → 交付」主线补齐为可日常使用的研发文档工作流，
并修掉了一批会导致 Word 能力被误判、界面静默失效与运行时崩溃的缺陷。

## 一、新增与增强

- **Word 导入与重导入**：导入结果页集中展示保留/降级事实；重导入差异预览支持按章选择，
  脏章（未保存编辑）默认不参与应用，冲突项逐项说明。
- **批量章节操作**：跨目录复制/移动会重写进出引用，目标冲突自动改名、绝不覆盖；
  名称与章节号中的真实数字不再被误删。
- **资产与引用**：图片引用按磁盘侧同一规则解析，编辑器未保存内容参与缺失校验，
  减少「缺失引用」误报导致的误删/误修。
- **质量工作台**：问题分组、按章预览与应用确定性修正、「暂不处理」个人视图真正生效；
  检查范围/时点与「新增/消失/保留」基线比较接入真实数据。
- **模板与出稿**：模板库浏览与选用、小样试出稿、模板变更映射差异可见。
- **交付与修订**：交付准备、成员成果汇总、两版事实比较与修订说明、接收人离线包
  （zip 或目录）与副本恢复。
- **发布与诊断**：Word 阶段事实（LAST_REPORT）可用于说明「卡在哪一步」。

## 二、关键缺陷修复

1. `scripts/refresh_fields.py` 在工作树中被写成 0 字节，Word 刷新链路整体失效；
   已按补丁意图重建并补回 `LAST_REPORT` 阶段契约。
2. `STAGE_PENDING` 使用未导入，导致 stderr 读线程解析首个阶段标记后即退出，
   保存失败被误报为一般刷新失败。
3. `communicate()` 与后台读线程争抢同一 stderr，阶段/原因标记可能丢失；
   改为只由后台线程读取。
4. `check_word_dispatchable` 的成功分支是不可达死代码，且超时不再强杀挂起探测进程。
5. `check_word_available` 从不回写 `word_dispatchable`，装有 Word 的机器上正式合并、
   `.doc` 转换与 PDF 导出会被拒绝且提示「未知原因」。
6. 5 处真实运行时 `NameError`（`sys`、`QCursor`、`logger`、推导变量 `rel`、`GroupedFixItem`），
   其中差异计算与 lint 修正跳过分支会被静默吞掉。
7. 12 项中危问题：预览暂存目录泄漏、空操作批量移动报成功、目录形式成果包被误判损坏、
   「打开所选项目」只打开第一项、批量对话框堆积等。

完整清单、证据与未解决项见 [改动代码审核与修复报告](product-v3.0.0-code-review-and-fixes.md)。

## 三、版本与兼容

- 应用版本 3.0.0；`installer.iss`、`build.ps1`、GitHub/GitLab CI 版本源已统一
  （发布门禁要求 tag 与四处一致）。
- 项目 schema 保持 2，v1 项目仍可读可写。
- 设置与窗口偏好沿用既有迁移逻辑，旧版本可并存安装。

## 四、已知限制

- 正式合并需要交互式 Windows 会话与 Microsoft Word；无 Word 时请使用诊断构建。
- 仍有 5 项审核记录的未解决项（详见报告第六节），均为诊断/清理类，不影响构建产物正确性。

## 五、安装

- 安装包 `DocTool-Setup-3.0.0.exe` 与免安装包由 CI 在 `v3.0.0` 标签构建后上传为正式资产。
- 默认安装到 `%LOCALAPPDATA%\DocTool`，无需管理员权限，可与内部旧版并存。
