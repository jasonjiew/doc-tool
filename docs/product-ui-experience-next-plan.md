# 下一轮 UI 与交互实施计划

日期：2026-10-02。用户：企业研发文档团队。基准：`2e5be72` 与当时工作树，上一轮 UI 实现包含未提交文件；后续执行必须重新核对实际代码。独立 change：`product-ui-experience-next`，6 批 / 26 项。

## 1. 本轮方向

把现有功能整理成“继续写文档 → 找到章节 → 修改 → 按需要导出 → 找回成果”的日常工作台。优先解决空间、导航、设置和反馈；界面使用既有 Qt 控件、主题与动作，不引入一套新业务引擎。

上一轮主流程、写作默认布局、非模态成果、批量/模块/辅助首用已经实现。读取的旧任务为 19/20，剩余 5.3 是 Windows 缩放/输入法/Word 实机验证，单列保留，不成为本轮全局前置条件。旧任务编号、实现和勾选不重置。

## 3. 页面结构和使用方式

### 首页：优先继续工作

上方显示产品标题与简短说明；主体左侧为“继续工作 / 最近项目”，右侧为“新建文档项目”。最近项目有固定、类型筛选和已有搜索；卡片只显示名称、类型、最近打开时间、当前位置。项目路径和技术指纹进入详情。底部或次级区域保留文档互转与 PDF 工具，仍可拖放直达。

“继续工作”打开最近有效项目并复用既有标签/滚动/草稿恢复，补回光标和阅读偏好。缺失路径可重新定位，取消后可继续打开其他项目；固定项目和移除最近记录只改变个人偏好。空首页直接给“导入 Word”“Markdown 建项”“从规范起步”，各入口调用现有流程。

### 写作工作台：知道在哪，能回到刚才

```text
文档名称 / 状态                   [导出 Word] [成果] [更多 ▾]
章节树 | [←] [→]  文档 › 第1章 › 1.1 目的     [定位当前章]
       | 标签页 / 当前章动作 / 视图与字号
       | 正文编辑                 | 结构预览（按需显示）
       | 问题、资料、成果面板按操作打开，可随时返回正文
```

这是信息层级示意，不强制新增永久侧栏。保留现有菜单、Dock、命令面板和用户布局。顶部常驻导出 Word、成果；检查、快速构建、正式出稿、分支、文档详情和关闭项目进入更多/菜单。宽屏可显示“检查”，窄屏优先保住正文与主动作。

路径可点击定位树中节点，可复制完整路径；长名称省略显示，提示和复制保留全值。后退/前进记录主动跳章、搜索/问题/资料来源定位的文件、光标、滚动和来源说明，连续同位置合并，项目之间隔离。不按每次按键记历史，不回放正文，不因返回而保存或覆盖未保存修改。

视图提供“写作 / 对照 / 阅读”，复用现有专注、预览、目录与分栏；记录用户选择。字号按可配置档位放大/缩小/重置，可调编辑区与预览，均不改变 Markdown 或 Word 模板。预览仍称结构预览，不能显示为 Word 精确分页。

### 导入：进入工作后再处理可选问题

保留已实现的一键导入。后台识别时可调整名称/目录；完成后在工作台内显示一句摘要、最多三条可行动提醒、原件/完整报告/定位章节入口。“开始编辑”是主动作，结果不反复弹窗。缺图、复杂对象和不确定标题标明实际保留或降级，不要求全部修复才能写作。

Word、Markdown、规范起步仍各用原入口；统一完成后的呈现和返回方式，不要求改成统一多步向导。文件不支持、来源不可读或无法创建项目才影响这次导入；取消保留用户已填写内容以便重新选择。

### 导出：常用一键，更多需求一张表单

“导出 Word”继续默认整份 / 当前编辑内容 / Word / 遵循模板，一键执行。新增旁边的“导出设置…”（菜单、更多和命令面板共用同一动作），打开时即可按默认值提交，不出现新的强制预检。

| 区域 | 基础字段 | 默认与反馈 |
|---|---|---|
| 导出什么 | Word、PDF、离线 HTML、源码包 | 默认 Word；一个格式不可用时其他格式继续，显示待转换/失败原因 |
| 导出范围 | 整份、当前章、所选章节 | 默认整份；当前章显示名称；多选按文档顺序，空选显示实际整份回退，可改选 |
| 内容来源 | 当前编辑内容、已保存版本 | 默认当前；有未保存修改显示数量，选择已保存时明确哪些修改未纳入 |
| 放在哪里 | 输出目录、文件名 | 合理默认；同名沿用既有不覆盖策略，目录失败回退并显示实际位置 |
| 版式 | 遵循模板、正文自适应 | 默认模板；仅暴露 LayoutProfile 已支持字段 |
| 高级（折叠） | 图片宽度、普通表格列宽/表头/跨页、章前分页/横向、已有变体、严格模式、原件纳入 | 显示适用格式和真实限制，严格模式默认关闭 |

底部实时摘要：“当前内容 · 整份 N 章 · Word / HTML · 遵循模板 · 输出位置”；单击“开始导出”收集当前缓冲并交给原 TaskRunner。设置关闭不丢编辑状态。

记住格式、目录和版式等便利偏好；快速 Word 不继承上一次严格模式、所选章节或已保存来源。每次明确显示实际来源与范围，已失效的章节选择提示并可继续用整份。单独的只读项目仍能查看/导出到外部目录，不能通过偏好绕过写入限制。

### 成果：先打开，再看细节

按轮显示生成时间、实际范围和内容来源，格式列表优先显示可读文件。“待刷新”可以打开 Word；PDF 待转换不会使 Word/HTML 消失。默认隐藏长路径/摘要 ID/后端日志，提供展开、复制路径、定位和完整报告。状态使用文字加语义色。

窄面板显示一列结果和一个主动作；“补本轮缺项”“按当前内容再生成”“更改设置…”按宽度折行或放入更多。补旧轮必须使用匹配 `roundId` / `captureId` 的报告和捕获；失配时不拿最新报告冒充，用户可直接开设置生成新轮。新轮默认带入原格式和能解析的原范围，让用户看到并可修改；不悄悄改成整份。

最多保存 12 条本地历史引用/生成时摘要，不复制正文和成果文件。重启后历史状态标注为“生成时记录”，当前可用性另外核对；文件失效仍保留名称/位置供重新定位。历史缓存不作为正式状态或业务报告。过期缓存可以跳过，不挡最新成果和新导出。

### 高级面板与表单：当前上下文明确

辅助面板显示当前项目/章节/资料范围，搜索与建议详情共用原接口；340px 宽度下搜索、范围和主动作可分两行，空内容给现有添加范围动作，后台结果不抢焦点。模块库显示明确版本、来源和插入位置，沿用固定引用/复制/撤销。

批量表单成员行显示文档名称、路径和可执行状态；成员错误就地修复/移除，其他有效成员可提交。已有变体从实际可用列表选择；服务暂缺可保留原高级输入并显示真实原因，不能假装完成解析。批次仍写原 schema 1，续跑仍用既有 V3.2 队列。

跨这些界面统一：正在加载、没有内容、没有匹配、部分成功、错误、只读、被移动。提示有一个可执行下一步；可选配置坏了可以回退，取消后保留表单输入。成功通知不抢正文焦点，触发导航/提交后的焦点去向明确。

## 4. 视觉与尺寸规则

| 项目 | 具体规则 |
|---|---|
| 字体 | 保留现有 10pt 正文、9pt 辅助、12pt 小标题、16pt 页面标题；编辑/阅读另有字号偏好，不全局硬编码像素字号 |
| 间距 | 复用现有 4/8/12/20 逻辑像素 token；卡片、字段、对话框采用相同对齐和边距规则 |
| 按钮 | 一个区域通常一个主动作；次级与更多使用原角色。完整文字按 QSS 后 sizeHint/内容边距计宽，不靠缩字号挤入 |
| 图标 | 使用已有资源/Qt 图标；无资源给简洁文字。不能依赖 Emoji 才能理解动作 |
| 颜色 | 原浅/深主题为基础；状态同时有文字，聚焦/选中/禁用层级清楚；更换主题后现存面板同步 |
| 自适应 | 按控件实际可用宽度测量，主窗口 1024×640、1280×720、1920×1080；成果/辅助面板 340/420/700px；允许竖向滚动 |
| 长内容 | 名称/路径省略可取全值；警告换行；更多动作完整可达；必需提交/取消不在可视范围之外 |
| 焦点 | Tab 路径合理、键盘聚焦可见；Esc 关闭当前临时层并返回触发点，不取消无关后台任务；全局快捷键同一次只触发一次 |

正文可用面积不低于当前相同布局基线；默认 1280 写作编辑区高度目标 ≥480px，若用户展开摘要/目录/面板则不作同一面积比较。窄窗口选择写作/阅读单栏，不强制双栏。面板宽度目标在 340px 可操作，而非将面板 minimumWidth 固定为 400+。

## 5. 执行批次

| 批次 | 优先级 | 任务数 | 独立可用成果 |
|---|---|---:|---|
| UI2-A 视觉与工作台层级 | P0 | 4 | 主按钮完整可读，项目条自适应，共用视觉/焦点规则 |
| UI2-B 首页继续工作 | P1 | 4 | 常用项目可固定，过滤与恢复入口顺手，长路径可处理 |
| UI2-C 正文导航与阅读 | P0 | 5 | 路径/定位、后退前进、视图与字号，跳走后能回来 |
| UI2-D 导入与导出设置 | P0 | 5 | 导入后可继续写；一张表单调用已有多格式/范围/版式能力 |
| UI2-E 成果与高级面板 | P1 | 4 | 窄面板可操作，历史可信，批量/模块/辅助反馈一致 |

默认执行 A→B→C→D→E→F，每批自带直接验证和交付。只想先改善日常写作时可 A→C→D→E，再补 B/F；无需先归档旧包。缺少某个选项服务只影响它，继续其他直接可执行任务。详细编号见 [26 项任务](../openspec/changes/product-ui-experience-next/tasks.md)。

| 场景 | 必须看到的结果 |

步骤目标：快速 Word 保持一次提交，随后一次“打开”；配置导出打开设置后一次提交即可；搜索/问题跳转后一次后退回原位置。记录实际点击和强制弹窗数量，不宣传未测得的操作耗时。

## 7. 与其他计划的边界

- 旧 UI：保留已实现入口、布局、非模态成果与首用路径，本轮只增量改进。
- CORE：继续负责来源/捕获/装配/格式/有限版式/兜底，本轮负责表单和反馈。
- RD：负责工作区、关系、矩阵、影响、集合和项目业务设置；本轮给共用控件和上下文模式，不重新定义关系和配置。
- V3.4 / V3.5 / V3.6：分别负责表格网格、包制作、索引性能；可以复用本轮视觉和导航，不并入本包。
- V3.0～V3.3：使用原模块、建议、命令、队列服务，不新增审批/联网/模型必经步骤。

首轮不增加启动看板、强制教程、账号/云端协作或大量装饰动画。下一步是否做复杂 Word 对象交互，等真实样例和本轮使用反馈再决定。
