# 主流程实用性与易用性要求

修订日期：2026-10-01。适用于 [主功能优化计划](product-core-workflow-plan.md) 和 `product-core-import-export`；要求并入既有 8 批/40 项。这里描述待实现行为，当前不代表已完成产品能力。

目标：**用户用默认设置完成常见工作；需要细调时能找到；遇到问题有直接下一步。** 接口与来源记录保留在内部，日常界面使用“文档、章节、导出、原件”等用户熟悉的词。

## 1. 首个交付点与后续补齐

| 阶段 | 必须实际可用 | 交付判断 |
|---|---|---|
| 先交付日常闭环 | 单份 DOCX/Markdown 导入、无标题接管、复杂内容原件/缺口、编辑与图片插入、全份 Word快速导出、缺 Word可读稿、打开结果/原件、已有重导入入口 | 用真实脱敏文档完成导入→改一章→导出→打开；不能只显示说明或模拟成功 |
| 随后补完整出稿 | 当前章/勾选章、多格式同时出稿、失败格式重试、离线 HTML | 选择范围清楚且输出一致；失败不撤掉其它结果 |
| 再补效率与交接 | 映射预设、批量导入、普通表格细调、横向章、源码包 | 有单独样本与验收，未交付的选项不在日常页显示为可用按钮 |

已可读结果先交付。先交付某阶段不等于整个 change 完成，未实现任务和待验收项目继续保留；后续直接依赖可用时可继续 V3工作。首阶段对应 CORE-A/B/C、E/F的基本路径和 H的相关检查/说明，不要求提前完成 D/G或全部性能试点。

## 2. 首页以继续工作为中心

- 主操作为“导入文档”“新建文档”和最近文档的“继续编辑”；同一操作在菜单、工具栏与快捷入口执行同一服务。
- 最近文档显示名称、位置和上次打开时间，复用已有列表/会话能力。移动或丢失时提供“重新定位”，不能因一个失效记录让首页无法使用。
- “导入文档”选择 DOCX/DOC/Markdown 后自动进入对应流程，不让用户先理解“接管”和“模板填充”的内部区别。临时格式转换与其它工具在“更多工具”内仍可访问。
- “新建文档”采用已有通用模板/规范建项服务；选定规范包后实际建立项目。入口不能只是提示一段文字再转到不相关的 Word文件选择。
- 本次不建设新的首页框架、账户/团队中心或复杂引导系统；完成现有入口和合理布局即可。

## 3. 导入默认值与最短路径

日常单份导入路径：**选择/拖入文件 → 开始导入 → 进入编辑**。后台给出预检摘要，细调大纲不成为正常路径的必经页。

| 项目 | 默认行为 | 用户可调整的位置 |
|---|---|---|
| 文档名 | 已有元数据中可信名称，否则文件名；清理文件名非法字符 | 导入页直接编辑 |
| 项目目录 | 已有最近有效目录，否则应用现有默认目录 | “更改位置” |
| 编号/版本 | 编号可空；版本用源中可信值或既有通用默认值 | “更多设置” |
| 章节 | 自动识别全部正文；无标题按单章；标题前正文保留 | “调整章节” |
| 格式/模板 | DOCX默认保持原格式；Markdown用已有通用模板 | “套用规范/更换模板” |
| 样式映射/严格策略 | 自动匹配、普通模式 | “高级设置” |

信任已有元数据识别的支持范围，未知字段不猜成业务事实。目标同名自动后缀，目录失效回有效默认；所有默认决定有一行摘要。新用户无需填写编号、选择规范包、安装 Word或确认全部复杂对象才能处理有效 DOCX/Markdown。

单份从首页导入成功默认进入编辑并保留结果摘要；已有工作区发起导入时保留当前编辑，在结果中给“打开新文档”，不自动切掉未保存内容。批量成功列表给逐项打开和只重试失败；已经进入编辑后仍可查看导入处理记录。

## 4. 编辑不用记住所有 Markdown语法

复用现有常用格式工具栏、图片粘贴/拖入、表格插入/美化、片段、撤销与草稿。标题按钮显示“标题”与可选级别；常用“列表、表格、图片、保存、导出”可见，其它工具放“更多”且可查找。

插入图片、应用标题/列表/片段按一次操作进入撤销栈；Ctrl+V图片与选择图片调用同一资源服务。普通表格先沿用插入/美化能力，本包不增加完整可视化表格编辑器或 Word式富文本编辑器。

编辑状态用“未保存”“草稿已保存”“已保存”“草稿保存失败，内容仍在当前窗口”，区分草稿与正式文件。草稿/恢复复用现有服务，无需启用开关；保存失败保留缓冲并就地给“重试保存/另存副本”，恢复采用用户明确动作。用户导出当前内容时不会被迫先解决所有保存问题。

预览在输入去抖后更新；旧预览显示“内容已更新，正在刷新/点击刷新”，定位跳转保持当前章和上下文。小窗口下通过“更多”/换行容纳动作，不能把保存或导出挤到窗口外。

## 5. 快速导出默认值与高级设置

首用快速导出为 **整份文档 + 当前编辑内容 + Word + 项目可用导出目录**。有未保存修改只显示“包含 2章未保存修改”，不弹逐章保存框。

- 主按钮说明格式，例如“导出 Word”“导出 Word/PDF”；旁边显示范围和目录摘要。打开“导出设置”才展开多格式、选章、已保存版本、底模/排版和严格检查。
- 成功后记住格式、有效目录和兼容排版设置；整份范围与当前内容仍是普通快速导出默认。上次选过某章、已保存版本或严格模式，不得悄悄缩小下一次出稿或漏掉修改。
- “导出当前章/选中章节”作为明确动作，显示章名/数量与实际顺序。再次生成该范围只有对应动作/结果页明确声明时才沿用。
- Word文件名默认为文档名与有效版本，编号可选；冲突增加可辨识后缀。同一轮多格式尽量同名，结果只展示真实路径。
- 目录失效先回项目可写导出目录；只读项目用应用既有用户导出目录；均不可用才给“更换目录”。自动回退后结果明确实际位置，保留已选范围/格式/内容来源。
- 日常导出不要求查看技术快照、hash、schema或选择内部 backend；机器报告仍保留这些记录。

Word生成可读稿后即可显示“打开 Word”。字段刷新在后台串行处理，采用稳定可读副本避免打开正在刷新/被锁定的临时文件；刷新结束后列明更新稿。没有 Word或刷新失败时使用可读稿，提示“目录/页码待刷新”，可之后再处理。

PDF只从同次 Word转换；转换失败结果给“稍后补 PDF”。离线 HTML作为明确格式或“生成离线预览”动作。可读 Word并不等待所有附加格式完成才开放，未完成格式继续展示阶段进度。

## 6. 结果与问题就地解决

结果先显示“Word已生成”“HTML已生成”“PDF待转换”及“打开文件/打开目录”。第二层显示“3处内容待完善、8项已自动处理”；默认最多展开 3个有行动价值的问题，全部问题在“查看全部”中。原件留存/文本降级/可编辑保留的细分事实在详情中可查。

| 问题 | 直接动作 | 处理范围 |
|---|---|---|
| 缺一张图片 | 定位此处 → 选择替代图片 | 复用当前资源修复，不重新导入整份文档 |
| 公式/文本框待完善 | 定位正文／查看原件 | 原件能打开，正文位置清楚 |
| 目录/页码未刷新 | 打开可读 Word／重试刷新 | 同一轮原稿，完成后显示更新稿 |
| PDF转换失败 | 稍后补 PDF／查看原因 | 只补该格式，已有Word/HTML保留 |
| 输出目录不可写 | 使用有效默认目录／更换目录 | 保留输入、选章、格式和模板设置 |
| 源内容后来改过 | 按最新内容重新生成 | 新一轮，旧结果仍可打开 |
| 外部修改与本地冲突 | 查看差异／暂跳该章 | 其它已选无冲突章继续 |

同类问题按类型/章节归并，自动处理的低优先级提示默认收起。普通告警不弹阻断对话框；确实无法出稿或会覆盖未保存内容时，显示原因和明确下一步。错误码、阶段日志与诊断复制在“技术详情”，默认不让用户从长日志中找解决方法。

## 7. 等待与键盘操作

点击开始/取消后立即显示“处理中/正在取消”，按钮防重复提交；编辑仍可继续。进度给正在处理的文件/章节与阶段，无法估算时不显示假百分比或 ETA。取消保留已完成内容与当前输入/设置，重试不重新选文件。

沿用现有 Ctrl+S保存、Ctrl+F查找等快捷键；普通页面 Tab顺序符合阅读顺序，文件/目录可复制，主操作支持键盘。新增导出快捷方式先核对已有映射，不抢占其它动作。基础对话框以 1280×720逻辑窗口检查可达性，并在 125%/150%缩放实测；复杂选项可以滚动，主按钮固定可见。

## 8. 可直接验收的易用性场景

以下操作数从源已选择/项目已打开开始统计，不计系统文件选择器内部动作或用户主动细调；适用于有效输入和默认可写路径，不以异常恢复步骤冒充常规步骤。

| 编号 | 场景 | 易用性验收 | 落入任务 |
|---|---|---|---|
| U-1 | 首次单份 Word/Markdown导入 | 源已选后最多 2次主要提交进入编辑；不强制编号、模板选择或风险确认；格式入口真实正确 | 1.3、2.1、2.2、2.5、4.4 |
| U-2 | 已有文档继续工作 | 最近文档一次点击继续；从已打开工作区导入不丢未保存内容；失效位置可重新定位 | 1.3、1.4、2.5 |
| U-3 | 标题/图片/表格操作 | 常用动作可见，图片粘贴/拖入正常，一次撤销；草稿/已保存状态区分；可读预览 | 5.2、5.3、5.5 |
| U-4 | 修改后快速 Word导出 | 最多 2次主要操作生成并打开；包含当前修改，不要求逐章保存；结果无误导状态 | 6.1、6.2、6.6 |
| U-5 | 上次只导出一章/保存版本/严格模式 | 下一次普通快速导出回整份当前内容，按钮与摘要反映实际格式/范围；不隐式漏章 | 6.1、6.6 |
| U-6 | 一次出 Word/PDF/HTML其中一项失败 | 可读结果出现即能打开，失败格式一键补原轮；源改动后一键生成新轮有清楚区分 | 6.2～6.6 |
| U-7 | 复杂对象/缺图/输出位置失效 | 原因与直接动作可见；不用查长日志；回退后实际位置明确，同类提醒归并 | 2.4、3.3、6.4、6.5 |
| U-8 | 工作中取消或等待 Word | 及时反馈和阶段说明，无重复提交，已完成成果/设置保留，可继续编辑 | 4.3、5.4、6.2、6.5 |
| U-9 | 小窗口/高 DPI/只用键盘 | 主操作可达，内容不盖住按钮，Tab/快捷键可用；实际缩放环境未测单列 | 5.5、6.6、8.2、8.4 |

CORE-H跑上述实际服务/GUI闭环并记录步骤、弹窗数与证据；有用户试点时记录首次成功点与误操作，不等待试点才做可自动验证的修复。不增建埋点平台或登录系统；本地计时/样本和离屏检查足够作为本轮直接依据。
