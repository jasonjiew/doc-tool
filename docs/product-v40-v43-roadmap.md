## 1. 方向：把已有能力连成稳定、好用的日常工作

| 优先级 / 版本 | 要解决的实际问题 | 用户完成后的体验 | 范围 |
|---|---|---|---|
| P0 / V4.0 出稿与运行可靠性 | Word 等待不透明、回归有失败、取消/退出/恢复事实不足 | 看清阶段，先打开已生成文件，失败项能补，关闭重开能继续 | 5 批/20 项 |
| P0 / MAIN2 主线优化 | 导入结果不完整、复导入入口缺选择、部分操作未接当前内容、最终出稿顺序待核实 | 导入后直接写，修订按章接收，复制/修图用当前内容，最终成果一致 | 6批/24项 |
| P1 / V4.1 企业模板工作流 | 模板/规范/方案分散，反复配置，换模板效果不清楚 | 找到合适模板，试小样，保存常用设置，直接用当前内容出稿 | 5 批/20 项 |
| P1 / V4.2 增量检查工作台 | 检查收益有限，问题处理和规则调整需要反复切换 | 改一章少做重复工作，按章节/规则处理，先看差异再成组修正 | 5 批/20 项 |
| P2 / V4.3 交付与修订工作台 | 多成员交付、版本比较和接收人包缺统一组合体验 | 看清本次交付与变化，局部失败继续，接收人离线直接打开 | 5 批/20 项 |

默认仍是“导入 → 编辑 → 检查 → 快速导出 → 打开成果”。负责人按需使用模板制作、研发关系和多成员交付。普通流程使用有效默认；高级设置、试用小样和团队工作台按需展开。

流程尽力完成：缺一个成员或单格式失败只影响该项；Word 不可用先给可读成果；普通 warning 可继续出稿；冲突保留当前内容并提供副本/重新定位。限制只作用于确实无法证明来源或会覆盖内容的动作，不把可选能力变成全工程门禁。

### MAIN2：将主线优化落实到任务

原计划对导入/编辑主要安排验收，本次增加具体可实施差额：A导入结果完整列表与接续，B原复导入预览接真实入口，C当前正文章节复制/批量操作，D活缓冲资源修复与清理事实，E最终成品顺序和来源读回，F三条闭环。详细默认、兜底、静态线索与验收见 [主线计划](product-mainline-optimization.md)和 [24项任务](../openspec/changes/product-mainline-usability-and-fidelity/tasks.md)。

静态复核还确认HTML底层已有时间戳/UUID独立轮次目录，沿用并验证，不重建；新增重点为消除“当前内容已捕获却仍提示未导出”的来源说明/清单差额。V4.0只负责运行适配，MAIN2负责主线行为，后续模板/检查/交付继续使用同一服务。

## 4. V4.0：生成有结果，等待有出口

典型场景：导入后改了未保存表格，提交 DOCX/PDF/HTML；Word 刷新卡住，用户仍能打开 HTML 和已生成的可读稿，只补原轮 Word，或用后来改动明确生成新轮。

| 批次 | 核心成果 | 验收事实 |
|---|---|---|
| 40-A | 重现失败/超时，校正测试收集、编码/模态与旧缺项分类 | 保存真实命令/用例/退出；收集为零或退出异常不算通过 |
| 40-B | 探测/启动/打开/处理/写文件/退出各阶段有界 | 启动取得 PID 前也可返回，只清理可证明属于任务的资源 |
| 40-C | 取消、部分成果、原轮恢复及关闭重开 | 旧捕获同源；晚到结果不覆盖；草稿与已生成文件可用 |
| 40-D | 原任务/成果页的阶段、行动与诊断 | 打开、补原轮、生成最新、回输入可达；源码/冻结路径分别核实 |
| 40-E | 导入到出稿完整循环与回归/原生试点 | 内容/范围/资源一致；自动、真实 Word、未测分别留证 |

交互顺序是“本轮来源 → 当前阶段 → 已可用格式 → 待处理项与动作”。耗时阶段用真实名称和经过时间，无依据不显示假进度。取消请求一秒内有确认，真实停止/资源回收独立显示。

沿用已有 Word 工作进程/helper 与线程适配；不可中断 COM 线程不能承担“保证终止”。忙锁和终止绑定真实所有者。Word 归属无法证明时只结束自有 helper，标明残留待处理，其他格式/编辑继续；不能按进程名或全局新增 PID 推测并清理用户 Word。

## 5. V4.1：选企业模板后直接用

典型场景：负责人维护“需求说明书”规范，成员搜索并选择模板，查看版本和适用用途，按需试一个小样，然后用同样设置导出当前正文。换模板时看见实际映射变化，旧成果仍能查看与补充。

| 批次 | 核心成果 | 验收事实 |
|---|---|---|
| 41-A | 本地目录引用原模板/规范/recipe，搜索/最近/详情 | 同名可区分；缺路径重定位；坏索引不损坏原资源 |
| 41-B | 保存受支持的模板/映射/版式预设 | 消费者读回实际设置；未知声明保留；来源范围独立 |
| 41-C | 从实际底模生成独立小样并展示结果 | 真实模板摘要使缓存失效；无 Word 有可读结果；不覆盖业务正文 |
| 41-D | 模板更换摘要与常用入口 | 旧/新身份、失效映射/替代设置可见；主动作可用、草稿保持 |
| 41-E | 负责人制作到成员导入/出稿闭环 | 原加载器消费、参数/资源读回；企业 Word 视觉另有实证 |

页面顺序：用途/搜索 → 模板列表 → 所选详情 → “试用小样 / 使用此模板”。高级样式映射默认收起。试用是可选动作，普通成员无需先完成小样或规范制作才能导出。

初版预设只消费已支持字段：`mode`、`image_width`、`table_width`、`repeat_header`、`allow_row_split`、`landscape_chapters`、`page_break_before_chapter` 及真实样式映射。任意字体、封面占位/页眉字段等需单独确认实际消费者，不直接加入“已支持”表单。规范 schema 保持 1；目录是可重建引用，不是另一份规范数据库。

快速导出仍默认整份当前内容。模板设置不偷偷带入旧章节范围；`template-fill --output` 仍是 DOCX 文件路径。HTML 是内容预览，Word 分页/目录/封面视觉按真实 Word 验收。小样默认通用内容，业务片段由用户明确选择。

相关：[提案](../openspec/changes/product-v41-enterprise-template-workflows/proposal.md)、[设计](../openspec/changes/product-v41-enterprise-template-workflows/design.md)、[20 项任务](../openspec/changes/product-v41-enterprise-template-workflows/tasks.md)。

## 6. V4.2：检查快一点，修正少切换

典型场景：只改一章术语，检查所选范围；负责人按规则或章节看问题，试调一条支持的规则，确认真实变化后保存；选择确定性建议，看差异、应用、撤销，不改整份工程其他内容。

| 批次 | 核心成果 | 验收事实 |
|---|---|---|
| 42-A | 同机分阶段 50/300/1000 章基准 | 每档至少五次冷/热/变化采样，结果和释放可复跑 |
| 42-B | 原索引会话及明确依赖的结果复用 | 同大小/同时间修改、跨章/模块/变量变化不漏检；坏缓存直接算 |
| 42-C | 按章节/规则/变化看问题与时点 | 统计不随分页改变；部分范围标未检查，旧结果标过期 |
| 42-D | 支持字段规则试跑与成组确定性修正 | 试跑不隐式保存；差异/选择/撤销；冲突项局部跳过 |
| 42-E | 性能、完整结果对照与资源生命周期 | 原始样本留存；未达目标如实记；真实大工程试点另列 |

问题列表负责“找到待处理项”，详情负责“理解依据、定位、修正”。返回保留筛选、选中和光标。缺基线显示未知，过滤后零条不代表整份无问题；个人“暂不处理”仅改变当前版本视图，报告仍保留真实问题。

缓存绑定正文、规则/参数、解析器、范围和依赖摘要；未知依赖全量兜底。活缓冲只用内存派生，不写成已保存正文。目标是实测主要热路径 p95 改善至少 30%，50 章不恶化超过 10%；取消一秒内确认。目标不是所有机器的秒数承诺，不能靠删规则或弱化断言达标。

## 7. V4.3：一次交付看清本次内容和变化

典型场景：需求/设计/测试三份文档交一版。负责人选成员/章节/模板/格式，开始后继续编辑；一个 PDF 失败仍打开其他成果，补原轮不混入新正文。比较两个实际版本，生成修订说明和本地包，接收人离线打开；恢复时生成副本。

| 批次 | 核心成果 | 验收事实 |
|---|---|---|
| 43-A | 现有请求的交付准备视图 | 摘要来自实际参数；提交固定逐成员捕获；编辑不混原轮 |
| 43-B | 成员×格式成果表与局部重试 | 可用先打开；旧身份来自可信记录；部分结果不冒充完整正式 |
| 43-C | 两版正文/资源/条目/成果比较与修订说明 | 实际 ID/路径区分同名；配置和装配差异均可见；缺历史信息未知 |
| 43-D | 本地接收人包、原快照补 Word 包与副本恢复 | 离线链接可用；用途/输入真实；恢复不覆盖当前项目 |
| 43-E | 三成员闭环、回归与团队试点 | 合成路径可先自动完成；真实团队/Word 证据单列 |

工作台沿用 RD/原出稿页面：准备 → 成员成果 → 版本比较 → 打包/恢复。普通单文档用户继续从原快速导出入口工作，不默认要求创建研发工作区。

成果包默认所选可读文件、资源、清单、修订说明和离线入口，源码为明确选项。跨机补 Word 仍用原 `snapshot_package`，保留必要原捕获与资源；只读成果包缺刷新输入时不能标成可刷新包。生成本地文件不自动上传/发消息。

比较使用固定正文及真实稳定身份，不能凭名称/显示编号猜对齐。历史数据不足仅对应部分不可比较，其他差异继续。修订说明可编辑，不自动改变复核/正式状态。副本目标冲突默认新名，坏项局部跳过，当前活缓冲保持。

## 9. 执行、证据与本轮边界

MAIN2按A→F，其他四包按A→E；先查已有实现只补差额，相关验证通过后继续，不逐批确认。包末核对相关覆盖，最终核对当前默认runner清单，保存真实文件/用例/退出/失败/超时/未覆盖范围；新改动或未决问题再扩大/重复验证。

真实底模/Word/冻结/IME/团队/大工程条件不足仅保留对应子项，继续独立任务。MAIN2 6.3和四版5.3真实试点未执行不能勾完；旧九项逐项复核，合成可测工作不拖到无限“等环境”。

本轮不展开账号/云协作、审批签章、在线市场、OCR、全功能 Word 编辑器或外部需求系统连接。下一轮从实测反馈选择一个高频缺口：复杂对象往返、真实版式差异或明确授权的只读系统接入；先有样本和收益再建任务。

正常下一直接任务：**40-A 1.1**。五包104项与入口校验见 [本次复核](../analysis/product-mainline-plan-review-20261003/verification.json)，原80项 [历史校验](../analysis/product-v40-v43-plan-20261003/verification.json)保留。它们只证明规划结构，不代表业务实现、Word视觉或性能完成。
