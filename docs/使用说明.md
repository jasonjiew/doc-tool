# Doc Tool 使用说明

一句话：把一份带 Heading 结构的 Word 拆成 Markdown 章节树，在树上改，再合回 Word。

本文只讲“怎么用”。项目格式、Markdown 扩展、章节树命名约定见 [README](../README.md)。

## 1. 打开程序

| 方式 | 操作 |
| --- | --- |
| 便携包 | 解压 `DocTool-X.Y.Z-portable.zip` → 首次先按「请先读我.txt」双击 `安装证书.cmd` 导入公司证书 → 双击 `启动DocTool.cmd` 启动（不要只把 `DocTool.exe` 拆出来用）；仍失败则双击 `diagnose.cmd` 并回传生成的 `DocTool-diagnose.txt` |
| 安装版 | 运行 `DocTool-Setup-X.Y.Z.exe`，安装到 `%LOCALAPPDATA%\DocTool`，无需管理员权限；安装目录内有同样的 `安装证书.cmd` / `请先读我.txt`，首次导入一次证书即可 |
| 源码 | `python -m doc_tool.app`，或双击 `start-doc-tool.cmd` |

## 2. 新建项目

**文件 → 新建项目…**（Ctrl+N），向导 6 步：

1. **选择源 Word 文档** —— 必须是用 Heading 1～6 组织的 `.docx`，手动加粗大字号的“伪标题”识别不到；
2. **导入预检** —— 报告标题层级、图片/表格数量与保真风险，有阻断项就先回 Word 修；
3. **样式映射** —— 确认各级标题与正文对应的 Word 样式；
4. **项目信息** —— 文档编号/名称/版本与项目目录；
5. **正在导入** —— 自动跑导入、试构建与往返检查；
6. **导入结果** —— 有差异会列出来。

导入后的目录：

```text
<项目>/
├─ project.yml                     项目清单（编号、名称、版本、样式映射、路径）
├─ original/                       导入时的源 Word 副本
├─ template/template.docx          排版模板（封面、页眉页脚、修订表都来自它）
├─ content/<类型>/                 章节 Markdown 树（日常只改这里）
│  └─ _revision_record.md          修订记录（见第 4 节）
├─ assets/<类型>/                  图片与复杂表格资源
├─ output/                         正式产物 DOCX
└─ logs/                           运行日志与校验报告
```

目录名与文件名就是章节编号和标题（`3.7 产品管理/3.7.9 呼吸机应用升级.md`），改名即改章节；批量调整用 **内容 → 章节重命名/重编号…**，它会同步引用。

## 3. 日常编辑

- 在左侧章节树选文件，用内置编辑器改，Ctrl+S 保存；也可 **在外部编辑器打开当前文件**（VS Code、Typora 均可）。
- 常用：**内容** 菜单下的 全文搜索、全局替换…、引用分析…、术语/一致性检查。
- 程序会写自动草稿与会话状态。异常退出后重新打开项目，恢复操作需要你确认，不会静默覆盖正式内容。
- 同一项目同一时刻只能有一个窗口持有写锁；状态栏会显示占用的进程。

## 4. 修订记录（最容易漏的一步）

修订记录只维护一处：`content/<类型>/_revision_record.md`。程序不会替你猜写了什么，出稿前自己在表格末尾加一行。

```markdown
| 版本 | 修改摘要 | 修改时间 | 修改人 |
|------|----------|----------|--------|
| 2.5 | 历史记录…… | 2026-07-01 | 王杰 |
| 2.6 | 新增模块：4.7 KSOA -> 4.7.25 客户信息管理<br>修改模块：第 6 章 -> 6.1 第三方转发 | 2026-08-20 | 王杰 |
```

三条规则：

- **末行版本号就是本次文档版本号**，会写进 `project.yml`、模板封面的「版本号」、页眉「版次」和输出文件名，所以别忘了递增；这几处一律是纯数字，写成 `V2.6` 也会自动规范成 `2.6`；
- 摘要里换行写 `<br>`（会变成 Word 表格里的真换行），竖线写 `\|`；
- 首次出稿时该文件不存在，程序会从模板的修订表自动提取一份，之后就归你维护。

旧项目从没走过合并的话，第一次正式合并会自动生成这个文件，可以先合一次再回来补内容。

## 5. 出稿三档

| 动作 | 快捷键 | 做什么 | 需要 Word |
| --- | --- | --- | --- |
| **操作 → 校验项目** | F5 | 只查结构、内容与资源引用，不产出文件 | 否 |
| **操作 → 诊断构建（无 Word）** | Ctrl+Shift+B | 重建 DOCX 但跳过字段刷新，产物标注为非正式 | 否 |
| **操作 → 正式合并** | — | 构建 → Word 刷新域 → 复验 → 原子发布 | **是** |

正式产物在 `output/`，命名为 `<编号> <名称>(<版本>).docx`（通用文档缺编号或版本时自动省略对应部分）；运行日志与校验报告在 `logs/`，也可以从 **文件 → 打开输出目录 / 打开日志目录 / 打开校验报告** 直接进。

正式合并失败会回滚，上一版正式产物保持可用。

## 6. 文档互转（Word / PDF / Markdown / HTML / 文本 / 表格 / RTF / ODT）

**工具 → 文档互转…**：批量转换任意文件，无需先打开项目。源文件一律只读，输出默认落在
源文件同目录（可自选输出目录，同名文件默认不覆盖）。

- 界面按转换工具的通行习惯组织：把文件**直接拖进窗口**（支持整个文件夹），或点首屏拖放区挑选；
  工具栏右侧的「转换为」下拉给出整批的目标格式，方向列显示每个文件的实际走向；转换中有进度条，
  完成后可点「打开输出文件夹」或**双击列表行**直达产物所在目录。
- 支持的源类型：`.docx/.doc`、`.pdf`、`.md/.markdown`、`.html/.htm`、`.txt`、`.xlsx`、`.csv`、
  `.rtf`、`.odt`。完整方向矩阵如下（「缺省」= 不选转出格式时的走向）：

| 源 \ 转出 | PDF | Word | Markdown | HTML | TXT | CSV | XLSX |
| --- | --- | --- | --- | --- | --- | --- | --- |
| .docx/.doc | **缺省** | — | ✓ | ✓ | — | — | — |
| .pdf | — | **缺省** | — | — | — | — | — |
| .md | — | **缺省** | — | ✓ | — | — | — |
| .html | ✓ | **缺省** | — | — | — | — | — |
| .txt | **缺省** | — | — | — | — | — | — |
| .xlsx | ✓ | — | — | ✓ | — | **缺省** | — |
| .csv | ✓ | — | — | — | — | — | **缺省** |
| .rtf | **缺省** | ✓ | ✓ | — | ✓ | — | — |
| .odt | **缺省** | ✓ | — | — | — | — | — |

  「转换为」选中的格式只对存在该方向的源生效，其余源按上表缺省方向转换（如选 PDF 时
  `.pdf/.md` 源仍转回 Word）；旧版 `.doc` 仅支持转出 PDF。MHT (.mht/.mhtml) 经真机探针
  验证本机 Word 无法打开，暂不提供。
- **页范围（转 PDF）**：只导出部分页面时填「1-5」或「3」（格式不对会以 E6008 拦下），
  仅对转出 PDF 的方向生效；Word 的导出参数级支持，实测可用。
- **Word → PDF**：走 Word 的正式导出，版式、目录与页码和出稿一致（实测 16 页模板约 7 秒）。
  由本机 Word 完成。
- **PDF → Word**：Word 的 PDF 重排是有损的素材级还原——**标题层级基本丢失**（实测 21 页文档只还原出
  7 个 1 级标题，2 级及以下为 0），列表里会逐文件给出实际识别到的层级数量；要拿去「新建项目」导入，
  先在 Word 中复核补齐标题样式，否则预检会以「没有可识别的 Heading 1 样式」（E1002）拦下。
  耗时取决于 Word 是否已启动过 PDF 重排：预热后同一文档 7.5 秒，冷启动首次要 84 秒以上，
  所以单文件超时按方向自动放宽：导出类 300 秒，PDF→Word 900 秒。
- **Markdown / HTML → Word**：先渲染成带排版样式的 HTML，再由本机 Word 导入——中文宋体、西文 Times
  New Roman，正文五号 1.5 倍行距；`#` 标题映射 Word 内置「标题 1~6」（可生成目录、可导入章节树）；
  表格带边框表头底纹，代码块等宽底纹合为一块，图片按版心宽度等比缩放并**内嵌进文档**（发给别人不丢图）。
  Markdown 源与 TXT 一样按 UTF-8（含 BOM）→ GBK 顺序探测读取，两种编码都解不出时以 E6007 拦下。
  勾选「文首生成目录」可自动插入 1~3 级目录（CLI 为 `--toc`）。
- **Word → Markdown**：纯 Python 离线完成，**不装 Word 也能用**。产出单文件 `.md` +
  同级 `<名字>_assets/` 目录（图片、无法用 Markdown 表达的复杂表格会原样存为 OOXML 资源并在正文留链接）；
  只对构建有意义的注记一律剥离，拿到的就是干净的读者版 Markdown。注意 Word 的图片显示尺寸方言
  （`=96x96` 后缀）不会保留——通用 Markdown 渲染器不认。
- **Markdown / Word / Excel → HTML**：纯 Python 离线完成，**不装 Word 也能用**。产出单文件
  `.html`（内嵌排版样式，浏览器直接打开）；Word→HTML 与 Word→Markdown 一样带
  `<名字>_assets/` 资源目录（图片、复杂表格，有资源时才创建），Excel→HTML 每个工作表一个标题加表格。
- **TXT → PDF**：按 UTF-8（含 BOM）→ GBK 顺序探测编码读取，空行分段；两种编码都解不出时
  以 E6007 拦下（请另存为 UTF-8）。HTML → PDF 与 Excel/CSV → PDF 走同一套 Word 导出链路，
  统一 A4 版心。
- **Excel / CSV 互转**：XLSX↔CSV 纯 Python 离线完成。公式单元格取缓存值（`data_only`）；
  合并单元格按左上角值填充整个区域并在产物说明里计数；CSV 读取兼容 UTF-8 与 GBK（两种编码都解不出报
  E6007），写出带 BOM 的 UTF-8（Excel 双击不乱码）；XLSX 转 CSV 只导第一个工作表（CSV 为单表格式，其余工作表会在
  产物说明里点名）。文件损坏或没有有效内容时报 E6006。
- **RTF / ODT 导入**：由本机 Word 打开后另存——RTF 可转 PDF/Word/Markdown/纯文本，
  ODT 可转 PDF/Word；RTF→Markdown/纯文本走「导入成 DOCX → 离线导出」组合链。
- 列表里每个文件单独给出结果与错误码，单个失败不影响其余文件继续转。
  新增错误码：E6006 表格文件读取失败、E6007 文本编码无法识别、E6008 页范围无效。

## 7. 命令行（无人值守 / CI）

```powershell
python doc_tool_cli.py --version
python doc_tool_cli.py preflight --docx D:\docs\source.docx
python doc_tool_cli.py import --docx D:\docs\source.docx --name my-doc --target-dir D:\projects --document-type general
python doc_tool_cli.py validate --project D:\projects\my-doc
python doc_tool_cli.py build --project D:\projects\my-doc --skip-word-refresh   # 诊断构建
python doc_tool_cli.py build --project D:\projects\my-doc                       # 正式构建
python doc_tool_cli.py convert D:\docs\手册.docx                                # → 同目录 手册.pdf
python doc_tool_cli.py convert D:\docs\手册.docx --to md                        # → 手册.md + 手册_assets\
python doc_tool_cli.py convert D:\docs\说明.md --toc --target-dir D:\out        # → Word，文首带目录
python doc_tool_cli.py convert D:\docs\a.pdf D:\docs\b.pdf --target-dir D:\out --output json
python doc_tool_cli.py convert D:\docs\手册.docx --to pdf --pages 1-5           # → 仅前 5 页
python doc_tool_cli.py convert D:\docs\报价.xlsx                                # → 报价.csv（第一个工作表）
python doc_tool_cli.py convert D:\docs\表.csv --to pdf                          # → 表.pdf（经 Word 排版导出）
python doc_tool_cli.py convert D:\docs\旧稿.rtf --to docx                       # → 旧稿.docx（Word 导入）
```

`--project` 可重复传入批量处理；`validate` 支持 `--format sarif|junit`；质量门禁或执行失败返回非零退出码。
`convert` 也可以直接传文件夹（收一层内的支持类型，见第 6 节矩阵）；`--to` 取
`pdf/md/html/docx/txt/csv/xlsx`，只对存在该方向的源生效；`--pages` 只对转出 PDF 的方向生效；
`--timeout 0`（缺省）表示按方向自动取超时。

## 8. 常见问题

- **正式合并报需要 Word** —— 必须在本机交互式会话里装有 Microsoft Word；远程无桌面会话或没装 Word 时只能用诊断构建。
- **报 `Failed to start embedded python interpreter!`** —— 程序文件在解压/安装时被安全软件改写损坏。先运行随包 `安装证书.cmd` 导入公司证书，再重新解压（安装版则重新安装）；仍不行用 `启动DocTool.cmd` 启动，并按 `diagnose.cmd` 回传结果。
- **双击 exe 报 `DLL load failed while importing _socket` 或「没反应」** —— 终端安全软件拦截未签名 exe。1.4.2 起程序会自动迁移到 `%TEMP%` 稳定目录重启；迁移失败时会弹窗并在旁边写入 `DocTool-startup.log`。也可双击便携包里的 `启动DocTool.cmd` 启动。彻底被策略拦截时请 IT 在安全管理平台加白名单，并把 `DocTool-diagnose.txt`/`DocTool-startup.log` 发给维护人员。
- **提示项目已被占用** —— 同一项目已在另一个窗口/进程打开，关掉那个窗口，或等它的任务结束。
- **导入预检报保真风险** —— 先在源 Word 里规范标题层级和图表，再重新导入，别在 Markdown 侧硬凑。
- **改了源 Word 想同步** —— 用 **工具 → 重新导入更新源 Word…**，不要手工覆盖 `original/`。
