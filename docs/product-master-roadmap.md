## 1. 产品方向

帮助研发人员把现有文档导入后继续写清楚，以企业模板快速交付可读 Word；帮助文档负责人管理需求、设计、测试关系和版本成果；帮助团队复用正文、规范和交付流程。

主线按三层建设：

| 层次 | 用户每天要完成的事 | 产品关注点 |
|---|---|---|
| 日常文档 | 导入、编辑、查看问题、导出、打开结果、再次修订 | 默认流程短，来源可靠，失败能继续 |
| 研发联动 | 跨文档找条目、建立关系、查缺漏、复核影响、打包一版 | 真实身份和内容版本，入口可用，部分成果保留 |
| 团队提效 | 公共内容复用、章节交接、规范包、批量出稿、大文档检索 | 复用既有服务，操作可解释，可撤销，可重复 |

近期保持本地桌面产品，Git 和 Word 按实际动作提供能力。账号、审批平台、联网模型、强制覆盖率不进入普通导入/编辑/出稿的必经路径。独立转换/PDF 工具保持可用，新增主功能围绕上述三层排程。

## 4. CORE：完成一个文档的日常循环

| 用户动作 | 完成后的体验 |
|---|---|
| 选择 Word/Markdown | 自动识别真实来源；普通模式优先导入，编号/高级映射不强迫填写 |
| 进入编辑 | 无标题可单章，缺图/复杂对象有可见占位及原件位置，最多先展示 3 个可行动问题 |
| 修改内容 | 预览、检查与出稿可读取当前未保存内容，草稿/已保存状态明确 |
| 点击快速导出 | 默认整份、当前内容、Word、有效目录；生成可读成果后即可打开 |
| 需要更多格式 | DOCX/PDF/HTML/源码 ZIP 使用同一来源捕获，失败格式可单独同源重试 |
| 再次修订 | 保留原件、来源版本、差异及安全副本，不覆盖用户当前改动 |

典型场景：数百章节、多图片和追踪条目，打开与搜索时用户仍能编辑，切章后不会显示上一章的迟到预览。

| 批次 | 可用成果 | 关键验收 |
|---|---|---|
| 36-A | 50/300/1,000 章节同机基准、计数和阶段观测 | 记录环境/输入、至少 5 次样本、实际瓶颈及目标 |
| 36-B | 摘要与配置指纹的增量索引 | 同大小修改、删除/移动、缓存损坏仍正确，直接扫描能兜底 |
| 36-C | CORE 缓冲捕获与 V3.0 装配指纹 | 未保存与模块新版本不会读到旧内容，同轮结果一致 |
| 36-D | 后台视图、代次、分页、取消和内存控制 | 旧结果不覆盖新章，扫描中不假报总数，取消请求及时确认 |
| 36-E | 正确性与性能对照、真实大项目试用 | 按实际同机提升记录，Word 全流程与源性能分开 |

目标：已测瓶颈热路径解析次数减少至少 70%；中大样例热路径 p95 耗时改善至少 30%；小样例 p95 不恶化超过 10%。这是本包验收目标，需同机测量或有证据调整，不能宣传成所有机器的秒数承诺。未达项如实记录，不阻断其他独立功能。缓存始终可删除/重建，不替代正文、关系和评审记录。

资料：[提案](../openspec/changes/product-v36-large-document-performance/proposal.md)、[设计](../openspec/changes/product-v36-large-document-performance/design.md)、[任务](../openspec/changes/product-v36-large-document-performance/tasks.md)。

## 11. 每批完成标准

| 检查面 | 必须看到的证据 |
|---|---|
| 用户可用 | 从真实菜单/按钮进入，有实际结果；不能只新增类或服务 |
| 默认正常流程 | 按默认值跑通，不要求可选配置/Git/模型/评审全部就绪 |
| 兜底 | 自动处理、待完善、未执行分开；缺项可定位、可继续、可重试 |
| 数据与来源 | 源文件/缓冲/身份/版本正确；不覆盖无关内容；同轮 captureId 清楚 |
| 验证 | 相关自动检查、执行环境、命令/退出码/成果；失败分类真实 |
| 实机边界 | Word 视觉、真实剪贴板、冻结升级、缩放等有证据或明确待验收 |
| 交接 | 当前 tasks 勾选与证据对应，下一直接任务明确 |

实机缺失不阻止没有依赖的编码和验证；含未完成验收的任务不能勾为全部完成。可读成果不等于正式结果。发布/推送/安装到他人环境作为独立后续动作，不由本地实施指令自动包含。
