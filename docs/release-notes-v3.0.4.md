# 文档工具（Doc Tool） v3.0.4

本版围绕「报障能不能定位」与「Word 刷新会不会卡死」两条主线收尾：
新增全局滚动日志、环境快照与一键诊断日志包，修正 Word 属主锁识别、
专用实例归属与重启判定，并把「为什么这轮是待刷新」说明清楚。

## 一、新增与增强

- **全局滚动日志**：`%APPDATA%\DocTool\logs\doc-tool.log`（5 MiB × 3 份备份），
  启动横幅、环境快照、未捕获异常（主线程/后台线程/不可捕获异常）、Qt 告警
  与原生崩溃堆栈（faulthandler）统一落盘；目录不可写时按 APPDATA → TEMP →
  用户目录回退，全部失败也不阻断启动。
- **一键诊断日志包**：「帮助 → 导出诊断日志包（ZIP）」把 README、环境快照、
  构建信息与应用日志打包到桌面；同名文件自动追加序号，绝不覆盖上一次的包。
- **环境快照**：应用/系统/Python/Qt(含 WebEngine 运行件)/Office(Word 可用性、
  `Word.Application` CLSID、WPS 安装痕迹)/Git 逐项实测，任一探测失败只影响该行。
- **Word 刷新防卡死**：忙锁与只读预检（新增 `E3004`）、Word 自动化关闭链接/转换
  弹窗、按阶段预算监督、取消可立即终止本次专用 Word；成果页新增
  「更新目录与页码 (Word)」入口，不必再手动 Ctrl+A → F9。
- **待刷新原因可读化**：导出结果的 message 与 warnings 说明本轮为什么没有刷新
  （设置未勾选、本机 Word 不可用、WPS 接管、刷新失败、已取消），不再只有
  「待刷新」三个字。
- **WPS 接管降级**：当 `Word.Application` 的 CLSID 不是 Microsoft Word 时自动改用
  静态目录的诊断构建（目录条目正确、页码待刷新），不再把不可见弹窗拖满预算。
- **VCS 拉取失败分类**：无上游分支时显式 `git pull origin <branch>` 重试；分叉、
  鉴权失败、未跟踪文件冲突分别给出可执行说明；后台拉取显式禁用交互式凭据提示。
- **高保真预览诊断**：「诊断/修复」弹窗逐项检查模块、离线资源与打包运行件，
  源码态可一键补装 PySide6，打包态可启用兼容模式（禁用 Chromium 沙箱/GPU）。
- **打开目录智能寻址**：选择中间层目录、工作区根或含多个项目的父目录时，
  自动定位唯一项目、进入研发工作区或让用户选择，不再直接报「缺少 project.yml」。
- **章节顺序自然序**：`3.7.2` 排在 `3.7.10` 之前（章节树、内容索引与出稿一致）；
  未列入 `chapters` 的章节按编号插入而不再一律追加末尾，导出前给出顺序体检。

## 二、关键缺陷修复

1. **Word 属主锁文件名规则错误**（导致防卡死主路径失效）：真实锁文件是
   `~$` + 文件名去掉前 1～2 个字符（去掉 `~$` 后至少保留 11 个字符，
   如 `out.docx` → `~$out.docx`、`0123456.docx` → `~$123456.docx`、
   `DocTool 说明(1.0).docx` → `~$cTool 说明(1.0).docx`），原实现按
   `~$` + 完整文件名探测，长中文名的导出稿永远命中不了，Word 仍在不可见
   对话框上卡满预算。已按真机实测规则修正并补齐边界用例。
2. **PID 差集兜底可能误杀用户 Word**：超时后用「启动前后新增的唯一 WINWORD」
   认领并 `taskkill /T /F`，用户恰好在这段时间自己打开的 Word 会被杀掉
   （未保存文档丢失）。现要求该进程**没有可见顶层窗口**才认领，无法判断
   （无 pywin32/枚举失败）或有可见窗口时只登记残留事实，绝不按差集杀进程。
3. **高保真诊断「重启」失败被当成成功**：PySide6 `QProcess.startDetached`
   返回 `(bool, pid)`，失败结果 `(False, -1)` 是非空元组恒为真，原实现照样
   `QApplication.quit()`，用户只看到窗口消失且没有重启。已正确解包判断，
   失败时保留窗口并提示手动重开。
4. **流水线跳过原因只挂在动态属性上**：`PipelineResult` 未声明
   `word_skip_reason`，类型检查与序列化都拿不到。已改为显式字段，
   WPS 跳过的说明在导出结果与状态里可追溯。

## 三、版本与兼容

- 应用版本 3.0.4；`installer.iss`、`packaging/build.ps1`、GitHub/GitLab CI
  版本源已统一（发布门禁要求 tag 与四处一致）。
- 项目 schema 保持 2，v1 项目仍可读可写；既有项目无需迁移。
- 日志与诊断包只打包程序自己写下的诊断数据，不含文档正文；其中含本机路径、
  用户名与错误堆栈，请只发给内部维护人员。

## 四、已知限制

- 正式合并需要交互式 Windows 会话与 Microsoft Word；WPS 接管
  `Word.Application` 时自动降级为待刷新的诊断构建。
- 成果页「更新目录与页码」目前只刷新文档与界面状态，不重写该轮的正式状态
  与导出索引：重新打开项目后该轮仍显示待刷新，需要重新出稿才登记正式状态。
- 超时后的进程清理只在能证明归属（worker 回写 PID，或差集唯一且无可见窗口）
  时执行，其余情况留下残留事实并提示用户手动关闭 Word。

## 五、安装

- 安装包 `DocTool-Setup-3.0.4.exe` 与免安装包 `DocTool-3.0.4-portable.zip`
  由本地构建后发布到内网 GitLab Release；GitHub 侧由 `v3.0.4` 标签触发的
  Actions 构建并发布同一组资产（含 SHA-256、SBOM 与 `latest.json`）。
- 默认安装到 `%LOCALAPPDATA%\DocTool`，无需管理员权限，可与内部旧版并存。
