# DocTool 主流程智能化：深度调研与执行计划

日期：2026-10-16\

用户决定：**全流程更省心；离线为主，AI 可选。** 用户随后授权完成调研后直接实施、不中途提问。本文件先固定契约，执行事实另行补充；计划中的验收不等于已通过。

## 1. 结论

不建议先增加聊天窗口、换一套转换引擎，或重新开发导入、增量检查、修订合并与出稿服务。当前最有价值的智能化是：

> **知道当前处理的是哪份内容 → 解释问题和影响 → 推荐一个可执行的下一步 → 安全地处理或接续 → 如实说明成果状态。**

优先顺序：

1. **先保证“聪明但不误导、不丢稿”**：检查与当前编辑内容同源；建议采纳/撤销不覆盖后续编辑；登记失败不显示正式完成。
2. **把已有能力连成离线智能主线**：依据当前事实给出下一步，直接连接现有检查、问题、设置、修订接收和成果入口，不增加审批问卷。
3. **减少查找和判断成本**：导入结果按可处理原因组织；资料按证据相关性排序；旧结果、未执行和范围不足明确展示。
4. **最后完善可选 AI**：只在用户主动调用并看过发送内容后请求；结果先展示，再明确采用；失败保留本地候选。

## 3. 需要优先闭环的具体差额

下列是静态复核发现，实施时先补可观察回归，再修复。

### 3.1 F5 检查与快速出稿的来源不同

- 主窗口 `main_window.py:2839–2921` 的 F5 路径优先找磁盘已有 DOCX，仅以 Markdown 修改时间提示陈旧；无产物时另建磁盘索引。
- `main_window.py:4414–4442` 的快速出稿则采集当前未保存编辑。
- 正文格式检查面板已经有活缓冲、所选范围和配置诊断，应该**接通它**，而不是再实现检查器。
- 目标：日常 F5 检查当前内容，显示实际范围/未保存来源；历史成品验证保留为明确入口。CLI 原有 `validate`/`check` 契约不擅自改变，也不声称 CLI 能读取 GUI 内存。

### 3.2 成果登记失败不应仍返回正式完成

`project_export.py:401–431` 捕获最终状态登记异常后追加提醒，但返回值仍可能沿用之前的 `formal=True`/ready。目标是拆清“文件可读、Word 已刷新、登记未完成”三个事实；登记失败保留文件，不谎报正式登记完成，不把已成功的格式删掉。

### 3.3 跨面板建议的缓冲时点需要保护

- 助手打开/换范围时采集缓冲；采纳后面板发送整个 `current_texts()`，宿主按整篇文本写编辑器。
- 原撤销事务也会直接恢复旧全文。
- 目标：每次检索/建议/采纳/撤销获取最新活缓冲；只发送受影响章节；写回前核对预期文本。若采纳后又编辑，助手撤销不能抹掉新内容；保留原生编辑器一次撤销路径。

### 3.4 关键质量回归未进入默认 runner

当前 `scripts/tests/run_tests.py` 显式注册 **230 个不同测试文件**，其中不含 `test_mainflow_quality.py`。该文件定义了配置损坏、零执行、CLI 退出码、构建保留旧产物和 GUI 只读等关键回归。应纳入默认验证并防止再次遗漏。

另有三组 UI 证据测试会写到当前已有修改的分析文件。执行全量回归前应支持独立证据目录，不能覆盖用户原有 16 个分析/截图修改。

### 3.5 已有功能仍需要“一个下一步”

目前检查、导入结果、资料建议、成果补充分别存在。增加的应是**纯派生建议**，不是新的执行引擎：输入已有报告、运行状态、范围/缓冲事实和成果状态，输出带原因的白名单动作，并调用已有处理器。

## 4. 目标交互与安全边界

### 4.1 六个用户场景

| 场景 | 目标行为 |
|---|---|
| 导入后发现缺图/特殊对象 | 先进入可编辑项目；完整结果可重开；建议明确为修图/查看原件/继续编辑，不连续弹窗 |
| 未保存编辑后按 F5 | 检查当前正文；范围与配置异常清晰；不隐式全保存，不用旧 DOCX 冒充当前检查 |
| 看到一批相似问题 | 按现有规则/原因分组，直达检查和修正预览；不一键猜测语义或删除资源 |
| 收到外部 Word 修订 | 推荐进入已有差异预览；只应用已选合法项；冲突项保留，其他项继续 |
| Word 不可用/某格式失败 | 先打开可读成果；从原轮补失败/待刷新格式，或明确新建当前内容轮次；不混用两轮内容 |
| 需要 AI 辅助摘要/术语 | 本地候选先可用；查看目标、目的、实际发送内容/截断与来源后才调用；结果不自动写正文/术语库/修订记录 |

### 4.2 动作分层

- **自动完成**：只读诊断、确定性推荐、按既有策略命名/占位/缓存/归类。不得新增强制审核步骤。
- **明确一次采用**：正文修正、修订接收、候选摘要/术语采用；展示实际差异，限定受影响范围，可撤销。
- **不能代替人**：业务真实性、需求是否可测试、批准/签字、语义冲突裁决、版本发布决策。

质量规则损坏、执行异常、零适用规则都不能伪装成“规范通过”。普通待完善内容仍按既有宽松出稿策略处理；严格交付只在用户主动选择时提升约定门禁。损坏的必需质量配置不能通过静默回退绕过门禁；其他可选设置的可读降级仍保留。

### 4.3 技术约束

- 复用当前 `ContentIndexService`/活缓冲、质量报告、`EffectiveSnapshot`、任务运行器、导入记录、出稿轮次、写入/撤销及评审模型。
- 建议层无持久化第二真相；未知保持 unknown，不以“没有问题记录”推导“已检查通过”。
- 建议只调用固定动作白名单，不执行文档/模型给出的命令或路径。
- 推荐只作帮助，不强制先检查才出可读稿，不自动保存全部正文，不默认清理图片。
- provider 默认禁用；不启用真实 HTTP/模型调用，不上传文档。不安装新依赖、不改认证/主机/终端安全策略。
- 不提交、推送或发布；不修改父框架及其他子仓库；不碰既有分析文件修改。

## 7. 验证与回退

### 7.1 验证层次

1. **失败复现/单元**：来源不一致、登记失败、建议后编辑、撤销后编辑、未知检查状态、中文两字检索、limit 后高相关结果、请求取消与无凭据。
2. **真实应用服务**：Word 导入→未保存编辑/修图/检查→同轮 DOCX/HTML；Markdown 多来源→批量章节→选章离线包；源修订→所选接收→再次比较→新轮成果。
3. **真实 Qt 自动化**：F5/菜单/建议按钮、焦点返回、候选选择与发送预览；离屏自动化不替代 IME/原生缩放。
4. **默认完整回归**：使用独立证据目录；记录文件数与真实用例数，不把 runner 的“一文件一个 JUnit testcase”当成单元用例总数。
5. **可用实机**：仅受控测试副本、既有有界 Word 适配；不打开未知企业文档，不杀用户 Word。企业底模、三成员接收人和人工视觉条件缺失，继续记 not-run/blocked。
6. **合成量测**：50/300/1000 章，比较冷/热及结果一致性；数字是本轮环境样例，不宣称真实企业效率提升。

### 7.2 退路

- 推荐为只读派生层，关闭入口仍能使用原菜单/快捷键和服务。
- 新增 CLI 仅增量，不删旧参数/退出码契约。
- 不迁移已有项目/规则、模板或历史；共享规则、旧 `.state` 优先级维持当前约定。
