# 页面交互最终实施计划

最终复核：2026-10-02。对象：企业研发文档团队使用的PySide6桌面工程。change：`product-ui-interaction-polish`，5批/20项，起始0/20。具体任务以[任务清单](../openspec/changes/product-ui-interaction-polish/tasks.md)为准，设计及规格在同一change；实施证据记入[执行台账](product-ui-interaction-execution.md)。

## 1. 最终方向与范围

先把“导入→写作→快速Word→打开成果→继续修订”做顺。默认采用**写作优先**：章节树+正文，预览/大纲/问题/任务按需展开。常用动作直接可见，高级设置保持可发现，局部失败给下一步，普通成功不打断编辑。

本包负责入口、布局、键盘、成果及已有高级能力的首用交互；研发成员/关系/矩阵仍由RD计划实施，网格表格由V3.4实施。复用已有服务，界面只增加必要适配。

当前已开始的批次先完成其直接验证；其后优先UI-A/B/C，再UI-D/E。旧包的归档授权、人工评价和缺失实机环境不是UI编码前置。后续产品顺序为RD→V3.4→V3.5→V3.6；CORE/V3.0～V3.3有实际代码差额时按直接依赖补齐，依据当前勾选和证据，避免按旧规划重做。

## 4. 页面最终交互

### 首页与导入

最近文档“继续编辑”和导入/新建/打开作为主入口，互转/PDF收在更多工具。主区拖放与导入按钮同路由，转换卡拖放只做转换。多DOCX逐份处理，MD按现有显式顺序组稿；不同来源的实际策略要显示清楚。

导入只突出“开始导入”，章节/映射/位置等细调为副入口。缺图/复杂内容保留原件和位置，进入编辑后完善；失败和取消保留源与设置。已打开项目接收外部修改沿现有差异流程，保留未保存处理。

### 写作工作台

文档名、真实保存状态、当前修改数量与导出Word优先。来源指纹/长路径进入详情，格式动作溢出可发现，标题可选级别。首用底部和右任务无事时收起；用户主动展开后保持，预览可切换。布局恢复只改显隐/尺寸，不动文档与会话内容。

Ctrl+F查当前章，Ctrl+Shift+F查项目全文；编辑器焦点Ctrl+B/Ctrl+I做格式，分支另有无冲突入口。帮助可键盘访问，Esc关闭当前临时层回原位置，不同时取消任务。

### 导出与成果

顶部“导出 Word”默认整份/current-buffer/有效目录，普通模式先生成可读稿；高级多格式、范围、来源及版式在设置。旧轮部分范围/saved/strict不隐式继承到下一次快捷操作。

成果逐格式显示可读稿/更新稿/HTML/PDF的真实状态和路径，每项打开明确。普通完成轻提示，成果持续可查，技术细节按需。无Word/某格式失败保留其他产物；无文件的命令显示摘要，不编造“打开”按钮。

| 操作 | 确切行为 |
|---|---|
| 补这次成果 | 用旧捕获/范围/来源，只补缺项或刷新，不读新正文 |
| 按当前修改重新生成 | 新收集当前缓冲，建立新轮，显示采用的格式/范围 |
| 换目录并重新导出 | 明示来源/范围并建立新轮，默认当前内容；旧成果仍在 |

全部长操作使用已有后台/队列，Word串行；UI线程采集缓冲后传入，工作线程不读编辑器。忙时只限制重复启动，保留运行状态。晚到结果归原项目/轮次，不覆盖新界面；取消沿安全边界保留完成项。

### 批次、模块与辅助

批次表单只收成员/现有变体/格式/目录，生成原batch格式并经过原服务校验。合法成员可继续，无效成员就地定位/移除/跳过；全部无效时保留输入。

模块空库提供当前章节创建和选择已有库安装；选定明确版本后固定引用或复制正文，资源可解析，一次撤销。创建标清缓冲/保存来源，当前正文为空不读取旧磁盘内容冒充；只读仍能预览/复制。

辅助按资料/建议切页，共用出处/差异详情，保留搜索、插入、采纳/撤销和建议导出。无资料时有真实添加/设置动作，模型默认折叠，本地功能先可用。

## 5. 验收与依赖

验收I-1～I-8沿[调研](product-ui-interaction-research.md)，额外核对三种恢复来源、旧会话优先、忙时状态和失效成果路径。1280/1024/1920为逻辑窗口尺寸；字体、DPR、实际窗口及正文矩形必须记录。

| 接口 | 复用位置 | 本包补的差额 |
|---|---|---|
| 导入 | intake_entries、ImportWizard、ReimportService | 入口语义、主次路径和结果展示 |
| 快速出稿 | project_export、EffectiveSnapshot、OutputState | 顶部入口、来源摘要、逐文件成果/后台恢复 |
| 后台/结果/会话 | task_bridge、task_dock、workbench_state、workspace_state | 薄适配、最近轮次、首用布局/恢复 |
| 批次 | delivery.contract、gui_tasks、gui_hooks、queue、result_index | 最小表单与成员格式动作 |
| 模块 | reuse_commands、module_refs、现有编辑事务 | 库设置/创建/安装/固定插入入口 |
| 辅助 | AssistPanel与application.assist | 切页、空状态、已有动作保留 |

单项缺服务接口时补最小公共适配并验证；无需重写引擎。相关测试参考[执行台账](product-ui-interaction-execution.md)，修改旧GUI断言时保留业务和来源保护，新测试登记原runner。

## 6. 执行与交接规则

1. 固定当前HEAD/工作树/勾选与环境，保留既有未提交实现，按当前差额开始。
2. 按任务顺序实施，普通技术问题自行排查，每项代码及直接验证通过后勾选并记录证据。
3. 无Word/Git/模型/实机或某个无关旧测试失败，只影响直接相关项；继续无依赖任务，保留可用成果。
4. 外部环境无法完成的5.3保持未勾选，台账写原因/复验步骤；可以完成5.4，但结束时必须标清实机未验收。
5. 所有可执行项完成后统一报告用户入口、验证/成果路径、剩余编号和继续入口。

本轮交付是最终计划和执行指令。OpenSpec strict仅证明结构有效；当前Qt离屏截图和对话方案预览不证明新交互已在产品实现，也不替代真实Windows/Word验收。
