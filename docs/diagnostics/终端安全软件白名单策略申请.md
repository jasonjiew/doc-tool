# Doc Tool 终端安全软件白名单策略申请

> 写给 IT / 安全管理平台负责人。目标：让 **DocTool.exe（GUI）** 与 **doc-tool-cli.exe（CLI）**
> 在装有 **亿赛通 DocGuard / IP-guard / 火绒企业版** 的终端上正常启动。
> 版本基线：2.0.0（策略按签名者配置后可覆盖后续所有版本）。

## 一、背景与证据（30 秒看完）

程序文件**本身完好**（与官方构建逐字节一致；系统 Python 可正常加载同样的 .pyd），
**唯独 DocTool.exe 进程**在非临时目录加载自身 `_internal\` 目录内的 .pyd 时被拦截/读到密文，
报：

```
ImportError('DLL load failed while importing Shiboken: %1 不是有效的 Win32 应用程序。')
```

同一份文件、同一进程，从 `%TEMP%` 目录启动则 **GUI 正常显示**（"Doc Tool v2.0.0 - Doc Tool"）。
→ 结论：属**进程/路径/文件类型维度的管控拦截**，不是文件损坏、也不是程序缺陷。

## 二、推荐策略（按优先级）

### ✅ 首选：按「代码签名者」信任（一条规则覆盖所有版本与路径）

- 证书：**江苏康尚生物医疗科技有限公司** 代码签名证书（随包分发 `codesign.cer`，
  终端执行 `安装证书.cmd` 或由域策略推送导入信任）
- 在三个平台均按 **签名者/发布者 = 江苏康尚生物医疗科技有限公司** 加入信任/白名单
- 覆盖 DocTool.exe、doc-tool-cli.exe、安装器及后续所有版本，无需按路径/版本维护

### 亿赛通 DocGuard（透明加密客户端）

> 说明：这里说的"读取权限"是**加密客户端的「进程授权 / 明文读取授权」**
> （信任进程读取加密文件时透明解密），**不是 Windows NTFS 文件权限**——
> 文件本身可读（PowerShell、系统 Python 等进程都能读到明文），
> 唯独 DocTool.exe 进程读 .pyd 时被返回密文。请 IT 在 DocGuard 管理台
> 「进程权限 / 信任进程」里按下表授权即可，无需动 NTFS ACL。

1. **信任进程**：DocTool.exe、doc-tool-cli.exe（读取 .pyd/.dll 时透明解密，不再返回密文）
2. **不加密目录**：`%LOCALAPPDATA%\DocTool`、`C:\ProgramData\DocTool`
   （后者为中文用户名终端自动使用的安装目录）
3. **不加密扩展名**（可选兜底）：该目录下的 `.pyd`、`.dll`、`.zip`

### IP-guard（终端 DLP）

1. **应用程序白名单/信任程序**：DocTool.exe、doc-tool-cli.exe
2. **文件操作控制排除**：安装目录（`%LOCALAPPDATA%\DocTool` 等）及其 `.pyd/.dll/.zip`
3. **进程/模块加载**：放行 DocTool.exe 从自身目录加载扩展模块（.pyd）

### 火绒企业版

1. **信任区/软件白名单**：DocTool.exe、doc-tool-cli.exe、安装目录
2. **系统加固/防护**：允许其加载自身目录扩展模块；若开启「软件安装拦截 / DLL 加载防护」需对 DocTool 放行

### Windows Defender（可选，稳妥起见）

- **排除项**：进程 DocTool.exe、doc-tool-cli.exe；路径 `%LOCALAPPDATA%\DocTool`、`C:\ProgramData\DocTool`

## 三、IT 加完策略后的验收标准

1. 终端点开始菜单「Doc Tool」图标（或安装目录下 `启动DocTool.cmd`）
2. **通过**：GUI 窗口 "Doc Tool v2.0.0 - Doc Tool" 出现，黑窗口约 8 秒后自动关闭
3. **未通过**：黑窗口停住，显示 `[ERROR] ... DLL load failed while importing Shiboken ...`
   及处置指引（新版启动器已把失败原因可见化）
