# 主流程智能化使用说明：离线为主，AI 可选

适用：2026-10-16 本轮源码实现。版本号与既有发布流程未改变；源码已实现不代表旧便携包已包含，也不代表通过企业试点。

相关文档：[调研与执行计划](mainflow-intelligence-plan-20261016.md) · [质量规则与执行状态](mainflow-quality.md) · [本轮执行与验证交接](mainflow-intelligence-execution-20261016.md)。

## 1. 日常先用这条主线

1. **导入后直接编辑**：保留既有原件和导入记录。导入结果可从文件菜单重开；处理方式按“可编辑、参考文本、仅原件保留、占位、未执行”分别说明，不把原件留存说成可编辑还原。
2. **按 F5 检查当前正文**：使用当前工作台的活缓冲和格式检查服务，不再优先拿旧 DOCX 代表当前编辑。不会为检查而隐式“保存全部”。在“格式检查”选择整份文档、当前章或所选章，查看本次实际范围、来源和未执行原因。
3. **需要接续时看“下一步”**：状态栏的“下一步：…”按钮给出首选动作；其下拉菜单或“操作 → 下一步建议（离线）”展示原因。打开面板不会调用模型，也不会自动执行推荐。
4. **保留可读成果，按正确轮次继续**：部分格式失败、Word 待刷新或登记待办时，已生成的可读文件仍可使用。“补原轮”继续原捕获/原来源/原范围；“按当前内容导出新一轮”才使用现在的编辑。

下一步仅从当前事实派生。菜单、面板和主按钮都携带展示时的项目/轮次身份，点击前核对动作是否仍适用；项目关闭/切换、原轮变化或缺少身份时拒绝旧动作并刷新，不转向新的项目或轮次。主按钮不会在点击时悄悄改选另一个首选动作。旧索引缺少轮次身份时，仍可从原有“成果”入口查看历史文件，不让建议入口猜造身份或补轮目标。状态、项目路径或未保存正文无法读取时，清除旧建议并停用失效执行入口，不把读取失败称为“已保存来源”。推荐不是新审批门禁，不要求先清零所有普通提醒才生成可读稿。

### F5 与已有成品验证不是同一件事

- **F5 / 操作 → 检查当前正文**：当前编辑内容的格式与规则检查。工作台中的未保存章节可以参与；磁盘正文不因此改变。
- **操作 → 验证已有 Word 成品（已保存来源）**：保留原来的已有成品验证入口。它不能证明稍后或未保存的编辑已经通过。
- CLI 的 `check` / `validate` 沿用原接口。CLI 无法读取另一个 GUI 进程的内存，不会把磁盘检查标成“当前未保存缓冲”。

## 2. 如何读检查与成果状态

| 看到的情况 | 正确含义与接续 |
|---|---|
| 未知 / 尚无执行证据 | 还不能判断；“问题数为零”不代表已经检查 |
| 配置不可用 | 先修正规则配置再重检；不会静默绕过损坏的必需配置 |
| 未执行任何规则 | 规则被关闭或不适用；不能认定检查通过 |
| 未完整执行 / 来源不可用 | 查看具体原因；已有问题与原稿保留，不伪装成干净结果 |
| 结果已陈旧 | 正文或规则变了，应重新检查；旧结果不能证明当前内容 |
| 当前范围未发现问题 | 只覆盖报告中实际执行的范围和规则；当前章/所选章不等于整份认证 |
| 可读稿待刷新 | 文件可打开，但 Word 的目录/页码等正式刷新仍待完成 |
| 待登记 `pending-registration` | 可读文件及 hash 保留，但最终状态登记未完成；不是正式登记成功 |
| 某格式失败 | 保留其他成功格式，按原轮补未完成项；不会因一项失败删除可用成果 |

既有问题分组、定位、修正预览和撤销继续使用。批量处理仍按受影响章节和当前证据核对；语义是否正确、冲突取哪一方、是否批准交付仍由作者/审核人决定。

## 3. 导入诊断与资料检索

- 导入结果的原因摘要从**完整处理记录**计算，不因首屏、动作数量或分页而少算。详细列表保留分页与定位，可按处理方式筛选。
- 缺图引导定位/选择替代图片；仅原件保留引导核对原件；跳过项明确为未执行。原件不存在时不显示“可打开原件”的假承诺。原件相对路径按项目根判断，不以启动目录猜测。修图只清除唯一对应的那条事实；定位过时/多处不明确、只读、项目已切换或目标章有未保存编辑时拒绝磁盘替换，不自动保存。记录更新失败保留已写正文和未完成账本，并说明待核对。
- 资料检索仍只搜索显式加入的项目、模块或当前缓冲，不扫描全盘，不依赖 embedding、模型或网络。
- 大章扫描分段检查取消；物理目标按文档取得，不为每条命中重复 stat。结果先按确定性相关信号排名，再保留前 K 条；标题、精确标题、完整条目标识符、文件名等原因可在提示中查看。总数仍是完整命中数，不是显示条数。
- 中文两字词、原正则/整词语义、自然路径顺序继续保留。陈旧内容明确标记；排序不是语义正确性的评分。围栏代码中的 `#` 不冒充 Markdown 标题加分。

## 4. 建议采纳与撤销保护

本地建议在检索、刷新、采纳和撤销前同步最新活缓冲。只写回受影响章节，宿主核对预期文本；若期间发生其他编辑，不整篇覆盖作者的新内容。

- 建议后继续编辑，再采纳：检查最新目标/差异，不用旧整篇快照盖回去。
- 采纳后继续编辑，再点助手“撤销上次采纳”：后续编辑不能被助手旧快照抹掉。必要时提示重新核对，原生编辑器的撤销路径仍保留。
- 只读项目可查看/复制，不可通过助手绕过宿主写保护。

## 5. 可选 AI：每次先预览，再发送，再选择

**默认 provider 禁用。** 日常导入、编辑、检索、检查与出稿不会自动请求模型；本轮实施没有为用户创建/启用真实 provider，也没有上传真实文档。已有用户级 provider 配置负责显式启用，凭据仍通过环境变量提供，不写进项目或交付包。无需安装新增依赖。

使用“增强摘要”或“增强术语”时：

1. 先采集本次明确范围的最新本地上下文，冻结为预览。禁用或无输入时直接保留本地候选，不弹网络确认。
2. 预览显示目标、用途、范围、实际正文/原始字符数、截断提示、证据标识及**实际 JSON 请求体**。目标展示去掉 URL 用户信息/查询值和本地参数值；认证头值不展示、不记入请求日志。
3. 选择“取消，不发送”时零请求。只有“确认并发送一次”才调用一次；配置在预览后改变则拒绝旧请求，要求重新预览，不偷偷换目标或增加范围。内置 HTTP 不自动跟随重定向（包括同域）；返回 3xx 时保留本地候选，核对并配置最终端点后须重新预览。
4. 已确认请求通过现有任务运行器在后台执行。可继续编辑；发送的是确认时的冻结内容，不是随后新增的文字。重复发送会被阻止。
5. 可“取消增强”。尚未调用时不发送；已经进入阻塞 HTTP/本地命令的，可能仍须等待配置的超时结束，**不承诺立即杀掉外部调用**，迟到结果会被丢弃，不自动重试。
6. 结果进入“增强候选”页。可先查看/复制，再点“采用所选候选”；只采用当前选中的一条，不批量弹修订窗口、不自动修改术语库、不保存或批准修订记录。

摘要候选进入已有修订编辑入口，仍由用户编辑/确认；术语候选可经既有编辑器插入和原生撤销。无本地出处的内容标为**措辞候选**；即使返回的 evidence ID 与本地记录一致，也只代表标识可匹配，作者仍须核对内容是否支持结论。含可执行指令特征的建议不被执行、不作为证据。

超时、断网、缺凭据、坏响应或取消均保留本地候选。项目切换会清除候选并丢弃旧项目尚未完成的结果。请求/响应格式预览针对内置 HTTP 与本地命令适配器；自定义注入实现仍属于受信任扩展，需要独立验证。上述确认是桌面入口的交互契约；现有直接服务 API/CLI 显式调用保留兼容，集成方应先调用准备/预览接口自行确认，不能把增强接到保存/检查/出稿的自动路径。失败诊断会遮盖已知认证/URL/参数值，内置本地命令不展示原始 stderr。

## 6. 只读 CLI 查询

在源码仓库的 Bash 中，使用现有 Python 环境：

```bash
python -B -m doc_tool.cli mainflow-advice --project '<项目绝对路径>' --output json
python -B -m doc_tool.cli mainflow-advice --project '<项目绝对路径>' --output human
# 只看已有事实，不执行正文检查；质量状态保持 unknown
python -B -m doc_tool.cli mainflow-advice --project '<项目绝对路径>' --output json --no-check
python -B -m doc_tool.cli capabilities --format json
```

JSON stdout 为单一文档，声明 `readOnly: true`、`sourceMode: saved`、质量执行事实及动作白名单。查询不创建项目规则、成果或第二套流程状态，不依赖 Word/模型；不能读取 GUI 未保存内容。

退出码 `0` 表示成功取得查询结果，**不是质量通过或业务批准**；质量配置错误/未执行仍在 JSON 中如实保留。项目不可用/查询失败返回非零。原 `check` 的质量退出码契约不改变。

## 7. 维护、回归与验收边界

- 新回归已进入 `scripts/tests/run_tests.py`：质量检查及四组主流程智能化测试。旧导出 UI 脚本也已补齐实际执行入口，避免“只定义用例却静默返回 0”。JUnit 的一条 testcase 是一个脚本文件，不能当成内部单元用例数；显式跳过的方法/类及自定义场景应分别统计。
- 如已有分析文件修改，先设置 `DOC_TOOL_TEST_ARTIFACT_ROOT` 为本轮**独立的绝对目录**，再运行套件，避免覆盖历史 UI 证据。
- 实机 Word 用例按 `CORE_REAL_WORD=1`、`V32_REAL_WORD=1`、`V40_REAL_WORD=1` 单列执行；PowerShell 签名脚本集成按 `DOC_TOOL_TEST_NATIVE_SIGNING=1` 单列，遵守现有执行策略，不加 Bypass。不通过改用户配置/安全策略强行获得通过。
- 合成规模脚本：`python -B scripts/benchmark_mainflow_intelligence.py --sizes 50 300 1000 --output analysis/<独立目录>/scale.json`。只创建自有临时合成正文/缓存，验证冷/热结果一致、limit 后高相关结果与源 hash 不变；数字不是企业效率承诺。
- 增加新动作时，同时更新闭合白名单、真实宿主路由及安全测试；不得把文档/模型文本直接当命令执行。新增 provider 时需独立验证预览与真实传输一致、取消、超时、脱敏和候选采纳。
- 可关闭下一步面板、忽略可选建议，原有菜单/快捷键与服务仍可用。未迁移既有项目/规则/模板/历史；任何回退必须只处理本轮已确认的修改，不 reset/stash/revert 用户修改。

自动回归、离屏 Qt、受控 Word 冒烟、原生桌面/IME/DPI、企业底模、接收人环境、业务批准与发布是不同层次。既有五个真实试点未因此自动完成；具体本轮结果见执行交接，不以测试定义或静态能力探测代替实际运行。
