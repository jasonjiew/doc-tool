# 从内部旧版迁移到公共版（Doc Tool）

> 任务 11.3：旧内部版到公共版的安装、设置和项目迁移指南，明确并存、回滚和
> 不兼容入口。内部旧版的具体安装目录/可执行文件名/设置目录等值记录在内部发布
> 基线（`docs/release/01-baseline-internal.md`，不随公共仓库发布）。

本文档面向已经使用内部旧版（品牌化需求/详细设计工具）的用户，说明如何平滑
迁移到公共版 **Doc Tool**。

## 1. 并存安装（无需卸载旧版）

公共版与内部旧版**可以并存**，互不覆盖、互不干扰：

| 项 | 内部旧版 | 公共版 |
| --- | --- | --- |
| 可执行文件 | 内部旧版名称（见内部基线） | `DocTool.exe` |
| 安装目录 | 内部旧版目录（见内部基线） | `%LOCALAPPDATA%\DocTool` |
| 安装器 AppId | 内部版专用 | 公共版专用（不同值） |
| 用户设置目录 | 内部旧版目录（见内部基线） | `~/.doctool` |
| 项目类型 | 通用 / 需求 / 详细设计 | 通用（需求/设计仅兼容读取） |

- 安装公共版**不会**覆盖或卸载内部旧版。
- 两版可同时启动，使用不同的安装目录与设置命名空间。

## 2. 设置迁移（自动、只读）

公共版首次启动时，会把内部旧版用户目录中的**非敏感偏好**只读复制到公共目录：

- 窗口几何（`geometry.json`）
- 最近项目列表（`recent.json`）

规则：
- 仅在公共设置尚为空时迁移；已存在公共设置则跳过，**不覆盖**。
- 旧目录**原样保留**，便于回滚。
- 密钥/缓存等敏感文件**不迁移**。
- 主题/Dock/标签状态按项目存放在项目内，不涉及此迁移。

## 3. 项目迁移（旧 requirement/design → 通用）

公共版可以**继续读取与构建** schema v1 的旧 `requirement` / `design` 项目，
并在项目栏标注「旧版专用」。若希望把旧项目转为通用项目，使用迁移功能：

```powershell
# CLI 迁移：把旧项目复制到新目录并转为 general
python -m doc_tool.cli migrate --project <旧项目目录> --target <新项目目录>
```

迁移语义：
- **复制到新目录**，源项目全程只读、保持不变。
- 重写 `documentType: general`，并把 `content/<旧类型>`/`assets/<旧类型>`
  移到 `content/general`/`assets/general`。
- 结构、资源引用与试构建全部通过后才原子发布；任一失败则清理暂存并回滚，
  源项目仍可用。
- 迁移报告写入目标项目 `logs/migration.json`。

> 提示：公共版**不再新建** requirement/design 项目；如需新文档，请用通用大文档
> 流程创建后迁移或重建。

## 4. 回滚

- **代码回滚**：公共版与内部版安装隔离，卸载公共版不影响内部版；内部版仍可
  读取未被改写的旧项目与设置。
- **设置回滚**：旧设置目录从未被修改，删掉 `~/.doctool` 即可回到旧版偏好。
- **项目回滚**：迁移不修改源项目，删除迁移目标目录即可回到迁移前状态。

## 5. 不兼容入口（已退出公共产品面）

以下入口在公共版中**不再可用**：

- 新建需求/详细设计项目（向导与 CLI 只创建通用项目）。
- `build requirement|design|all` 旧构建命令（请改用 `build --project <目录>`）。
- 内部旧版启动脚本与需求/设计/全部生成 `.cmd` 兼容入口不再进入公共发行；
  请使用 `start-doc-tool.cmd`。
