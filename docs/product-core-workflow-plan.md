# 主功能优化计划：导入、编辑、预览与导出

编制日期：2026-10-01。面向企业研发文档团队，承接 [流程与兜底原则](product-flow-fallback-policy.md) 和 [V3 后续规划](product-plan-v3.0-v3.3.md)。目标是让现有功能更好用：**文档进得来、正文改得动、预览对得上、结果交得出，外部修改能接回来。**

本轮是规划，业务功能尚未实施。新增独立 change `product-core-import-export`，8 批/40 项，优先排在 V3.0 正文复用之前；不把新需求塞进正在执行的 V2.6～V2.9，不修改其任务勾选。发布版本在实施收尾确定。

易用性增补：[默认交互与验收契约](product-core-usability-contract.md)。先交付单份导入→编辑→快速Word→直接打开；随后补完整多格式/选章与批量/精细排版。要求并入现有40项，入口要实际调用服务，普通路径不要求用户配置所有参数。

## 1. 主功能优化清单

| 主功能 | 优先级 | 本次重点 | 用户得到的结果 |
|---|---|---|---|
| Word 导入 | P0 | 普通模式快速接管、无标题单章、跳级整理、标题前正文保留 | 不必先回 Word 整理全部样式，就能开始维护正文 |
| 导入保真 | P0 | 原件/复杂对象位置、明确参考文本或占位、报告定位 | 公式、脚注、文本框暂不支持时仍能工作，并知道哪里要补 |
| 导入范围 | P1 | 勾选章节、祖先结构/图片依赖、预览调整与实际导入一致 | 只接管需要维护的部分，不被迫导入整份文档 |
| 导入提效 | P1 | 映射预设、Word 多文件独立项目、MD 顺序/资源入口 | 同类文档少配一次参数，一份失败不影响其它文档 |
| 日常编辑 | P0 | 接好现有章节调整/拆合、图片修复/片段和导入缺口定位 | 导入后直接整理、修复、续写，操作能撤销和正常保存 |
| 预览与检查 | P0 | 当前缓冲/保存版本明确、统一范围/变量/图表/题注、旧预览提示 | 看到和导出的是同一次内容，未保存文字不会悄悄漏掉 |
| Word 导出 | P0 | 一个出稿入口、整份/当前章/勾选章、常用设置、安全新名 | 日常一次操作拿到 Word，不必到多个工具拼流程 |
| PDF/HTML 导出 | P0 | 同轮多格式、PDF 用本轮 DOCX、离线 HTML 自带资源 | 一次出稿多份成果，某格式失败先拿已完成结果 |
| Word 排版 | P1 | 普通图宽度、普通表格表头/跨页/列宽、章级横向/分页 | 常见宽表和大图少做手工修复，复杂表格默认原样保留 |
| 源码交付 | P1 | 所选 Markdown/资源/底模/设置 ZIP，原件可选，搬目录再打开 | 交给同事一份能继续维护的项目，不只有 PDF |
| 再次修订 | P0 | 接入既有重导入差异/章节选择/冲突跳过、来源版本 | 外部改过的 Word 能接回项目，无冲突的已选章先应用 |
| 大文档体验 | P1 | 少重复解析、阶段/当前章节、取消与继续编辑、可读稿先开放 | 有反馈，先用可用结果；不预先承诺未实测速度 |

P0 应优先交付；先让普通导入和快速Word完整跑通，再补同轮多格式/选章；P1补效率和版式，不成为最先交付的门槛。所有普通流程先给可用内容，严格交付作为明确选择。复杂内容保留事实在详情明确，常用页不让用户逐项配置。

## 2. 导入与开始编辑应怎样优化

### 2.1 默认先接管，细调可以后做

首页主要给“导入文档”“新建文档”和最近文档“继续编辑”。导入自动识别Word/Markdown并真实调用对应建项服务，格式转换/模板填充在更多工具里。标准Word自动给章节树，无标题默认单章；大纲与映射细调放“调整章节/高级设置”，不强迫采用弱推断候选。

名称、有效目录和版本用已有可信值或默认补齐，编号可空；Word默认保持源格式，Markdown用通用模板。源已选后常规路径最多2次主要提交进入编辑；首页单份成功可直接继续工作，已有工作区发起时保留当前内容并给打开新文档动作。

标题前正文保留在明确范围内；原件保留在项目里。复杂对象集中显示处理结果，不再因公式/脚注等逐项要求风险勾选才能下一步。真正无法读取或无法形成有效项目才使对应输入失败。

### 2.2 缺口有位置，不丢在长日志里

导入结果先给“进入编辑”和待完善数量，再按类型/章节归并问题，默认最多3项可直接处理的问题，其余在详情。正文保留缺口位置，点击可定位章节、补图片或查原件；细分的可编辑保留、文本降级、原件留存和未完成对照都可查。

### 2.3 范围和重复工作更省力

可勾选需要接管的章节，保留依赖图片和祖先结构；样式映射可保存为预设，失配回自动/单章。Word 多文件按“一份一个项目”处理，失败项单独重试；Markdown 多文件按确认顺序建立一份项目。DOC 没有 Word 时保留输入、标记待转换，其它 DOCX 继续。

### 2.4 常用编辑和恢复就近可达

复用已有标题/列表/表格/图片工具栏、图片粘贴、片段、撤销与草稿。常用动作和保存/导出可见，其它工具放更多；标题显示可理解的级别，一次插入可一次撤销。状态明确“未保存/草稿已保存/已保存”，保存失败保留缓冲并给重试/另存；草稿不冒充源文件保存。先修入口和布局，不新增完整富文本编辑器。

## 3. 导出应怎样优化

### 3.1 一个入口，先明确这次出什么

首用主按钮“导出Word”，默认整份/当前内容/有效目录；未保存修改用“包含2章未保存修改”摘要说明，无逐章确认。用户打开设置才调整多格式、选章、保存版本、模板/排版与严格检查。成功后记格式/有效目录/兼容样式，但不隐式继承上次部分范围、保存版本或严格模式。

生成并打开可读Word的普通路径最多2次主要操作。捕获缓冲不自动保存或清空脏状态；旧HTML入口的保存版本默认通过适配明确保留。目录失效回可用默认位置并显示实际路径，原输入/设置保留。

任务开始后固定一轮内容，继续编辑不影响本轮。结果显示捕获时间、范围与来源；后续变化可再次出稿。选章输出按项目顺序，范围外交叉引用有说明，不偷偷加入未选正文。

### 3.2 多格式一起出，失败部分后补

DOCX 和离线 HTML来自同一快照；Word 版式 PDF从本轮 DOCX转换。没有 Word先拿可读 DOCX/HTML，PDF标记待转换；不把未刷新稿显示为正式成功。已存在的结构参考 PDF仅在明确选择时使用并标明版式近似。

可读Word先形成稳定副本即开放“打开Word”，字段刷新/PDF等后台继续，用户能继续编辑或取消。结果先显示各格式实际成果和打开动作，再显示归并问题；技术日志可展开。

“补PDF/重试刷新”使用原轮内容；“按最新内容重新生成”明确开始新轮。缺图直接定位替换，复杂对象直接查原件，输出位置可就地更换；无需重新选所有输入。取消保留完成格式，同名或文件锁采用安全新名或单格式失败。

### 3.3 优先解决高频版式和源文件交付

默认遵循底模。普通图片按正文宽度等比缩小；普通表格支持合理列宽、重复表头和跨页行设置；横向章与章前分页明确选择。复杂合并表格沿用已有原样机制，超宽提醒定位，不隐藏列或任意缩小字号。

源码 ZIP包含所选 Markdown、依赖资源、底模/必要设置、来源与结果索引，原件可选择包含；可搬目录再次打开。包不带用户凭据、.git、缓存和无关历史。缺资源保留占位并列缺项，不把不完整包说成完全自足。

## 4. 执行顺序与已有功能的关系

| 批次 | 内容 | 项数 | 直接依赖 |
|---|---|---|---|
| CORE-A | 真实接口核对、共同契约、用途入口与夹具 | 4 | 当前服务可读，无整版完成前置 |
| CORE-B | 普通导入、无标题/跳级、有效项目回退 | 5 | A；复杂缺口与 C 联合验收 |
| CORE-C | 原件记录、正文缺口、来源查阅与版本 | 5 | A/B；既有 fidelity/重导入 |
| CORE-D | 选章、映射预设、Word 文件批次/MD 入口 | 5 | A/B/C |
| CORE-E | 当前缓冲/保存版本快照、同源预览和进度 | 5 | A；现有章节/变量/PreparedSource |
| CORE-F | 统一多格式出稿、格式状态和局部重试 | 6 | E；缺口展示用 C |
| CORE-G | 普通排版、横向节、源码包 | 5 | E/F；章级策略用现有内核 |
| CORE-H | CLI、场景/性能证据、说明与收尾 | 5 | 各相关用例已可验证 |

默认依文件顺序执行，优先主流程可按 **A→B→C→E→F→D→G→H**；各阶段及时执行H相关检查与说明。最先交付“普通导入→原件可查→修改→快速Word→直接打开”，随后补全多格式/选章和D/G；未完成任务保持未勾选，首阶段不等于整个change完成。

已有拖拽、样式预览、格式互转、模板配方、章节调整、图片修复、HTML和重导入不再重复建设。本包补贯通能力；V3.0复用本包的有效快照，V3.2再补持久队列/换机任务包，两者范围不同。版本发布号收尾时依据实际最高版本决定。

## 5. 验收与度量

必须跑通：标准/无标题 Word接管；复杂对象/缺图默认继续并留可查原件；三份文件部分成功；缓冲修改后选两章同轮 Word/PDF/HTML；缺 Word与单格式失败；原轮重试；只读外部出稿/取消/同名；宽表/大图/横向章；源码搬目录打开；外部 Word差异再次导入。

自动证据包括输入/源文件hash不变、各格式captureId/范围一致、未保存缓冲不被隐式写回、旧正式产物不受失败尝试影响、普通/严格结果区分。Word版式与冻结包需实机证据，有环境才执行，无环境单列待验收。

同机器记录导入/出稿阶段耗时、重复解析次数、峰值内存和取消响应，并记录导入点击步骤与恢复时是否重选参数。先建立基线，再按真实瓶颈优化，不用缺少测试依据的“秒开、100%保真”作为指标。

同时按U-1～9检验默认值、最多两次主要提交/生成打开、上次范围不误继承、结果边生成边可打开、直接补救、草稿状态、基础窗口与键盘可达。计数口径、缩放环境与异常路径见 [易用性契约](product-core-usability-contract.md)，它与功能验收一起执行。
