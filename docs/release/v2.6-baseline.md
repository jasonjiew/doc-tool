## 签名材料与公开导出修复（1.4）

发现仓库忽略目录 scripts/cert-out 仍存放本机私钥/密码及备份，sign_artifacts.ps1 默认读取该目录。Git 当前跟踪列表未包含私钥/密码，但公开导出仅按跟踪文件与业务前缀过滤，误跟踪时缺少第二道保护。

本批将该目录 5 个文件移到 `C:/Users/18098/.doctool/signing`，迁移前后逐文件 SHA-256 一致，原目录已不存在；不记录私钥、密码或其 hash。生成/签名默认仓库外目录，可配置 CODE_SIGNING_DIR；CI 仍支持 CODE_SIGNING_PFX/PASSWORD。仓库内私钥、仓库内密码文件及配置不完整会拒绝；无配置可跳过。公钥打包/发布引用同步使用外部目录，仅 .cer 可分发。

共享 is_sensitive_file 防止旧签名目录、私钥扩展及 .pfx.bak/密码备份进入净化导出，目录扫描与 Git 跟踪扫描同源。新增真实临时文件导出/扫描回归，以及 Windows PowerShell 的无配置、仓库私钥拒绝、密码缺失和不输出密码场景；测试只用合成材料，不触发真实证书/远端发布。

`packaging/scan_leaks.py --strict` 退出 0：本机现有 dist/DocTool、packaging/Output 与 Git 跟踪文件通过；未指定 --source-root 的品牌内容扫描明确跳过。test_public_export 覆盖真实净化导出和模拟误跟踪敏感文件；不宣称完整公共发布验收。真实 PE 签名、时间戳及目标机器信任在 26-F 待验收。
