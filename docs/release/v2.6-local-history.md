## 实现与数据

新增 `doc_tool/application/content/local_history.py::LocalHistoryStore`，由已有 ContentWriter 持有。
数据位于项目 `.state/local_history/<path-key>/<snapshot-id>/content.md` 与 `metadata.json`；同文件 `index.json` 是可重建摘要。path-key 为规范相对路径的 SHA-256（Windows 大小写按同一路径处理）；snapshot-id 用 UTC 微秒时间加 UUID。
schemaVersion 1 元数据记录 snapshot_id、rel_path、created_at、sha256、size_bytes、operation，来源为 save / replace / refactor / restore。快照正文按原始字节保存，回读校验字节数和 SHA-256；不可读取条目提供问题说明，不删除原快照。

ContentWriter 在覆盖前先保存旧正文；本地模式继续维护 .bak，Git 模式正常不生成 .bak，但同样保存本地历史。历史写入失败时，无论是否 Git 项目都尝试本次旧正文的 .bak 并回读验证；旧的或损坏的 .bak 不算可靠恢复点。历史与 .bak 均不可用则返回 written=False，保留正文及编辑缓冲；索引失败与配额清理失败不撤销成功保存，警告附在 WriteResult.warnings。

复用原子替换函数，新增 byte 入口并使用唯一临时文件名，避免多个文件写入共用临时路径及固定 .tmp 链接风险。历史根、元数据、快照及清理路径验证项目边界，禁止历史路径链接/junction；.bak 不向符号链接写入。工作区只读状态同步给写入器/历史服务，禁止保存和恢复。

默认每文件保留最近 20 份、目标 50 MiB，在成功正文写入后淘汰最旧合法项。至少保留最新恢复点和最近一次恢复前的快照；显式 protected 参数保留进行中操作项。必要单份超限或两个保护点超限会保留并报告实际体积。损坏/未知条目不作为可自动删除缓存，报告后保留。

列表/预览/差异只读扫描快照元数据；坏索引不遮住合法历史，读取不重写索引。`rebuild_index()` 明确重建；读不到旧 .bak 只警告，不遮住其他合法快照。
接口为 list_entries / preview / read_bytes / diff / restore；支持仅有旧 .bak 的项目，legacy-bak 在恢复前先读入，再由 ContentWriter 保存当前内容并恢复。恢复要求 confirmed=True、同项目 writer 和写权限，支持 expected_sha256 拒绝预览后变化；取消不写入。

编辑保存、全局替换和引用重构继续调用既有写入器，保存/替换界面显示降级提醒。已有 ChangeManifest 兼容增加 historyId，旧记录字段可缺省；无 .bak 时事务回滚可使用验证后的快照。故障测试发现 refactor 的按数量回滚漏掉已去重的 edit，已复用 rollback_keys 补回成功写入的文件；旧 .bak 回滚语义保持。
