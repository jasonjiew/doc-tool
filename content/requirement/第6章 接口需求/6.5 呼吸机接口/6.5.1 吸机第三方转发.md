| 需求编号 | BREATHE-THIRD-FORWARD-001 |
| --- | --- |
| 功能概述 | 呼吸机第三方转发功能用于支持外部合作平台接收康尚云平台内的呼吸机治疗结果数据。第三方可按“设备维度”或“患者维度”建立转发关系；当呼吸机产生符合条件的数据后，系统自动将数据转发给对应第三方平台。 |
| 业务目标 | 1. 满足第三方按设备或按患者接入呼吸机数据的不同场景；2. 支持同一台设备同时服务多个第三方平台；3. 第三方转发失败不影响康尚云平台自身的数据入库、报告生成和业务处理；4. 转发过程可追踪、可重试、可联调。 |
| 适用对象 | 第三方平台、运营/交付人员、测试人员、产品人员。 |
| 总体验收标准 | 第三方可完成绑定、解绑、数据接收、失败追踪和重推验证；同一设备多平台互不影响；第三方异常不影响呼吸机主业务链路。 |

#### 业务模式说明

<!-- TBL:style=43 type=auto tw=0 cols=1515,2678,3034,2409 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 -->
| 模式 | 说明 | 适用场景 | 关键规则 |
| --- | --- | --- | --- |
| 设备维度转发 | 第三方只绑定设备，不绑定具体患者；系统按设备和时间范围转发该设备产生的数据。 | 第三方只关注设备产生的全部治疗结果，不需要区分患者。 | 不要求患者信息；同一设备可绑定多个第三方；需使用新版回调协议。 |
| 患者维度转发 | 第三方绑定设备和具体患者；系统只转发该患者在该设备上的治疗数据。 | 第三方关注特定患者的治疗数据，需要按患者归属管理。 | 必须提供并校验患者资料；患者资料不足时绑定失败；兼容旧版回调协议。 |

#### 第三方绑定

<!-- TBL:style=43 type=auto tw=0 cols=1590,2389,3707,1950 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 -->
| 需求标识 | 产品需求 | 验收标准 | 备注 |
| --- | --- | --- | --- |
| REQ-THIRD-BIND-001 | 第三方可按设备维度建立转发关系。 | 1. 第三方提供有效平台身份和设备信息时，系统可完成设备维度绑定；2. 绑定时不要求患者资料；3. 设备维度绑定不影响同设备已有患者维度绑定。 | 面向新接入平台使用。 |
| REQ-THIRD-BIND-002 | 第三方可按患者维度建立转发关系。 | 1. 第三方提供有效平台身份、设备信息和患者资料时，系统可完成患者维度绑定；2. 患者资料、设备与患者关系、机构归属校验通过后才允许绑定；3. 患者维度绑定不影响同设备已有设备维度绑定。 | 兼容已有患者维度接入方式。 |
| REQ-THIRD-BIND-003 | 患者资料不足时，绑定必须明确失败。 | 1. 缺少患者资料、设备患者关系或机构归属信息时，系统返回明确失败原因；2. 系统不创建临时绑定或待补全绑定；3. 资料补齐后，第三方需重新发起绑定；4. 绑定失败不影响设备维度转发和平台主业务。 | 避免后续自动补偿造成关系不清晰。 |
| REQ-THIRD-BIND-004 | 同一设备支持绑定多个第三方平台。 | 1. 同一设备可分别绑定 A、B 等多个平台；2. A 平台绑定失败不影响 B 平台绑定；3. 各平台后续接收数据互相独立。 | 平台之间相互隔离。 |
| REQ-THIRD-BIND-005 | 系统应防止重复绑定。 | 1. 同一平台、同一设备只能存在一个有效设备维度绑定；2. 同一平台、同一设备、同一患者只能存在一个有效患者维度绑定；3. 重复绑定时返回明确失败或已存在提示；4. 解绑后允许重新绑定。 | 面向业务关系唯一性，不暴露技术实现。 |
| REQ-THIRD-BIND-006 | 已有旧接入方式保持兼容。 | 1. 旧接入方未声明转发模式时，系统仍按患者维度处理；2. 旧接入方的原绑定、解绑和回调行为不因本次改造改变。 | 保障存量平台平滑升级。 |

#### 第三方解绑

<!-- TBL:style=43 type=auto tw=0 cols=1472,2025,3730,2409 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 -->
| 需求标识 | 产品需求 | 验收标准 | 备注 |
| --- | --- | --- | --- |
| REQ-THIRD-UNBIND-001 | 第三方可解除设备维度绑定。 | 1. 设备维度解绑成功后，该平台不再接收该设备的设备维度数据；2. 不影响同设备其他平台；3. 不影响同设备患者维度绑定。 |  |
| REQ-THIRD-UNBIND-002 | 第三方可解除患者维度绑定。 | 1. 患者维度解绑成功后，该平台不再接收该患者的数据；2. 不影响同设备其他患者绑定；3. 不影响同设备设备维度绑定；4. 不影响其他平台绑定。 |  |
| REQ-THIRD-UNBIND-003 | 解绑只影响后续转发。 | 1. 解绑不删除历史呼吸机治疗数据；2. 解绑不删除历史转发记录；3. 解绑后新产生或重推的数据按最新绑定关系判断是否转发。 |  |

#### 数据转发

<!-- TBL:style=43 type=auto tw=0 cols=1493,2207,3527,2409 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 -->
| 需求标识 | 产品需求 | 验收标准 | 备注 |
| --- | --- | --- | --- |
| REQ-THIRD-FWD-001 | 呼吸机结果产生后，系统自动触发第三方转发。 | 1. 在线治疗结果、重算结果、SD 卡导入结果和定时统计结果均可进入转发流程；2. 没有有效第三方关系时不触发外发；3. 转发不需要人工手动操作。 |  |
| REQ-THIRD-FWD-002 | 设备维度转发按整台设备取数。 | 1. 无患者信息时仍可转发设备维度数据；2. 同一天同一设备存在多个患者分时段使用时，设备维度数据覆盖完整设备时间范围；3. 设备维度数据不按患者切割。 |  |
| REQ-THIRD-FWD-003 | 患者维度转发按绑定患者取数。 | 1. 有有效患者绑定时正常转发该患者数据；2. 缺少患者标识时跳过患者维度目标；3. 患者维度数据不包含其他患者数据。 |  |
| REQ-THIRD-FWD-004 | 多平台按平台分别转发。 | 1. 同一设备命中多个平台时，系统应逐个平台处理；2. A 平台失败不影响 B 平台接收；3. 每个平台都有独立的转发结果记录。 |  |
| REQ-THIRD-FWD-005 | 第三方异常不得影响平台主业务。 | 1. 第三方不可用、超时、响应失败或转发记录失败时，不影响呼吸机原始数据入库；2. 不影响分钟聚合、报告生成和结果处理；3. 系统应保留异常记录供后续处理。 |  |
| REQ-THIRD-FWD-006 | 系统应避免同一数据重复转发。 | 1. 同一平台同一条业务数据已成功转发后，重复触发时不再次发送；2. 不同平台接收相同设备数据时互不影响；3. 已成功记录不得被后续失败记录覆盖为失败。 |  |
| REQ-THIRD-FWD-007 | 系统应支持失败补偿。 | 1. 第三方调用失败后，系统记录失败原因；2. 支持按失败记录自动重试或人工重推；3. 重推只影响指定失败平台，不修改其他平台的成功结果。 |  |
| REQ-THIRD-FWD-008 | 转发耗时应可控。 | 1. 第三方长时间无响应时，系统按约定超时时间结束本次调用；2. 单个平台超时不阻塞其他平台；3. 当平台数量较多导致总耗时变长时，应在上线评估中确认处理策略。 | 具体超时配置见详细设计。 |

#### 回调协议与数据内容

<!-- TBL:style=43 type=auto tw=0 cols=1493,1822,3912,2409 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 -->
| 需求标识 | 产品需求 | 验收标准 | 备注 |
| --- | --- | --- | --- |
| REQ-THIRD-CB-001 | 系统兼容旧版患者维度回调。 | 1. 存量患者维度平台可继续按原格式接收数据；2. 存量平台未升级时不强制改造。 |  |
| REQ-THIRD-CB-002 | 设备维度转发必须使用新版回调。 | 1. 设备维度数据必须能在回调内容中明确标识为设备维度；2. 患者信息允许为空；3. 未配置新版回调的平台不发送设备维度数据，并记录配置问题。 |  |
| REQ-THIRD-CB-003 | 新版回调应提供稳定消息标识。 | 1. 同一条业务数据多次重推时，消息标识保持稳定；2. 第三方可根据消息标识进行去重；3. 系统也可根据该标识追踪转发记录。 |  |
| REQ-THIRD-CB-004 | 新版回调应包含检查数据。 | 1. 回调内容包含约定的治疗结果和设置项检查数据；2. 平台配置不同模板时，系统按平台模板输出对应检查项；3. 未配置模板时使用默认检查项。 | 检查项明细由接口联调文档维护。 |
| REQ-THIRD-CB-005 | 第三方响应需可识别成功或失败。 | 1. 第三方返回成功码时，系统记录为成功；2. 返回失败码、空响应、无法解密或无法识别业务码时，系统记录为失败；3. 失败记录可用于后续重推。 |  |

#### 设备维度结果快照

<!-- TBL:style=43 type=auto tw=0 cols=1461,1757,4009,2409 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 -->
| 需求标识 | 产品需求 | 验收标准 | 备注 |
| --- | --- | --- | --- |
| REQ-THIRD-SNAP-001 | 系统应为设备维度转发准备完整设备结果。 | 1. 设备维度转发按设备和时间范围准备结果；2. 不因患者缺失而放弃设备维度转发；3. 多患者使用同一设备时，转发结果按设备整体口径生成。 |  |
| REQ-THIRD-SNAP-002 | 可复用完整结果时不重复计算。 | 1. 已有完整设备结果时直接用于转发；2. 不重复生成额外结果；3. 转发内容与设备完整结果一致。 |  |
| REQ-THIRD-SNAP-003 | 多患者混合场景应生成设备口径结果。 | 1. 同一设备时间范围内存在多个患者结果时，系统生成设备口径结果；2. 设备口径结果用于设备维度转发和重推；3. 设备口径结果不覆盖真实患者结果。 |  |
| REQ-THIRD-SNAP-004 | 设备口径结果不得影响患者侧展示。 | 1. 患者报告不展示设备口径结果；2. 患者维度转发不使用设备口径结果；3. 患者统计不被设备口径结果污染。 |  |

#### 转发记录与运营追踪

| 需求标识 | 产品需求 | 验收标准 | 备注 |
| --- | --- | --- | --- |

#### 异常与边界处理

<!-- TBL:style=43 type=auto tw=0 cols=2361,3525,3753 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 -->
| 场景 | 处理规则 | 验收标准 |
| --- | --- | --- |
| 第三方平台未启用 | 不参与数据转发。 | 平台停用后不再收到新数据。 |
| 绑定关系已解除 | 不参与后续数据转发。 | 解绑后新数据和重推数据均不再发送给该关系。 |
| 患者资料不足 | 患者维度绑定失败。 | 返回明确原因，不创建临时关系。 |
| 无患者标识 | 跳过患者维度目标，继续处理设备维度目标。 | 缺少患者信息时设备维度仍可发送。 |
| 第三方响应失败 | 记录失败并支持重试或重推。 | 失败平台可单独补偿。 |
| 多平台同时命中 | 平台逐个处理，互不影响。 | 一个平台失败不影响其他平台成功。 |
| 重复触发同一数据 | 已成功的不重复发送。 | 重复触发不会产生重复成功推送。 |
| 敏感信息 | 日志和联调输出应脱敏。 | 身份证号、密钥、明文请求等敏感内容不直接暴露给无关人员。 |
