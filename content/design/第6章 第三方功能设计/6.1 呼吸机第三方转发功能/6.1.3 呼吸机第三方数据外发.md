#### 功能描述

<!-- TBL:style=45 type=auto tw=0 cols=1590,8048 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 va=top -->
| 需求编号 | BREATHE-THIRD-FORWARD-001 |
| --- | --- |
| 设计编号 | Design-THIRD-VENTILATOR-FORWARD-001 |
| 功能描述 | 系统在呼吸机结果数据产生后，通过 MQ 异步链路将数据转发给符合绑定关系和平台配置的第三方系统。外发支持设备向和患者向两种数据范围，支持同一设备多平台逐个处理。 |
| 设计定位 | 数据外发链路与绑定、解绑分离；绑定关系只作为目标匹配依据，真正的第三方 HTTP 调用由 MQ 消费端统一执行。外发异常不得影响呼吸机主链路事务。 |
| 核心机制 | 1. 多入口触发：结果入库、重算结果、SD 卡导入、定时统计均可触发。 2. MQ 解耦：前置链路只判断是否需要投递 MQ。 3. 目标查询：按设备、患者和绑定配置查询全部有效第三方目标。 4. 模式分流：DEVICE_ONLY 按设备时间窗口取数，PATIENT_BOUND 按患者绑定取数。 5. 协议分流：V1 仅支持患者向，V2 支持设备向和患者向。 6. 平台隔离：每个平台独立校验、幂等、组包、调用和记录日志。 |

| processingResultData | 结果集入库后触发外发 | BreatheDataResultDto -> R | 保存治疗结果后组装外发上下文并调用 handleThirdPartyPush。 |

| pushThirdData | 单平台外发执行器 | 目标、结果数据、时间、接口类型 -> void | 每个平台独立权限校验、幂等检查、payload 组装、HTTP 调用和日志记录。 |

#### 核心逻辑

<!-- TBL:style=45 type=auto tw=0 cols=936,7200,1718 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 -->
| 序号 | 设计规则 | 关注点 |
| --- | --- | --- |
| 1 | 呼吸机外发由结果入库、重算结果、SD 卡导入、定时统计四类入口触发。 | 处理规则 |
| 2 | 非定时入口通过 handleThirdPartyPush 做前置判断；定时统计入口可直接发送 MQ。 | 处理规则 |
| 3 | handleThirdPartyPush 只负责轻量绑定检查和 MQ 投递，不直接调用第三方。 | 约束规则 |
| 4 | checkThirdPartyDeviceBinding 保持 R<Boolean>，只判断设备是否可能存在当前有效第三方目标。 | 约束规则 |
| 5 | 绑定检查异常和 MQ 投递异常只记录日志，不影响呼吸机主流程。 | 异常与边界 |
| 6 | MQ 消费端调用 pushThirdResultData，再按 flag 分流到 scheduledMothedPushData 或 importMothedPushData。 | 约束规则 |
| 7 | 外发执行前通过 getThirdAllDeviceByCondition 查询全部有效目标，不得只返回第一个。 | 异常与边界 |
| 8 | 有效目标需满足平台启用、绑定未删除、设备有效、租户匹配等条件。 | 约束规则 |
| 9 | DEVICE_ONLY 目标按 deviceCode 匹配，不要求 patientId。 | 约束规则 |
| 10 | PATIENT_BOUND 目标按 deviceCode + patientId 匹配；无 patientId 时跳过患者向目标。 | 异常与边界 |
| 11 | DEVICE_ONLY 按设备和时间窗口准备设备口径数据，不按患者使用时段过滤。 | 约束规则 |
| 12 | PATIENT_BOUND 按设备、患者和正式绑定关系准备患者向数据。 | 约束规则 |
| 13 | PATIENT_BOUND + V1 使用兼容 payload；V2 支持设备向和患者向。 | 兼容与上线 |
| 14 | DEVICE_ONLY + V1 属于平台配置错误，只写业务/配置错误日志后跳过，不发送不完整 payload，不发布 device_third_log 失败记录。 | 异常与边界 |
| 15 | V2 payload 需包含协议版本、稳定 messageId、数据作用域、设备信息、可空患者信息、时间窗口、dataId、checkData、时间戳和签名；第一批 V2 复用现有 party_url。 | 约束规则 |
| 16 | 第一批 checkData 使用代码侧白名单和 V2 默认模板，不新增动态模板表，不执行数据库中的表达式、脚本或反射方法名。 | 兼容与上线 |
| 17 | 每个平台目标独立 try/catch，A 平台失败不影响 B 平台。 | 异常与边界 |
| 18 | 平台级幂等维度至少包含 thirdId + interfaceType + deviceCode + explicit patient null/value + businessTime + deliveryCarrier。 | 处理规则 |
| 19 | deliveryCarrier 优先使用 V2 messageId，其次使用 dataId，最后使用 businessId；呼吸机 V2 外发必须把 messageId 写入日志 delivery_message_id。 | 约束规则 |
| 20 | 日志表只保留最小必要投递字段：delivery_identity、delivery_message_id、delivery_data_id、active_delivery_identity_hash；不保留 delivery_business_id、delivery_patient_key、delivery_business_time 三个可推导派生列。 | 约束规则 |
| 21 | delivery_identity 构造缺少 thirdId、interfaceType、deviceCode、deliveryCarrier 或 businessTime 任一维度时，日志状态置为失败，不生成投递身份，不走唯一 upsert。 | 异常与边界 |
| 22 | 不同 thirdId 不能互相压制；同一平台重复数据不重复发送。 | 处理规则 |
| 23 | 已成功日志不得被后续重复失败覆盖为失败。 | 异常与边界 |
| 24 | 调用第三方前通过 Redis guard 抑制同一投递身份短期并发重复；guard 后端异常时 fail-open，由日志唯一身份兜底。 | 异常与边界 |
| 25 | 第三方 HTTP 调用失败后记录平台级失败日志，支持自动重试或人工重推。 | 异常与边界 |
| 26 | 重推只处理指定失败平台，不影响其他平台成功记录。 | 异常与边界 |
| 27 | 呼吸机多平台外发不得沿用当前 RestTemplatePostUtils 600000 ms 作为单平台有效超时，需使用有界、可配置连接和读取超时；第一批默认连接超时 10000 ms、读取超时 60000 ms，对应 hcp.ventilator.outbound.connect-timeout-ms 与 hcp.ventilator.outbound.read-timeout-ms。 | 异常与边界 |
| 28 | 串行外发最坏耗时按 target count  (connectTimeout + readTimeout) 估算；当平台数量导致耗时超过 worker/scheduler 预算时，应在后续变更中采用更严格超时、有界并发或队列拆分。 | 约束规则 |
| 29 | 第一批不新增动态 checkData 配置表、不新增 V3 payload、不新增 device_third_log.idempotency_key、不做 device_party_relation NOT NULL 治理。 | 兼容与上线 |

#### 日志投递身份与迁移约束

<!-- TBL:style=45 type=auto tw=0 cols=1365,7843 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 -->
| 设计项 | 说明 |
| --- | --- |
| 投递身份格式 | v1 |
| 载体优先级 | delivery_message_id 优先，其次 delivery_data_id，最后 business_id。呼吸机 V2 外发由 V2VentilatorPayloadBuilder 生成稳定 messageId 并写入 delivery_message_id。 |
| 业务时间 | 优先使用 real_data_time 当天零点；没有 real_data_time 时使用 data_time。业务时间不再单独落库为派生列。 |
| 患者维度 | patient_id 为空时推导为 NULL_PATIENT，非空时推导为 PATIENT:{patientId}。患者键不再单独落库为派生列。 |
| 落库字段 | 仅保留 delivery_identity、delivery_message_id、delivery_data_id、active_delivery_identity_hash。 |
| 废弃字段 | 旧设计中的 delivery_business_id、delivery_patient_key、delivery_business_time 不再作为正式表结构保留；开发库如已执行旧脚本，由迁移脚本删除。 |
| 唯一保护 | active_delivery_identity_hash 为 MySQL 8 生成列，仅对未删除且投递身份非空的可重试日志生成 SHA-256，并通过唯一索引阻断重复有效身份。 |
| 历史回填 | 迁移脚本先回填 delivery_data_id，再按运行时公式重算 delivery_identity，不依赖旧派生列。 |
| 上线审计 | 加唯一索引前输出重复投递身份、缺失必要维度、身份长度和回滚参考导出；存在重复身份时唯一索引应主动失败，由人工先清理历史数据。 |

核心处理规则：

1. DeviceThirdLogServiceImpl.saveLog 对可重试接口调用 prepareDeliveryIdentity。 2. prepareDeliveryIdentity 若发现 thirdId、interfaceType、deviceCode、deliveryCarrier、businessTime 任一为空，写入失败状态和缺失原因，不生成 delivery_identity。 3. 具备投递身份时走 upsertRetryableDeliveryLog，由唯一索引和 ON DUPLICATE KEY UPDATE 处理重试更新。 4. 已成功日志遇到后续失败时保留成功状态和成功请求/响应信息；失败重试按规则增加 retry_times 并更新失败响应。
