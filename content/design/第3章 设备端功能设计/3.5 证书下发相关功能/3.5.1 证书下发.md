一、Netty CERT 协议接口

<EMPTY_PAR/>
<!-- TBL:style=44 type=dxa tw=9000 cols=1800,1800,1800,1800,1800 cm=90,110,90,110 ind=110:dxa lay=autofit bd=single:auto:4:0 va=center -->
| 子命令 | 名称 | 请求状态 | 服务端成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| 0x01 | 请求 Root CA | 0x00 REQ_NORMAL | 0x05 SUCCESS + Root CA Payload | Redis 未就绪时返回 0x06 WAIT，并触发证书生成 MQ。 |
| 0x02 | 请求设备证书 | 0x00 REQ_NORMAL | 0x05 SUCCESS + Device Cert Payload | 返回设备客户端证书。 |
| 0x03 | 请求私钥和 Token | 0x00 REQ_NORMAL | 0x05 SUCCESS + Private Key + Token Payload | Payload 包含私钥长度、私钥、Token 长度、Token。 |
| 0x04 | 写入成功确认 | 0x01 WRITE_OK | 0x09 CONFIRM_OK | 设备确认写入成功后，服务端同步安装状态并销毁私钥。 |

#### 核心逻辑

<EMPTY_PAR/>
<!-- TBL:style=44 type=dxa tw=9000 cols=4500,4500 cm=90,110,90,110 ind=110:dxa lay=autofit bd=single:auto:4:0 va=center -->
| 功能点 | 核心逻辑 |
| --- | --- |
| CERT 指令接入 | Netty 解码器识别 CERT 协议头后，将请求路由到证书下发处理器，不影响原有 P/D 指令、结果集、OTA、时间同步等旧链路。 |
| 设备号校验 | 设备号有效长度必须为 13 位，不合法时直接返回 SN_FAIL，不触发证书生成。 |
| 证书缓存读取 | 服务端优先读取 Redis Key gl:cert:{deviceSn}，当 status=1 且对应字段存在时返回证书数据。 |
| 证书生成触发 | Redis 缓存不存在或未就绪时，Netty 发送证书生成 MQ，Device 服务消费后从 MinIO 加载 CA 证书和私钥，生成设备证书、私钥和动态 Token，并写入 Redis。 |
| Root CA 下发 | 设备发送 0x01 时，服务端返回 Root CA；首次 0x01 生成成功后，异步补建 MySQL 证书部署主表、证书明细和下发项记录。 |
| 设备证书下发 | 设备发送 0x02 时，服务端返回设备证书，并记录 Redis 交互状态 0x02 已下发。 |
| 私钥和 Token 下发 | 设备发送 0x03 时，服务端组合返回私钥和 Token，格式为私钥长度、私钥内容、Token 长度、Token 内容，并记录 0x03 已下发。 |
| 写入成功确认 | 设备发送 0x04 且状态为 WRITE_OK 时，服务端检查 0x01、0x02、0x03 是否已下发，确认后发送私钥销毁 MQ。 |
| 安装状态同步 | Device 服务消费私钥销毁 MQ 后，先调用安装状态同步逻辑，将证书状态更新为已安装，将下发记录更新为部署成功。 |
| 私钥销毁 | 安装状态落库后，删除 Redis 中的 deviceKey 字段，实现私钥阅后即焚。 |
| 交互完成控制 | 设备 0x04 成功后，在 Redis gl:cert:interaction:{deviceSn} 中写入 completed，后续重复 CERT 请求返回系统错误，避免重复获取私钥。 |
| 吊销处理 | 管理端吊销证书时，同步更新 MySQL 证书状态，并清理 Redis Token，将 Redis 证书状态置为吊销，避免 DB 已吊销但设备仍可使用旧凭据。 |
| 下发记录展示 | 下发记录根据 device_cert_deploy 和 device_cert_deploy_item 聚合展示 Root CA、设备证书、私钥、Token 的写入状态及部署状态。 |
