#### 核心逻辑

<!-- TBL:style=44 type=auto tw=0 cols=1142,8886 cm=0,0,0,0 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 tcm=90,195,90,195 va=center -->
| 功能 | 功能描述 |
| --- | --- |
| 门诊类型更新 | 1. 接收并解析前端发送的更新请求数据。 2. 根据提供的部门ID更新门诊相关的缓存数据。 3. 发送消息到客户端通知门诊视图数据更新。 4. 检查是否有慢病数据的变化（慢病患者数量或慢病管理数）。 5. 如果有慢病数据更新，进一步更新慢病监测缓存，并通知客户端更新慢病视图层。 |
| 居民类型分布信息 | 1. 从前端接收居民分布信息更新请求，并解析请求数据。 2. 更新居民年龄分布缓存： - 根据部门ID获取年龄分布缓存键。 - 遍历缓存中的数据，根据前端传来的年龄段数据更新缓存中相应年龄段的居民数量。 - 更新完后，删除原缓存并重新插入更新后的数据。 3. 更新居民性别分布缓存： - 根据部门ID获取性别分布缓存键。 - 遍历缓存中的数据，根据前端传来的性别数据更新缓存中相应性别的居民数量。 - 更新完后，删除原缓存并重新插入更新后的数据。 4. 发送消息到客户端通知居民分布信息已更新。 |
| 监测人员地理位置分布图 | 1. 接收前端传来的监测数据更新请求，包括地理位置信息和监测结果。 2. 根据部门ID构建缓存键，用于访问或更新地理位置数据。 3. 从缓存中检索当前部门的地理位置分布信息。 4. 更新操作包括： - 如果找到当前机构的地理位置记录，则根据提交的数据更新正常或异常数值，并更新地理位置、监测批次号和患者ID。 - 如果未找到具体机构的记录，尝试更新父级机构的数据，并添加或更新地理位置信息。 5. 如果是新监测数据，将详细记录添加到子数据集缓存中，用于具体事件的点击响应。 6. 更新完毕后，删除原有的缓存数据，并重新插入更新后的列表，确保数据的准确性和最新状态。 7. 完成更新后，确保客户端收到通知，以便刷新显示最新的地理位置分布图。 |
| 实时检测数据列表 | 1. 接收前端传来的实时检测数据更新请求。 2. 根据部门ID构建缓存键，用于访问或更新实时检测数据。 3. 从缓存中检索当前部门的实时检测数据列表。 4. 检查实时数据列表的大小，如果超过10条记录，从列表左侧删除最旧的记录以保持列表长度为10。 5. 更新操作中，将新的实时检测数据插入到列表的右侧，确保最新的数据总是可见。 6. 完成更新后，确保客户端可以接收到最新的实时检测数据，以便及时反映在监控界面上。 |
| 慢病人数统计 | 1. 根据传入的部门ID构建两个不同的缓存键，一个用于慢病数据统计，另一个用于门诊数据统计。 2. 从慢病数据统计缓存中检索当前存储的统计信息。 3. 从门诊数据统计缓存中获取辖区人口总数，这是计算慢病管理率的基础数据。 4. 根据传入的更新信息修改慢病统计数据： - 如果提供了建档人数，更新建档人数统计。 - 如果提供了慢病人数，更新慢病人数统计，并根据辖区人口重新计算慢病管理率。 - 如果提供了糖尿病和高血压患者数量，分别更新这些统计数据。 5. 将更新后的数据重新存储回慢病数据统计缓存。 6. 通过此更新操作，确保慢病管理数据始终保持最新，便于实时监控慢病患者管理效果。 |
| 高血压随访统计 | 1. 使用部门ID构建业务缓存键，用于存储高血压随访的实时数据。 2. 从缓存中检索当前存储的随访数据列表。 3. 检查列表的长度，如果超过9条记录，则从列表左侧移除最旧的记录，保持列表长度为最新的10条数据。 4. 将新的随访数据推送到列表的右侧，确保最新数据始终被保存。 5. 通过这种方式，保证高血压随访数据的实时性和可追溯性，便于迅速获取最近的随访信息。 |
| 糖尿病随访统计 | 1. 使用部门ID构建业务缓存键，用于存储糖尿病随访的实时数据。 2. 从缓存中检索当前存储的随访数据列表。 3. 检查列表的长度，如果超过9条记录，则从列表左侧移除最旧的记录，以保持列表长度为最新的10条数据。 4. 将新的随访数据添加到列表的右侧，确保最新数据始终被保存。 5. 通过这种方式，保证糖尿病随访数据的实时性和可追溯性，便于迅速获取最近的随访信息。 |
| 基础数据修改 | 1. 使用部门ID构建业务缓存键，用于存储门诊相关的基础数据。 2. 从缓存中检索当前存储的基础数据。 3. 如果存在团队数量、医生数量或辖区人口的修改请求，更新对应的缓存值。 4. 对于辖区人口的修改，若发生变动，重新计算慢病管理率。这需要从另一个缓存键中获取慢病人数，然后计算管理率，并更新。 5. 更新团队数量和医生数量，并计算新的总和存入缓存。 6. 最后，删除原有的缓存键，并用更新后的数据重新创建缓存，确保数据的准确性。 |
