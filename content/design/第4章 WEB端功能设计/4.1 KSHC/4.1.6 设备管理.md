#### 核心逻辑

<!-- TBL:style=44 type=auto tw=0 cols=1408,8620 cm=0,0,0,0 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 tcm=90,195,90,195 va=center -->
| 功能 | 核心逻辑描述 |
| --- | --- |
| 创建设备 | 1. 接收来自前端的JSON数据负载。 2. 对输入数据进行验证，确保所有必填字段完整且有效。 3. 将数据存储到相应的数据库表中。 4. 返回成功消息和新创建设备的ID（或其他标识）。 |
| 读取设备 | 1. 接收请求中的设备ID。 2. 在数据库中执行查找操作，检索匹配的设备记录。 3. 如果找到设备记录，返回设备数据；如果未找到，返回404错误。 |
| 更新设备 | 1. 接收更新请求和JSON数据负载，其中包含要更新的设备信息。 2. 在数据库中查找对应ID的设备记录。 3. 验证输入数据的有效性。 4. 更新数据库中的设备记录。 5. 返回更新成功的消息。 |
| 分配 | 1. 接收设备ID列表和机构ID。 2. 验证设备和机构的有效性。 3. 更新数据库中设备的机构分配信息。 4. 返回分配成功的消息。5.优化分配穿梭框，使得穿梭框支持大数据量，以及分页属性。6.优化用户交互逻辑，当点击向右的时候即为把设备分配到不同的组织下。 |
| 批量分配 | 1. 接收设备ID列表和机构ID。 2. 验证设备和机构的有效性。 3. 更新数据库中设备的机构分配信息。 4. 返回批量分配成功的消息。5.设备信息中的批量分配允许多次分配。6.设备信息中的批量分配，分配之后状态不变。7.只允许非 已绑定状态才能进行批量分配 |
| 批量修改组织 | 1.校验并批量变更设备归属组织，仅操作已存在设备2.批量修改机构会重置数据。3.出厂管理中的批量分配只允许分配一次。4.并且分配后的状态要改成未绑定。5.只允许非 已绑定的状态进行分配 |
| 设备详情 | 1. 接收设备编码，查询设备基本信息。 2. 验证设备信息和关联的用户ID是否存在，如果不存在，则返回空的分页结果。 3. 获取居民信息，如果居民信息不存在，同样返回空的分页结果。 4. 分页查询设备的SD卡数据记录。 5. 转换每条记录，添加居民姓名，设备编码，并将总时间从秒转换为时分秒格式。 6. 返回转换后的分页结果。 |
| 使用记录 | 1. 根据设备编码查询设备信息，验证设备是否存在。 2. 如果设备存在，验证是否有关联的用户ID；如果没有用户ID，查询设备绑定记录。 3. 分页查询设备使用记录，确保结束时间不为空。 4. 转换每条记录，添加设备编码，并将总时间从秒转换为时分秒格式。 5. 返回转换后的分页结果。 |
| 数据重置 | 1. 保存数据重置审批记录，包括期望时间、申请原因、审批类型、审批状态、和操作者信息。 2. 根据设备ID查询设备信息。 3. 保存数据重置详细记录，包括设备信息、审批记录ID、设备编码、设备名称、软件版本、部门ID。 4. 查询设备类型信息并保存。 5. 查询并保存机构信息。 6. 返回操作成功信息。 |
