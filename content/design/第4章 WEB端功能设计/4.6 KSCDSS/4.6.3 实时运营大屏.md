#### 核心逻辑

<!-- TBL:style=45 type=pct tw=5175 trh=2248 cols=2415,7784 cm=0,108,0,108 ind=0:dxa lay=fixed bd=single:auto:4:0 va=center -->
| 功能 | 描述 |
| --- | --- |
| 统一数据推送入口 | 1. 获取上级机构列表: - 获取当前推送机构的上级机构列表，通过调用`remoteDataScopeService.getSuperiorDeptList`方法实现。 2. 构建顶级部门列表: - 将获取到的上级机构ID存储在`topDeptList`中。 - 如果上级机构列表不为空，将这些机构ID收集到`topDeptList`。 - 然后将当前推送机构的ID添加到`topDeptList`中。 3. 检查推送机构列表: - 如果`topDeptList`为空，函数返回失败信息“当前可推送的机构为空”。 4. 记录在线用户数: - 记录当前在线的用户数及其会话ID列表，用于后续可能的推送操作。 5. 根据消息类型推送数据: - 遍历`cdsDataPush.getMsgType()`得到的消息类型列表。 - 根据不同的消息类型调用相应的数据推送服务，如`cdsLeftDataService`, `cdsCentreDataService`, `cdsRightDataService`等。 - 每个服务根据消息类型和参数对象执行特定的数据处理和推送逻辑。 6. 缓存重置逻辑: - 对于某些消息类型，如`VIEW_RESET_ALL`, `VIEW_RESET_L2`, `VIEW_RESET_C1`, `RESET_R1_DEVICE_INFO`，调用`institutionCacheService.clearDeptCache`来清除相关机构的缓存。 7. 异常处理: - 在数据推送或缓存重置过程中捕获异常，记录错误日志。 8. 返回结果: - 完成所有数据推送和缓存重置后，返回成功响应。 |
| 测量次数统计初始化接口 - L1 | 1. 获取缓存中的测量频率数据: - 首先，构建一个Redis的键名，该键名由租户ID、常量`CdsScreenCacheConstants.CHRONIC_DISEASE_STEWARD_L1_TYPE_KEY`和部门ID(`deptId`)组成。 - 使用`redisTemplate`从Redis中读取与该键名对应的数据，数据类型为`List<CdsMeasurementVo>`。 2. 判断并处理缓存数据: - 如果从Redis中获取的数据为空（即`CollectionUtils.isEmpty(measurementList)`为真），则进行以下操作： - 创建`StatisticsCommonIn`对象`commonIn`用于统计输入参数。 - 初始化一个`deptIdList`用于存储部门ID及其子部门ID。 - 调用`institutionCacheService.getDataOfSubOrganization`方法，传入`deptIdList`和`deptId`，获取所有子部门的ID。 - 设置`commonIn`的`deptIds`属性为`deptIdList`，表示需要统计的部门范围。 - 设置`commonIn`的`isAll`属性为`true`，可能表示是否需要统计所有相关数据。 - 调用远程服务`remoteStatisticsService.getCdsMeasurementStat`，传入`commonIn`和`SecurityConstants.FROM_IN`，以获取测量统计数据。 - 从远程服务响应中提取`CdsMeasurementVo`对象列表，使用`RetOps.getRemoteObj`方法。 - 如果获取的`CdsMeasurementVo`列表不为空，将其存入Redis中，键名为之前构造的`redisKey`，并设置过期时间。 |
| 测量次数统计初始化接口 - L2 | 1. 构建Redis键名: - 构建两个Redis键名，分别用于存储当天和近30天的慢性疾病管理二级（L2）类型数据，键名结构为：`<tenantId>:<constantKey>:<deptId>`。 2. 从Redis读取数据: - 尝试从Redis中读取当天和近30天的数据，使用`redisTemplate.opsForValue().get()`方法。 - 如果数据为空或不存在，进入下一步计算。 3. 数据权限与计算: - 在查询数据前，计算用户的数据权限，确保只查询用户本级和子集机构的数据。 - 当天数据缺失时，调用`regionalRankingCalculateBranch`方法计算当天数据并存入Redis。 - 近30天数据缺失时，同样调用`regionalRankingCalculateBranch`方法计算近30天数据并存入Redis。 4. 数据处理与封装: - 使用`regionalRankingCalculate`方法处理从Redis获取或计算得到的数据。 - 创建`CdsOneAndThirtyDayPCVo`对象，其中包含`oneDay`和`thirtyDay`两个属性，分别存储处理后的当天和近30天的排名信息。 |
| 测量次数统计初始化接口 - L3 | 1. 生成Redis键名: - 根据当前租户ID、部门ID以及预定义的常量生成两个用于访问Redis的键名：`redisOneKey`和`redisThirtyKey`。 2. 从Redis获取数据: - 尝试从Redis中获取当天(`measurementListOne`)和近30天(`measurementListThirty`)的慢性疾病管理指标数据。 3. 数据权限与缓存检查: - 如果从Redis获取的数据为空（`CollectionUtils.isEmpty()`），则执行以下操作： - 调用`indexDetectionCalculateBranch`方法来计算并获取对应时间范围内的数据。 - 对于当天数据，传入参数为`0L`。 - 对于近30天数据，传入参数为`29L`。 - 计算结果将被存储回Redis中，以便后续请求直接读取。 4. 数据处理与封装: - 使用`indexDetectionCalculate`方法对获取到的原始数据进行处理，转换成更易于使用的格式。 - 创建`CdsOneAndThirtyDayPCVo`对象，其中封装了当天和近30天的处理后数据。 - 设置`oneDay`属性为当天处理后的数据。 - 设置`thirtyDay`属性为近30天处理后的数据。 |
| 监测人员地理位置分布图 - C1 | 1. Redis数据获取 - 步骤1: 根据`TenantContextHolder.getTenantId()`、`CdsScreenCacheConstants.CHRONIC_DISEASE_STEWARD_C1_TYPE_KEY`和`deptId`生成一个Redis键。 - 步骤2: 使用`redisTemplate.opsForValue().get(redisKey)`尝试从Redis中获取与该键关联的`List<CdsMapDistributionPCVo>`对象。 2. 缓存缺失时的数据处理 - 步骤3: 如果Redis中没有找到数据，初始化一个空的`List<CdsMapDistributionPCVo>`。 - 步骤4: 调用`institutionCacheService.getDataOfSubOrganization(deptIdList, deptId)`来收集当前部门及其子部门的ID列表。 - 步骤5: 使用远程服务`remoteDeptService.getListByDeptIds(deptIdList)`获取这些部门的详细信息，然后过滤出有`addressCode`的部门。 - 步骤6: 将过滤后的部门`addressCode`转换为`Long`类型，再使用远程服务`remoteAddrService.getListByIds(areaDeptIds)`获取这些地址码对应的地区信息。 - 步骤7: 将地区信息映射成`Map<Long, SysArea>`以提高查找效率。 - 步骤8: 遍历过滤后的部门列表，使用地区信息创建`CdsMapDistributionPCVo`对象，并添加到`mapDistributions`列表中。 3. 数据缓存 - 步骤9: 调用`institutionCacheService.setCacheKeyExpiration(redisKey,mapDistributions)`将处理后的数据存储回Redis，并设置过期时间。 |
| 实时监测数据 - C2 | 获取实时检测数据的初始化信息。首先，根据当前租户ID、类型键和用户部门ID生成Redis的键值。然后，从Redis中获取该键值对应的实时检测数据列表。如果列表为空，则通过远程调用查询实时检测数据，并将查询结果转换为指定的对象列表。如果远程查询结果为空，则返回空列表。最后，将获取到的列表封装成响应对象并返回。 |
| 设备耗材统计初始化 - R1 | 1. 参数解析与缓存键构建: - 接收一个`Long deptId`作为参数。 - 如果`deptId`为null，使用当前登录用户所属的部门ID。 - 构建Redis缓存键，键值包含租户ID、常量`CHRONIC_DISEASE_STEWARD_R1_DEVICE_CONSUMABLE_DATA_KEY`以及部门ID。 2. 缓存数据读取: - 使用构建的Redis键从缓存中读取`CdsDeviceConsumableVo`对象。 3. 缓存缺失时的处理: - 如果缓存中没有找到数据： - 创建一个新的`CdsDeviceConsumableVo`对象。 - 获取当前部门及其所有子部门的ID列表。 - 创建`ConsumableCommonIn`对象并设置部门ID列表。 - 调用远程服务`remoteConsumableService`获取设备耗材统计数据，存储在`CdsDeviceConsumableVo`的`deviceConsumable`属性中。 - 设置设备类型列表，再次调用远程服务获取设备统计数据，存储在`CdsDeviceConsumableVo`的`device`属性中。 - 如果统计数据非空，将`CdsDeviceConsumableVo`对象存入缓存，并设置过期时间。 |
| 异常指标数 - R2 | 复用L1的逻辑，进行重组 |
| 干预人员初始化 - R3 | 获取测量频率初始化数据： - 调用`cdsLeftDataService.measurementFrequencyInit`方法，传入当前用户部门ID（通过`SecurityUtils.getUser().getDeptId()`获取），以获取与该部门相关的测量频率初始化数据。 - 返回的数据类型为`List<CdsMeasurementVo>`，其中包含了多个`CdsMeasurementVo`对象，每个对象代表一条测量频率记录。 填充统计数据： - 遍历上述获取的测量频率数据列表。 - 对于列表中的每一个`CdsMeasurementVo`对象，调用`fillStatisticsR3Data`方法，将统计信息填充到`interventionPersonVo`对象中。 获取实际检查数据： - 调用`getRealCheckData`方法，同样传入当前用户部门ID，以获取与该部门相关的实际检查数据。 - 获取的实际检查数据被设置到`interventionPersonVo`对象的`checkDetails`属性中。 |
