#### 功能描述

<!-- TBL:style=142 type=auto tw=0 cols=1384,8470 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 va=bottom -->
| 设计编号 | Design-BREATHE-DATA-VERIFY-001 |
| --- | --- |
| 功能描述 | 新增 WiFi 历史数据补偿触发、重算 MQ 链路、归档数据透明恢复、以及同步侧按天/按区间导出校验能力，确保历史上传、补传、跨天数据和归档后的查询导出仍然可用。 |
| 设计定位 | 将“数据归档”与“数据可用性”闭环打通。归档后并非只解决存储问题，还必须支撑后续查询、重算、分钟级补齐和线下校验导出。 |
| 核心机制 | 1. 历史上传阈值识别：单设备一批消息达到阈值后，写入 Redis 触发 Key。 2. Redis 过期监听：监听补偿触发 Key，到期后扫描该设备当日在线日期集合。 3. MQ 重算：向 BREATHE_DATA_RECOUNT_BY_SMG_OUTPUT 投递统计指令，消费端执行 statisticsBreatheDataResult。 4. 透明恢复：重算前先执行 handleArchivedDataAndRestore，若目标日已归档则先从 OSS 恢复。 5. 校验导出：同步侧提供 /exportDataDay 与 /exportDataRange，若热库无数据则从归档文件读取后导出 Excel。 |

#### 接口设计

<!-- TBL:style=142 type=auto tw=0 cols=4329,3368,2157 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 va=bottom -->
| 接口/方法 | 入参设计 | 职责与设计意图 |
| --- | --- | --- |
| processHistoryDataCompensation | String expiredKey | Redis 过期监听回调。将设备历史补偿触发转化为具体日期重算任务。 |
| mqBreatheDataRecountByDay | StatisticsResultDataIn payload | MQ 消费端。消费重算指令并执行结果集统计、分钟级保存与 ACK/NACK。 |
| statisticsBreatheDataResult | String deviceNo, Long patientId, LocalDateTime endTimePoint | 单日统计主入口。重算前校验归档状态，必要时先恢复冷数据。 |
| /breatheCureVerify/exportDataDay | deviceCode, pId, date | 导出单天秒级数据校验文件；若热库无数据则从归档文件读取。 |
| /breatheCureVerify/exportDataRange | deviceCode, pId, startDate, endDate | 按日期范围循环导出多天校验文件，用于历史问题排查与人工比对。 |

#### 核心逻辑

<!-- TBL:style=142 type=auto tw=0 cols=997,6190,2667 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 va=bottom -->
| 执行步骤 | 详细逻辑说明 (Step-by-Step) | 业务约束与红线 |
| --- | --- | --- |
| 第一步：历史上传识别 | WiFi 上传消费时统计同批次内同一设备的消息数量，超过阈值后写入历史补偿触发 Key。 | 约束：触发 Key 仅用于延迟聚合与削峰，不能直接在上传线程中同步重算。 |
| 第二步：延迟触发重算 | Redis 监听器在 Key 过期后扫描当日在线日期集合，组装 {deviceNo, patientId, endTimePoint} 并投递重算 MQ。 | 红线：必须通过 MQ 异步执行，避免 Redis 监听线程承担重计算。 |
| 第三步：归档前置恢复 | 统计服务在查询秒级数据前，先调用 handleArchivedDataAndRestore 判断目标日是否已归档；若已归档则先从 OSS 拉回热库。 | 红线：禁止在已归档但未恢复的状态下直接统计，否则结果集与分钟级数据会缺失。 |
| 第四步：日界点重算修正 | 当 cureEndTime 恰好命中呼吸机自然日边界（如 BREATHE_DAY_START_TIME / BREATHE_DAY_END_TIME）时，重算前需反查秒级表最后一条有效数据时间，并以真实末点覆盖本次统计结束时间。 | 红线：禁止直接使用边界时间作为最终统计结束点，否则会出现“定时统计已生成结果集，后续追加数据无法覆盖旧结果”的问题。 |
| 第五步：重建结果与分钟级 | statisticsBreatheDataResult 在结果集保存成功后，继续执行 saveMinutesData，同步补齐分钟级聚合。 | 约束：结果集与分钟级数据视为一个统计闭环，两者必须同批次完成。 |
| 第六步：校验导出兜底 | 导出接口优先读热库；若目标日热库为空，则查询 ArchivedMetadata 中的文件路径，从 OSS 流式解压并导出 Excel。 | 红线：导出仅用于核验和问题定位，不得反向修改生产数据。 |
| 第七步：消息签收闭环 | MQ 消费端和 SD 卡导入消费者均改为显式 Ack/Nack，解析失败时写失败状态并拒绝重入队。 | 设计意图：避免重复消费、消息丢失或异常消息无限重试。 |
