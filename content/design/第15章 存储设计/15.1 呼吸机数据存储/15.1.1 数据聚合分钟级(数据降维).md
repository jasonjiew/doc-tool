#### 功能描述

<!-- TBL:style=142 type=auto tw=0 cols=1668,8186 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 va=bottom -->

| --- | --- |
| 功能编号 | REQ-DATA-STORE-001/002/003/004 |
| 用户需求编号 | / |
| 功能描述 | 目标是存储优化与数据降维。通过将设备产生的高频/秒级原始治疗数据，经过特定算法转换为粒度更大的分钟级数据进行持久化，从而在保留核心临床指标（压力、漏气、潮气量等）与呼吸事件的前提下，大幅降低数据库的存储压力。 |
| 核心机制 | 1. 滑动窗口聚合：以 60 秒为逻辑步长，对窗口内的压力、流速等连续物理量进行均值、极值提取。 2. 业务特征保留：针对血氧等关键体征，采用“关键值提取算法”，确保分钟级数据仍能准确反映血氧掉落等医学异常事件。 3. 异步触发机制：与归档模块类似，采用结果集触发模式，在数据上报完整后启动降维任务，确保数据的最终一致性。 |
| 触发条件 | 1. SD**卡离线数据导入** 2. WIFI**结束治疗统计/定时任务统计** |

#### 核心逻辑

<!-- TBL:style=142 type=auto tw=0 cols=1242,5701,2911 cm=0,108,0,108 ind=0:dxa lay=autofit bd=single:auto:4:0 hdr=0 va=bottom -->
| 执行步骤 | 详细逻辑操作说明 (Step-by-Step) | 业务约束与红线 |
| --- | --- | --- |
| 第一步：聚合任务登记 | 在秒级数据解析入库或每日统计任务触发时，同步将待处理的坐标 {deviceNo, pId, cureDate} 写入 Redis 的 SET 待办集合。 | 约束：此动作为旁路触发，必须包裹 try-catch，严禁因登记失败导致主业务入库流程回滚。 |
| 第二步：原始数据提取 | 调度器从 Redis 获取坐标，从 MongoDB 秒级明细表（sys_breathe_data_sec）中，按 deviceNo + pId + cureDate 一次性拉取该全天的原始点位。 | 红线：严禁在循环中按分钟去 Count 数据库。必须全量或分小时段拉入内存处理，以减少数据库 IO 会话开销。 |
| 第三步：逻辑窗口分桶 | 在内存中构建时间桶模型（Time Bucketing）。将秒级数据按照时间戳对齐，每 60 秒（如 08:00:00 - 08:00:59）划分为一个聚合单元。 | 设计意图：确保分钟数据点与自然时间对齐，方便前端以分钟为最小单位进行横轴对齐渲染。 |
| 第四步：特征算子计算 | 针对每一个 60 秒的数据桶，遍历其内部点位执行以下算子： 1. 均值计算：压力、流速、呼吸频率等连续物理量求平均值。 2. 极值捕捉：捕捉该分钟内的最低血氧 (Min SpO2) 和 最高压力 (Max Pressure)。 3. 状态压缩：若窗口内任意一秒出现“漏气”标记，该分钟记录设为“异常”状态。 |  |
| 第五步：批量幂等落库 | 将计算产出的分钟列表调用 MongoDB 的 bulkWrite。以 {deviceNo, pId,  minuteTimestamp} 为复合唯一索引执行 Upsert。 | 幂等红线：必须使用更新或插入（Upsert）语义。当历史数据补传触发二次聚合时，新结果必须物理覆盖旧结果，严禁产生重复数据。 |
| 第六步：清理任务标记 | 确认 MongoDB 返回 Acknowledged 成功信号后，从 Redis Set 中移除对应坐标，完成该批次降维闭环。 | 约束：若写入失败，保留 Redis 标记。后续通过补偿机制重试，重试上限 3 次，超过则推送到告警平台。 |
