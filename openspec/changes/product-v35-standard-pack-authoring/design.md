## Context

参见 [proposal](proposal.md)。现有规范包 schema 1 声明 packId/version/documentKind、文件及 hash，资源含模板、骨架、规则、术语、变量。包消费和项目固定版本快照已实现；本版新增制作端，复用现有安装模型，避免发行第二种包格式。

## Goals / Non-Goals

**Goals:** 文档负责人无需写 Python 即可制作包，保存草稿、样例试用、导出给同事；普通开发者无需配置全部规范即可继续文档工作。

**Non-Goals:** 云商城、组织权限、远程自动升级、脚本插件、在线 Word 模板设计器、任意封面/页眉占位自动绑定、强制 Word 正式样例才能分享。

## Decisions

### 1. 本地草稿及来源复制

草稿置于明确选择的制作目录，通过本地状态保存未完成元数据；正式冻结产物仍是现有 schema 1 包。来源可以是已有包的副本或当前项目选定的模板、章节骨架与支持的规范资源。源文件复制到草稿，不引用用户源文件路径，不编辑正在使用的固定安装包。

草稿状态与可安装包分离，允许缺少 version 时先保存。用户点击“导出规范包”才验证包身份、文件路径及声明摘要。变更已冻结内容需给新版本/新输出目录；同版本同摘要导出可复用结果，同版本不同摘要显示“另存新版本”，不覆盖既有产物或现用项目。

### 2. 支持字段的结构化编辑

界面包含基本信息、Word 模板、章节骨架、变量、术语和支持的规则。实现前读取 pack_resources 和 SettingsModel 的真实模型，建立包 YAML 与项目 quality JSON 的显式转换，不能直接复制文件后假定两者格式相同。每个字段显示实际用途与默认值；未知声明式字段保留原文，不执行脚本。

模板由用户选择已有 DOCX，可用系统 Word 打开编辑；封面和页眉仍属于底模。正文变量只承诺既有解析器实际支持的替换范围；模板其他位置没验证则显示“未绑定”，不自动宣称变量应用成功。复杂规则提供可保留原文的高级编辑，基础表单只编辑已实现类型。

### 3. 冻结、校验与分享

只打包规范资源及骨架所引用的包内图片，调用现有包校验/安装路径；排除 project `.git`、缓存、用户凭证、历史和输出文件。冻结清单由内容实际摘要生成，ZIP 经现有加载器可消费。名称冲突用新目录/新文件名，文件摘要不匹配按现有默认/严格政策处理。

分享是本地导出 ZIP 和打开所在目录；不发送给他人或上传平台。现用项目固定的 packId/version/hash 保持原值，是否采用新包是独立已有安装/创建动作。

### 4. 样例验证独立且可重试

选择少量现有样例或当前内容捕获，在草稿指定的样例子目录生成隔离项目，使用实际创建、check 与 CORE 出稿路径。样例输入与源项目不得改写。每轮结果绑定草稿摘要和内容 captureId，改包后旧结果标明过期而仍可打开。

结果区区分结构合法、规则问题、可读 Word、待 Word 刷新、正式成功及未验证。无 Word 可以生成可读样例/HTML，保存包并导出，余项可同源重试；只有包结构本身无法消费等真实错误阻止“可安装”产物，仍允许保存草稿和定位错误。

## Risks / Trade-offs

- [包 YAML 与项目 JSON 的转换遗漏] → 用现有消费者做 round-trip 测试，记录字段对应、未知字段和默认值。
- [来源项目包含业务正文或隐私] → 导出前显示文件清单；骨架由用户选定，不默认复制整份正文和历史。
- [模板正文变量与封面变量含义不同] → 显示支持范围和样例证据；未支持不算替换成功。
- [缺 Word 形成不完整视觉验证] → 保留合法包分享和待验证状态，正式视觉验收单列。

## Migration Plan

新增制作入口及草稿存储，不升级包格式或重置已有安装目录。使用原加载器验证每个导出包，已有项目无需迁移。退出制作流程只留下用户选择的本地草稿及产物。

## Open Questions

企业真实模板试用需由当前环境给出证据；不作通用底模以外的视觉保证。未知规则类型先保留原文，其结构化编辑属于后续小批迭代。
