## Why

当前产品的核心价值已经是“将大型 Word 文档转换为可维护的 Markdown 章节项目，并可靠重建为 Word”，但应用品牌、内建文档类型、模板、示例内容、安装包和测试仍与康尚需求/详细设计场景耦合，阻碍项目以通用工具定位安全开源。现在需要建立清晰的公共发行边界，在保留成熟编辑与构建能力的同时移除公司专用内容，并确保已有内部项目不会因公共版通用化而突然不可读。

## What Changes

- 将面向用户的产品名称、组织名、可执行文件、安装目录、安装器、CI、SBOM、日志和启动入口统一改为中性公共品牌；公共品牌的最终名称通过一个集中定义维护，首版使用 `Doc Tool` / `DocTool`。
- 新建项目只提供一种“通用大型文档”工作流；导入向导不再展示需求文档和详细设计预设，文档编号与版本均为可选元数据。
- 公共 CLI 的导入入口只创建 `general` 项目，不再公开 `requirement` / `design` 选项；面向仓库内置双文档的旧构建命令和 `.cmd` 入口退出公共产品面。
- 保留对既有 `requirement` / `design` 项目清单和目录布局的兼容读取与构建能力；旧项目在打开时显示为“旧版专用项目”，并提供迁移到通用项目的可逆流程或明确指导。
- 将文档类型从用户可选的业务分类降级为兼容层内部信息；搜索、章节树、问题中心和资源管理默认以当前单项目为范围，不再突出需求/设计分类。
- 从公共源码和安装包剥离公司 Word 模板、真实需求/设计 Markdown、业务图片、复杂表格、配置、分析记录及历史迁移证据；使用全新虚构的大文档示例和脱敏测试夹具替代。
- 禁止公共构建隐式打包仓库根 `templates/`、`config/`、`content/` 或 `assets/` 中的公司材料；新增公共发行允许清单和敏感标识/内网地址扫描。
- 增加开源项目治理文件和发布门禁，包括许可证、贡献指南、行为准则、安全策略、Issue/PR 模板及第三方许可证说明。
- 更新 README、帮助文本、关于页、错误消息、测试和发布说明，使定位统一为通用大型 Word 文档工作台。
- **BREAKING**：公共安装包名称、可执行文件名、安装目录、应用设置组织键和开发启动脚本名称发生变化；升级时必须迁移或兼容读取旧应用设置，不能静默丢失用户偏好。
- **BREAKING**：公共 UI 和新项目 CLI 不再允许创建 `requirement` / `design` 项目；旧自动化若依赖这些新建参数，需要改用通用项目或留在私有扩展中。

## Capabilities

### New Capabilities

- `generic-document-project`: 定义公共版唯一的新建项目模型、通用元数据、导入行为，以及旧版专用项目的兼容读取和迁移边界。
- `public-distribution-boundary`: 定义公共源码、安装包和 Release 可包含的内容，品牌集中化、专用资产剥离、敏感内容扫描与可复现发布门禁。
- `open-source-project-governance`: 定义许可证、贡献、安全、行为准则和社区模板等公开项目治理要求。

### Modified Capabilities

- `pyside6-app-shell`: 应用外壳改用中性公共品牌，并在品牌迁移后兼容读取旧的界面偏好和窗口状态。
- `dev-launcher-bootstrap`: 开发启动脚本改为中性名称和提示，不再包含公司品牌，同时保留现有 PySide6 探测和引导安装行为。
- `content-tree-nav`: 通用项目的章节树不再以需求/详细设计类型作为产品级分组，旧版项目仍能按兼容布局显示。
- `content-search`: 搜索范围以当前通用项目为默认，不再向新项目用户暴露需求/详细设计类型筛选；旧版多类型内容仍可兼容过滤。

## Impact

- **应用与领域层**：`doc_tool/app.py`、版本/品牌常量、项目清单、路径模型、导入服务、预检建议、内容索引、质量规则和旧项目迁移。
- **桌面 UI**：主窗口、空状态、导入向导、项目栏、章节树、搜索/替换/问题面板、关于页、设置持久化和用户提示。
- **CLI 与兼容入口**：`doc_tool/cli.py`、序列化输出、根目录启动脚本及仓库内置文档生成入口。
- **发布系统**：PyInstaller spec、Inno Setup、GitLab CI、安装路径、可执行文件、图标、SBOM、泄漏扫描、签名和发布说明。
- **仓库内容**：公司专用 `templates/`、`config/`、`content/`、`assets/`、`analysis/` 和 `migration/legacy/` 不得进入公共仓库；测试数据需要全量脱敏替换。
- **兼容性**：项目 schema v1 必须继续读取既有 `general`、`requirement`、`design` 项目；公共版只限制新建行为，不通过原地改写破坏旧项目。
- **法律与治理**：正式公开前仍需著作权人书面授权、许可证决策、商标/图标确认、依赖许可证复核和 Git 历史清理；本变更不能替代法律审批。
