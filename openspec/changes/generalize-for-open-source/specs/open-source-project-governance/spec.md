## ADDED Requirements

### Requirement: 公共仓库包含有效开源许可证
公共仓库在宣称开源或发布稳定公共版本前 MUST 在根目录包含由著作权人批准的、可机器识别的 OSI 批准许可证全文，并 SHALL 在 README 中准确说明许可证标识与第三方组件边界。系统和文档 MUST NOT 在许可证尚未决定时猜测著作权人或许可证。

#### Scenario: 许可证已获批准
- **WHEN** 著作权人书面批准许可证和版权信息
- **THEN** 仓库根 `LICENSE` 使用批准的标准文本，README 与包元数据使用一致 SPDX 标识

#### Scenario: 许可证尚未批准
- **WHEN** 许可证或权利人仍未确定
- **THEN** 仓库保持“开源准备中”状态，正式公共发布门禁失败且不宣称已开源

### Requirement: 公共贡献规则完整
公共仓库 SHALL 提供 `CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、Pull Request 模板和 Issue 模板，说明环境搭建、测试、提交范围、敏感数据禁令、版权贡献约定和社区行为标准。

#### Scenario: 新贡献者准备提交变更
- **WHEN** 新贡献者查阅仓库贡献入口
- **THEN** 可以找到可执行的开发、测试、分支、提交和 PR 指引，并明确不得提交真实业务文档或凭据

### Requirement: 安全报告渠道明确
公共仓库 SHALL 提供 `SECURITY.md`，说明支持版本、私密漏洞报告渠道、预期响应和禁止公开提交的敏感材料。公共 README SHALL 指向该策略。

#### Scenario: 发现恶意 DOCX 解析漏洞
- **WHEN** 研究者发现潜在安全漏洞
- **THEN** 可以通过非公开渠道报告，并获得受支持版本和所需最小复现材料指引

### Requirement: 第三方许可证与分发义务可审计
公共发布 SHALL 维护运行和构建依赖的许可证清单，并 MUST 在每次 Release 前验证主许可证与依赖分发义务。安装包 SHALL 携带适用的第三方许可证通知和 SBOM。

#### Scenario: 依赖版本发生变化
- **WHEN** 依赖清单或锁定版本被修改
- **THEN** CI 重新生成并验证许可证/SBOM 报告，未知或不允许的许可证阻断正式发布

### Requirement: 公开前人工批准有记录
正式公共发布 MUST 记录著作权授权、品牌/图标授权、Git 历史清理、敏感内容人工复核、依赖许可复核和干净环境验收的负责人及结果。

#### Scenario: 准备首个公开 Release
- **WHEN** 维护者请求创建首个公开版本
- **THEN** 发布检查单包含全部必需批准的可审计记录，任一缺失都会阻断发布
