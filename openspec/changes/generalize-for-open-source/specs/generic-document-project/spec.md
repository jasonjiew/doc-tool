## ADDED Requirements

### Requirement: 公共版新建通用大型文档项目
系统 SHALL 在桌面导入向导和公共 CLI 中只创建 `documentType: general` 的大型文档项目。系统 SHALL 要求文档名称，并 SHALL 将文档编号与文档版本作为可选元数据；系统 MUST NOT 要求用户选择需求文档或详细设计预设。

#### Scenario: 通过桌面向导导入普通 DOCX
- **WHEN** 用户选择结构化 DOCX、填写文档名称和目标目录并完成导入
- **THEN** 系统创建 `documentType: general` 的自包含项目，且向导未展示需求/详细设计类型选项

#### Scenario: 通用项目省略编号和版本
- **WHEN** 用户未填写文档编号与版本但其他必填信息有效
- **THEN** 系统允许导入，并生成安全且可预测的项目清单与输出文件名

#### Scenario: 公共 CLI 导入
- **WHEN** 用户通过公共 CLI 执行导入且未指定业务类型
- **THEN** 系统创建通用项目，并且 CLI 帮助不把 `requirement` 或 `design` 列为可创建类型

### Requirement: 导入能力与业务文档类型解耦
系统 SHALL 根据源 DOCX 的标题样式、正文和资源生成项目模板与 Markdown 章节树，而 MUST NOT 通过“需求”“详细设计”等业务关键词决定公共项目类型。标题样式映射、保真报告、往返差异和资源校验 SHALL 对通用项目继续生效。

#### Scenario: 导入标题含需求字样的普通文档
- **WHEN** 源 DOCX 标题或正文包含“需求”或“详细设计”字样
- **THEN** 系统仍创建通用项目，不自动切换到专用类型

#### Scenario: 导入非标准标题样式文档
- **WHEN** 用户在导入时提供有效的标题样式映射
- **THEN** 系统按映射拆分通用章节树并执行现有保真与往返检查

### Requirement: 旧版专用项目兼容读取
系统 MUST 继续读取 schema v1 中 `documentType` 为 `requirement` 或 `design` 的既有项目，并 SHALL 保留其原始内容、资源路径、质量规则和构建语义。打开旧项目 MUST NOT 静默修改清单或目录结构。

#### Scenario: 打开旧需求项目
- **WHEN** 用户打开有效的 schema v1 `requirement` 项目
- **THEN** 系统成功加载项目并标注为旧版专用项目，原始 `project.yml` 与目录保持不变

#### Scenario: 构建旧详细设计项目
- **WHEN** 用户对有效的 schema v1 `design` 项目执行兼容构建
- **THEN** 系统沿用该项目的模板、路径和专用校验完成构建，或给出明确的兼容性错误而非按通用项目误处理

#### Scenario: 公共版拒绝新建旧类型
- **WHEN** 用户尝试通过公共 CLI 新建 `requirement` 或 `design` 项目
- **THEN** 系统拒绝该参数并说明新项目统一使用通用模式，且不创建半成品目录

### Requirement: 旧项目迁移可恢复
系统 SHALL 为旧版专用项目提供迁移到通用项目的明确路径。自动迁移若实现，MUST 默认写入新目录或先创建完整备份，并 MUST 在结构、资源和试构建验证通过后才提交迁移结果；失败时旧项目 SHALL 保持可用。

#### Scenario: 迁移旧项目成功
- **WHEN** 用户确认将旧版专用项目迁移为通用项目且所有验证通过
- **THEN** 系统产生可打开的通用项目，保留内容与资源，并记录来源和迁移报告

#### Scenario: 迁移验证失败
- **WHEN** 迁移后的结构、资源或试构建验证失败
- **THEN** 系统中止提交、保留旧项目不变，并提供失败阶段和恢复指引

### Requirement: 通用项目的业务中性体验
系统 SHALL 在通用项目的项目栏、设置、问题中心和质量默认值中使用业务中性语言。通用项目 MUST NOT 因未包含需求章节、设计章节、公司文档编号或专用封面字段而产生默认错误。

#### Scenario: 打开通用技术手册
- **WHEN** 用户打开不含需求或设计章节的通用技术手册项目
- **THEN** 系统显示通用文档元数据并仅执行适用于大型文档的默认质量规则
