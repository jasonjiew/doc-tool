## Why

文档团队已经能够评审和处理 Git 冲突，但定位章节的修改来源、分配后续工作和离线交接仍需切换多个工具。V3.1 把章节历史、责任提示和交接应用连成日常协作流程。

## What Changes

- 增加章节 Git 历史与来源定位，支持重命名后的历史和历史版本只读比较；无 Git 时使用 V2.6 本地历史，历史恢复为当前内容的新保存。
- 给现有评审/影响待办增加可选负责人、处理说明和“我的待办”，名字为协作提示，不构成身份认证或编辑权限。
- 导出选择章节及所需资源的离线交接包，接收方查看前后差异后应用；冲突项保留本地，其他已选项继续，重复导入幂等。
- 渐进建立命令注册入口，让菜单与命令面板共享稳定命令 ID/可用状态/最近使用，只迁移本版涉及动作。
- 继续复用 V2.8 意见生命周期/HTML 包和 V2.9 影响数据，不另建审批系统或全套任务管理平台。

## Capabilities

### New Capabilities

- `chapter-change-history`: 章节 Git/本地历史、比较与来源定位。
- `team-handoff-workflow`: 负责人提示、现有待办聚合与离线内容交接。
- `context-command-registry`: 渐进共享菜单/面板动作及命令上下文。

### Modified Capabilities

无。评审是否通过仍由已有复核动作决定，新增协作字段可选并兼容旧记录。

## Impact

- 涉及 `content/{vcs_changes,local_history,reimport_plan}.py`、`review/versioned_review.py`、`export/review_package.py`、工作区概览、命令面板及菜单绑定。
- 新增项目内交接元数据/可选团队配置与用户级最近命令；包为显式文件导出，不自动发送或推送。
- 直接前置为 V2.6 历史和 V2.8 评审/差异应用；复用模块来源展示依赖 V3.0，其他协作能力可独立开发。
- 遵循默认继续、部分应用与集中提示；严格策略不作为日常协作前置。
