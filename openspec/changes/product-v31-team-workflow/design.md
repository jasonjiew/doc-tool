## Context

V2.6 有本地多版本历史；V2.8 已在工作树加入版本化评审和意见包；V2.9 正在实施影响/集合。`vcs_changes.py` 已提供状态、提交、分支、拉取和推送，`PaletteItem` 有标题/回调，不能将这些基础动作重写成新产品成果。执行时核对 V3.0 模块来源和当前实际接口。

## Goals / Non-Goals

**Goals:** 在章节内看清改动来源，以已有意见/影响项组织处理工作，低成本交接内容，入口一致。

**Non-Goals:** 项目管理 SaaS、强制身份/权限、编辑排他权、Git reset/rebase 客户端、自动推送、实时多人编辑。普通流程按兜底原则继续。

## Decisions

### D1：章节历史提供一条可用阅读路径

新增只读历史 adapter，复用 VCS 命令执行/解码，支持 Git 已提交记录、重命名跟随、提交正文和当前编辑缓冲比较。Git 命令使用参数数组及仓库相对路径，不拼接用户标题；异步分页，默认先取最近 50 条，其他记录按需加载。状态栏作者/时间只表示提交记录，未提交内容单独显示。

无 Git、浅克隆历史缺失或执行失败，自动展示 LocalHistoryStore 的可用记录；无任何记录显示当前内容及来源说明，不影响编辑。历史版本只读打开，选择“用此内容保存”经既有 ContentWriter/未保存保护创建新保存，Git 历史不改。图片历史若不可取得展示缺失说明，不能拿当前不同资源冒充当时资源。

### D2：待办附着现有对象

项目 `team.yml` schema 1 含可选成员展示名和当前显示身份；意见/影响对象的扩展记录含 assignee、note、updatedAt，不建立另一套评审结论。我的待办聚合待修改/待复核、悬空关系、模块升级提示，并按来源可定位；已复核的事实仍由 V2.8/V2.9 服务决定。

未配置负责人时分组“未分配”，所有人仍可处理；配置坏时回退未分配/当前本地显示名。不增加登录或阻断出稿。筛选偏好在用户配置，团队分配在项目版本控制数据，旧记录缺字段可用。

### D3：交接包是选择内容的差异应用

包 schema 1 含 packageId、projectId、来源文档版本、创建时间、选定章节基准文本/hash与当前文本/hash、资源、固定模块/必要变体配置，以及可选相关意见 ID。基准优先用户所选集合/交付记录；没有基准用新内容交接，报告未知基准，不虚构无冲突。

复用 review_package 的元数据/HTML 阅读和 collection_ops 的安全文件打包能力，新增内容 handoff plan/apply，不重写意见 JSON 回流。对当前同项目比较 base/current/incoming；仅接收方已选且没有本地冲突的项直接应用。冲突项保留本地并展示可保存副本/待处理，其他项继续；删除默认未选，应用删除仍软删除。实际写入失败回滚本次已写范围。

资源用 hash 防同名误覆盖，修改引用时复用 V2.6 精确引用服务；模块依赖缺失用固定包快照，版本冲突另存候选而不改其他引用。异项目包可通过“导入新项目副本”读取合法内容，原项目不动。基于 packageId+条目身份+incomingHash+应用结果保存幂等记录，二次导入不重复；接收方后来修改过的结果再次比较，不强行恢复旧状态。

### D4：命令入口渐进统一

轻量 CommandRegistry 保存稳定 commandId、标题、别名、分类、适用上下文、可用原因和回调；菜单/面板使用相同 handler。首先覆盖本版历史/待办/交接和新增复用入口，其余既有 PaletteItem 保留适配，避免为了入口重构全 main_window。

已注册动作在不同入口可用状态相同；无项目的命令可给打开项目动作。最近使用记录命令 ID 和时间，不保存正文。注册失败/缓存坏时保留既有菜单入口，任务照常可执行。

## Risks / Trade-offs

- [Git 路径跟随不完整] → 明确当前可查范围并自动补本地历史，正常编辑不等候全仓扫描。
- [负责人被当作访问权限] → 分配只参与展示/筛选，已有只读项目边界保持。
- [交接覆盖本地内容] → 选定范围、三方比较、冲突跳过、资源 hash 和事务写入。
- [命令迁移扩大回归面] → 只迁移本版触及入口，旧 PaletteItem 适配保留。

## Migration Plan

无强制项目 schema 升级，协作字段缺省可用。交接包/团队配置各自 schema 1。旧意见回流、VCS 手工操作、普通项目保持原入口，版本收尾统一版本源并记录直接回归。应用任务证据写新 V3 台账，不回写并发执行的 V2 文件。

## 验收标准

- A31-1：真实 Git 两次提交/一次重命名可查、可比较当前缓冲；Git 不可用自动看本地历史。
- A31-2：负责人分配/未分配/我的待办能定位，不能替代复核状态；坏配置不阻止编辑出稿。
- A31-3：交接包含正文和资源/模块，接收方选择应用；同名不同资源不误换，个别冲突不阻止合法项。
- A31-4：重复导入不重复写/增意见，已改动的接收内容保留，失败/取消可恢复；异项目可新副本导入。
- A31-5：菜单/命令面板同动作同状态，最近命令可用，旧命令未迁移仍可达。
- A31-6：无 Git、无团队配置、离线两机器交接完成正常使用流程。
