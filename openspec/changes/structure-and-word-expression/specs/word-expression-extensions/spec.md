## ADDED Requirements

### Requirement: Markdown 超链接渲染为 Word 超链接

构建层 SHALL 把 Markdown 链接 `[text](target)` 渲染为 Word 超链接：站内章节文件或锚点目标生成 `w:hyperlink` 并指向目标书签，外部 URL 生成带关系 `r:id` 的外部超链接。解析失败的链接目标 SHALL 不使构建崩溃，并按既有引用校验逻辑给出可定位的警告或错误条目。

#### Scenario: 外部 URL 超链接

- **WHEN** 正文含 `[官网](https://example.com)`
- **THEN** 生成的 DOCX 含指向该 URL 的 `w:hyperlink` 且关系表存在对应 `r:id`

#### Scenario: 站内章节链接

- **WHEN** 正文含 `[设备管理](3.7.5 设备管理.md)`
- **THEN** 生成的 DOCX 含指向目标章节书签的 `w:hyperlink`，目标存在对应书签

#### Scenario: 带锚点的站内链接

- **WHEN** 链接目标为 `3.7.5 设备管理.md#图1`
- **THEN** 生成的超链接定位到目标文件内的 `图1` 锚点书签

#### Scenario: 链接目标缺失

- **WHEN** 链接指向项目内不存在的文件或锚点
- **THEN** 构建继续完成，校验输出可定位到源文件与行的警告或错误条目，不生成失效超链接

### Requirement: 标题书签唯一生成

构建层 SHALL 为每个标题生成唯一书签（`w:bookmarkStart`/`w:bookmarkEnd`），使站内链接与章节引用可精确跳转；书签名 MUST 基于 rel_path 或编号稳定生成，且 MUST 在文档内唯一，重名时按确定性规则去重。

#### Scenario: 标题自动生成书签

- **WHEN** 构建包含 `# 3.7.5 设备管理` 的文档
- **THEN** 对应标题段落被包上以稳定 id 命名的书签，重复构建生成的 id 不变

#### Scenario: 书签重名去重

- **WHEN** 两个标题或锚点产生相同的书签名
- **THEN** 后出现的书签名追加稳定后缀以保证唯一，且链接仍指向正确目标

### Requirement: 行内格式渲染

构建层 SHALL 支持 Markdown 行内格式：`**粗体**` 渲染为含 `w:b` 的 run，`*斜体*` 渲染为含 `w:i` 的 run，`` `行内代码` `` 渲染为使用等宽字体的 run（如 `w:rStyle` 或 `Consolas`）。行内标记 SHALL 在超链接文本与列表项内部正确拆分 run，不破坏其他结构。

#### Scenario: 粗体

- **WHEN** 段落含 `**关键**内容`
- **THEN** 生成一个含 `w:b` 的 run 对应 `关键`，其余文本 run 不受影响

#### Scenario: 斜体

- **WHEN** 段落含 `*备注*`
- **THEN** 对应文本生成含 `w:i` 的 run

#### Scenario: 行内代码

- **WHEN** 段落含 `` `print(x)` ``
- **THEN** 生成使用等宽字体样式的 run 对应 `print(x)`

#### Scenario: 行内格式与其他结构组合

- **WHEN** 行内标记出现在超链接显示文本或列表项内
- **THEN** 行内格式在链接/列表 run 内正确拆分，链接关系与列表结构不被破坏

### Requirement: 真实多级列表

构建层 SHALL 把 `-`/`*` 无序列表与 `N.`/`N、` 有序列表渲染为真实 Word 编号列表（`numPr` 与 `abstractNum`），并按缩进层级生成多级编号。有序列表 SHALL 保持作者给出的起始编号，列表被普通段落分隔后 SHALL 新建列表实例而非强制续号，行首数字加句点/顿号但非列表语义的文本 SHALL 保持段落原样。

#### Scenario: 无序列表

- **WHEN** 连续多行以 `-` 开头
- **THEN** 这些段落生成同一 numId 下的 `w:numPr`，Word 中渲染为项目符号列表

#### Scenario: 有序列表

- **WHEN** 连续多行以 `1.`、`2.` 开头
- **THEN** 生成递增编号的真实有序列表，首项保持作者起始编号

#### Scenario: 多级嵌套

- **WHEN** 列表项按缩进分层
- **THEN** 生成多级 `abstractNum`，子级按层级编号与缩进呈现

#### Scenario: 列表中断后恢复

- **WHEN** 列表被普通段落分隔后再次出现列表
- **THEN** 新列表使用新的 numId 实例，不沿用前一段的连续编号

#### Scenario: 非列表文本不误转

- **WHEN** 行首为数字加顿号（如 `1、说明`）且不构成列表语义
- **THEN** 该行保持段落文本原样，不被误转为编号列表

### Requirement: 脚注支持

构建层 SHALL 支持脚注语法（正文 `[^键]` 与文末 `[^键]: 内容` 定义）生成 `w:footnote`，脚注引用与内容按出现顺序一一对应；引用未定义的脚注键 SHALL 不使构建崩溃，并由校验给出可定位的警告条目。

#### Scenario: 正文引用与脚注内容

- **WHEN** 正文含 `[^注1]` 且文末定义 `[^注1]: 术语说明`
- **THEN** 生成的 DOCX 含脚注且正文插入对应引用标记，Word 中可正常跳转

#### Scenario: 未定义的脚注引用

- **WHEN** 正文引用未定义的脚注键
- **THEN** 构建继续完成，校验输出可定位到源文件与行的警告条目

#### Scenario: 多脚注按序编号

- **WHEN** 文档含多个脚注
- **THEN** 脚注按正文出现顺序编号，引用标记与内容一一对应

### Requirement: 构建与校验同步扩展

构建层 SHALL 在新增上述表达后保持可重复构建：同一源文档两次构建 SHALL 产生事件流与新增表达元素一致的 OOXML。`validate_docx` SHALL 识别超链接、书签、多级列表与脚注，把它们纳入事件流对比与模板保留校验，不得把合法结构误报为损坏。

#### Scenario: 重复构建一致

- **WHEN** 同一项目先后构建两次
- **THEN** 两次生成的 DOCX 在事件流与超链接、书签、列表、脚注等元素上一致

#### Scenario: 校验识别新结构

- **WHEN** 文档含超链接、书签、多级列表与脚注且结构合法
- **THEN** 校验报告不把这些结构判定为失败，对非法嵌套或失效目标给出可定位条目
