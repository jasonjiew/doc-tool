## Context

CORE 已有尽力导入、当前缓冲捕获与同轮多格式出稿；内容工作台已有图片、重构、排序、全文替换、检查与恢复。V3.7～V3.9 当前均 0/20，解决共享交互和特定页面。MAIN 新增六批/24 项，以真实主功能差额和输入→正文→成果对照为范围，原包任务与勾选不改。

可复核的具体线索：`project_from_markdown._copy_resources` 当前按 basename 去重，同时以相对路径写资源；`a/logo.png` 与 `b/logo.png` 需要核对是否误跳一份。`ReplaceService` 基于传入索引定位并通过 ContentWriter 写入，必须追踪实际 GUI 是否已用活缓冲构建索引、预览后变更如何处理。其余行为先复现验证，不能因本计划就宣称旧实现全部有缺陷。

## Goals / Non-Goals

**Goals:** 常用 Word/Markdown 内容导入后少修复；多章修改包含当前内容、范围可控；章节和资源引用联动；检查修复及预览与所见正文一致；常见 Word 排版可用、可读成果及时交付。

**Non-Goals:** 全功能 Word 富文本编辑、任意复杂对象无损转换、在线共同编辑、后台删除未引用资源、OCR、依赖模型自动改正文、自动改变评审/正式状态、重造导入或出稿引擎。

## Decisions

### 1. MAIN 与交互包分工

| 范围 | MAIN 负责 | 原计划复用 |
|---|---|---|
| 导入 | 内容/资源识别与实际读回、来源映射、默认可用结果 | 38-C 负责来源/章节预览、进度与冲突选择 UI |
| 编辑 | 活缓冲替换、章节/资源引用联动、确定性修改及恢复 | 37-B/D 负责导航、焦点与草稿入口；38-A 负责表格专用交互 |
| 检查预览 | 内容与请求代次、范围、修复和增量正确性 | 37-C 负责面板反馈/返回；39-D 负责研发慢路径 |
| 出稿 | 实际内容/版式/资源一致性与默认失败续行 | 38-D 负责设置摘要、按格式动作和样例历史 |

采用一个专门 MAIN change，保持三版原编号；把范围塞入旧任务会让进度与验收含义变化。正常次序 MAIN→V3.7→V3.8→V3.9；正在执行的批次完成后插入 MAIN，已实施差额直接复用。

### 2. 导入建立内容与资源对照

复用 intake 的解析、大纲、批量、记录、来源保留和局部继续。预览及应用引用同一解析结果，普通设置不新增必填编号/模板选择。为标题、列表、普通表格、图片、链接/代码及保留对象建立样例对照；缺项列清楚位置与原件，合法内容继续。

资源身份至少包含真实来源基目录及相对路径；相同内容可按摘要复用，不同内容同名时生成可辨识目标并改写对应引用。沿用原许可路径边界；不自动读取未授权外部位置。相比按文件名猜同一资源，这样能保留多来源的正确图片。新增来源映射为兼容可选记录，原文件不改写。

### 3. 当前内容上的批量编辑

从原缓冲服务采集当前章/选章/整份工作集，搜索预览携带相关文本摘要；打开中的脏章节在缓冲内应用并维持未保存状态，未打开已保存章节经 ContentWriter 更新。先校验所选条目的当前内容，冲突条目跳过/刷新，其余继续；不得为批量操作先保存全部章。用户一次应用的恢复范围是实际修改的内容；复用撤销和写入清单，必要时补最小分组恢复记录，不引入另一套正文存储。

章节新建/复制/重命名/排序调用 refactor/chapter_reorder/authoring_outline 和稳定条目服务。复制产生新条目身份，移动/重命名保留原身份；只有确定性引用自动更新，其余列为待修复并可定位。样例包括同名标题、代码围栏内类链接文本、脏缓冲与重复显示编号。

### 4. 图像与引用的日常修复

剪贴板、文件选择、拖入统一调用现有资源写入，引用为项目内相对路径。修复缺图选择当前引用或明确选中的引用集合；多个章节使用相同资源时显示实际范围，不默默替换全部。用户决定清理前先列实际引用；默认只报告未引用资源，不删除。

Mermaid 只用与当前源码一致的有效缓存；失败保留源码及可读说明。图片/图表/引用修复验证编辑器→预览→检查→HTML/DOCX，副本脱离原来源目录仍可消费资源。

### 5. 检查与预览共享真实工作集

沿用 EffectiveSnapshot/缓冲摘要与索引服务；当前章/选章检查不能读回旧磁盘正文。检查和预览以项目、范围、文本摘要和请求代次关联，旧结果不得覆盖新章。确定性 quick fix 先给差异并显式应用，可撤销；不能自动改编号身份、评审和业务含义。

增量检查复用 V3.6 指纹与已测依赖，无法确定影响时直接按正确范围扫描；缓存只是派生数据。至少 5 次取样比较响应与输出，性能目标根据基准写入实施台账，不能靠跳检查或隐藏问题提速。

### 6. 常用表达与出稿默认值

复用既有 DOCX 转换、模板映射、layout_profile、readonly_html 和 project_export。样例包含标题层级/列表、空值与多行表格、长表重复表头、宽图、代码/链接和字段。只调整正文支持的版式；底模封面/页眉/页脚与复杂表的原保留规则保持。缺样式自动匹配有效项，并报告实际底模及回退，不伪称全部保真。

快速出稿沿用整份+当前内容默认；选章为明确范围动作，不因上次预设暗中缩小。目标冲突/占用时尝试新的副本路径；后续格式失败不撤走已可用成果。PDF 仍按既有同轮 DOCX 路径，原轮补齐与当前新轮保持不同捕获。CLI `template-fill --output` 的文件路径含义不变。

## Risks / Trade-offs

- [为优化重做现有能力] → MAIN-A 建基准，存在的能力先证明并记录，只实现真实差额；交互任务复用接口。
- [批量修改遗漏未保存内容或隐式保存] → 工作集包含活缓冲，按选择与摘要逐项校验，修改范围与恢复清单断言。
- [同名图映射串来源] → 多目录不同内容同名、复制后脱离来源目录、同内容复用三个反例。
- [排版优化破坏底模或原复杂对象] → 正文支持矩阵、部件/OOXML 检查及原留存对照；真实 Word 视觉单列。
- [过度检查阻塞日常流程] → 同一解析/捕获复用，普通 warning 不阻止编辑与出稿，严格模式显式选择。

## Migration Plan

MAIN 为本地增量功能，不变更项目/规范 schema；必要来源或恢复记录作为向后兼容可选字段。老项目/捕获可读，无法补充新信息时显示真实缺项，不伪造身份。按 A→F 逐批交付，可回退新增 UI/适配而保留原正文、来源、旧成果和原服务。

## Open Questions

MAIN-A 先测现有接口差额，真实企业模板与 Word 视觉样例按可用环境采集。未获得样本时 MAIN-F 6.3 保留未验收，其余任务继续；不为真实环境缺口增加全局门禁。
