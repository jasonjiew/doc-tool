## Context

工具是 tkinter/ttk 桌面应用，围绕"项目"组织（`project.yml` 清单 + `content/<类型>/第X章/.../X.Y.Z.md` 分层内容，当前 requirement 类型下已 300+ 文件）。现有 UI（`main_window.py`）只覆盖构建链路：新建/打开项目、导入 Word→md、校验、正式合并、诊断构建、打开目录/报告。无任何内容级查看、检索或编辑能力——全文搜索、跨文件引用、编辑、替换等能力完全缺失。正在进行的 `optimize-internal-ui-workbench` 变更只打磨首屏（空状态/操作区/进度/结果展示），与本变更（内容操作能力）不重叠，应作为独立变更推进。

约束：
- 不更换 tkinter/ttk，不新增 markdown 渲染第三方依赖。
- 不改 `project.yml` 数据格式与 schema 版本。
- 只读项目（`manifest.is_writable()` 为假）以查看态运行，禁用写操作。
- 长操作复用现有 `TaskRunner` 后台任务框架，避免阻塞 UI。

## Goals / Non-Goals

**Goals:**
- 跨全部 .md 的全文搜索，结果按"文件+行+上下文"展示并可点击定位。
- 引用关系：识别 markdown 链接与章节号引用，支持反向引用与悬空引用检测。
- 章节树导航：左侧按章节层级渲染目录树，作为搜索/引用/编辑器共用的承载界面。
- 内置单文件 .md 编辑器，UTF-8 原子保存 + `.md.bak` 备份，侧边 md 预览（复用 build 链路渲染）。
- 全局替换：默认逐项确认、前后 diff 预览、`.md.bak` 备份、替换后自动跑校验、一键回滚。
- 章节重命名/重编号联动：基于引用分析提示受影响引用，确认后批量更新。
- 术语/一致性检查：重复标题、术语大小写不一致、TODO/TBD 残留。

**Non-Goals:**
- 不做富文本/所见即所得编辑器（tkinter 渲染能力有限，且新增渲染依赖违反约束）。
- 不做跨项目搜索（范围限定在已打开项目的 contentRoot）。
- 不做自动修复悬空引用（只检测并提示，修复走重命名/重编号联动）。
- 不引入全文搜索引擎（如 ripgrep/lucene）——内容规模（数百文件、纯文本 md）下内存内索引足够。
- 不做 md 源与 Word 源双向同步；预览仅为渲染呈现，不回写 .docx。

## Decisions

### D1 索引底座：一次扫描建内存索引，服务搜索/引用/术语三处消费
`doc_tool/application/content/index.py` 提供 `ContentIndex`：单次读取 contentRoot 下全部 .md（后台线程），构建三份结构：
- 行索引：`(file, line_no, text)` 列表，供搜索按行扫描与定位。
- 引用索引：每文件解析出的引用集合（markdown 链接目标 + 章节号引用 + 文件内标题锚点）。
- 术语表：文件内标题清单（供重复标题/一致性检查）、术语出现计数。

搜索用内存扫描而非常驻倒排：文件规模数百、单文件 KB 级，全量正则扫描耗时在可接受范围，且天然支持"整词/大小写/正则"开关而无需额外索引结构。**替代方案**：ripgrep 子进程——更快但新增外部依赖与跨平台打包复杂度，且与现有纯 Python 技术栈不符，否决。

### D2 引用识别规则：三类引用，保守解析
- **markdown 链接** `[文本](目标)`：目标是相对路径时解析为 contentRoot 下文件；目标是锚点 `#x` 时查同文件标题。
- **章节号引用**：文本中的 `X.Y.Z` 或 `X.Y`（形如 `3.7.10`）与章节文件路径 `content/.../3.7.10 名称.md` 前缀匹配。
- **文件内标题锚点**：`##`/`###` 标题生成锚点 id，供链接与"重命名/重编号联动"使用。

解析保守优先：无法可靠识别的引用形态（如 `文档3.7.10` 歧义）不强行判定，避免误报。**悬空引用** = 引用目标在索引中不存在（文件路径不存在 / 章节号无匹配 / 锚点无匹配）。

### D3 搜索/引用扫描/替换执行均走 TaskRunner
复用 `task_bridge.TaskRunner` 在后台线程执行扫描类长操作，UI 线程只消费结果事件。搜索输入去抖 + 结果集阈值（默认前 500 条，可展开），避免大文件集下结果面板卡顿。

### D4 写入安全：`.md.bak` 备份 + tmp+replace 原子写
所有写路径（编辑器保存、全局替换、重命名联动）统一走 `content_writer.py`：
- 写前将原文件复制为 `同目录/<file>.bak`（仅保留最近一份，覆盖式备份）。
- 写入采用 tmp 文件 + `os.replace`（同 manifest 保存套路），跨卷失败回退 `shutil.move`。
- 全局替换额外维护一份会话级改动清单（JSON，落盘到项目 `.state/`），供一键回滚。
**替代方案**：`diff-match-patch` 或 git 管理——增加复杂度且项目不一定纳入版本控制，否决。

### D5 md 预览：复用 build 链路的渲染，而非新增渲染库
预览不做通用 md→HTML 渲染。优先复用 `adapters/kernel.py` 与 `application/word_check.py` 对 md→docx 转换中已建立的**结构解析**（标题/段落/表格层级），在侧边用 tkinter `Text` 以富文本样式（标题分级、加粗、表格简化呈现）展示"合并后大致效果"。完整精确渲染属于 build 产物范畴（打开输出 docx 即可获得），预览只给编辑时的即时结构反馈。
**替代方案**：引入 `markdown` + `tkhtmlview` 做精确 HTML 预览——新第三方依赖、打包体积与跨平台风险增加，否决。

### D6 重命名/重编号联动：dry-run 预览 + 确认后批量写
改名/重编号时先执行 dry-run：用引用索引算出全部受影响引用（含章节号、链接、锚点），在确认面板列出"文件内位置 × 旧文本 → 新文本"，用户确认后经 `content_writer` 批量写回，完成后自动跑校验。与全局替换共享同一个"改动清单 + 回滚"机制。

### D7 术语/一致性检查：独立轻量检查器，结果进同一结果面板
`content_lint.py` 提供三类检查器（重复标题 / 术语大小写 / TODO-TBD 残留），复用 D1 索引与 D3 结果展示框架，不单独造界面。术语清单（大小写敏感对）存于项目 `.state/terms.json`，可在结果面板直接增删。

## Risks / Trade-offs

- [误报悬空引用] → 引用解析保守优先，仅识别 markdown 链接与确定性章节号；结果面板区分"确定缺失"与"疑似"，疑似项不阻断操作。
- [全局替换误伤内容] → 默认逐项确认 + diff 预览；`.md.bak` 覆盖备份 + 会话改动清单一键回滚；替换后自动跑校验。
- [重命名/重编号联动改错引用] → dry-run 预览先行，用户逐条确认；仅更新精确匹配的章节号/链接文本，不改正文自由文本。
- [大文件集搜索卡顿] → 后台 TaskRunner 执行 + 结果阈值 + 输入去抖；取消能力复用现有安全取消。
- [md 预览与真实 Word 渲染不一致] → 预览标注"近似结构预览"，精确效果以打开输出 docx 为准。
- [改动清单 .state 落盘与多实例冲突] → 沿用项目锁（`project_lock`）语义，改动清单以项目根为 key，冲突时提示先关闭另一实例。

## Migration Plan

1. 新增能力全部走新增模块与新增菜单/工作区，不改现有合并/校验语义，无 schema 或数据格式迁移。
2. 部署顺序：索引与引用解析（纯服务，可单测）→ 搜索与树面板 → 编辑器与预览 → 全局替换 → 重命名联动 → 术语检查。
3. 回滚策略：写操作以 `.md.bak` 与改动清单为兜底；UI 面板与菜单可在后续变更中独立移除，不影响构建链路。
4. 打包影响：完成后重跑 PyInstaller/Inno Setup 构建，无新运行时依赖。

## Open Questions

- 章节号引用是否需支持"跨文档类型的编号前缀歧义"（requirement 与 design 各有一套编号体系）？——初版按项目内当前文档类型单一编号体系解析，跨类型歧义留待 `content-references` spec 明确。
- md 预览第一版覆盖哪些元素（标题/表格/图片占位/代码块）？——初版覆盖标题分级、段落、表格简化呈现与图片占位，代码块高亮不做。
