## Context

公共版只允许新建 `documentType: general`，旧 requirement/design 项目兼容读写；当前 manifest 是 v1。质量规则与评审服务已有实现，但共享规范、设置编辑、项目概览与内容版本复核不足。V2.7 提供共享表达、预处理、检查/审计报告和 CLI 门禁。

## Goals / Non-Goals

**Goals:** 团队成员从规范起步；多人共享同版本规则；任务入口明确；评审与内容版本绑定；三类文档可持续维护。

**Non-Goals:** 企业业务硬编码、可执行插件、集中身份权限/审批签章、多文档追踪、自动修改正文、旧项目强制升级。

交互执行 `docs/product-flow-fallback-policy.md`：可选项兜底优先、结果集中提示、严格交付显式启用。缺可选配置/待复核项不阻止普通建项、编辑和出稿；仅停止会破坏用户内容的具体写入。

## Decisions

### D1：规范包是声明式文件集合

规范包目录：`pack.yml`（schemaVersion 1、packId、version、documentKind、文件清单与 hashes）、`template.docx`、`skeleton/`、`rules.yml`、`terms.yml`、`variables.yml`。只允许项目内文件和受支持格式，无 Python/JavaScript 插件执行。导入 ZIP 时安全提取、限制资源总量、拒绝路径穿越/外部链接；也支持选本地目录。

项目复制并固定 `standards/<packId>/<version>/`；`project.yml.standardPack` 记录 id/version/hash，不依赖用户电脑绝对模板路径。包升级先显示底模、章节与规则差异，生成备份；不自动覆盖已编辑正文，不静默改规则。提供公开可分发的 generic-requirement/design/test 三包，公司底模由团队自行导入。

模板或骨架缺失用既有通用底模/对应内置骨架继续，可选规则/术语/变量文件损坏用上次有效值或内置默认；hash 不匹配报告包发生变化，默认使用合法可解析内容，严格策略才要求固定版本完全一致。危险 ZIP 项不安装，不阻止改用内置包建项；已编辑正文不作为兜底可覆盖对象。

### D2：schema v2 把文档类别与引擎类型分开

新增 documentKind、chapters 顺序、variables、standardPack 和检查策略来源字段，公共项目继续 general。运行时顺序去重，缺失章节输出说明，非法越界项跳过不读取；未列入可输出章节给 warning，保留修订特殊规则。默认继续合法章节，不自动重写源清单；严格策略可要求清单完整。可派生基本元数据使用既有默认值，无法识别的 schema 仍只读。

迁移服务生成前后预览、完整迁移备份和日志，使用准备目录+原子替换；首次打开 v1 默认保持 v1，用户选择迁移才写入 v2。迁移后文档表达不因升级改变。未知新 schema 禁止写入，明确解释兼容边界。

### D3：章节编排与变量共用解析

v2 显式 `chapters` 是构建/树/预览/快速打开/索引的共同顺序；拖拽修改顺序并经现有重构事务处理需要重编号/路径改变的引用。v1 保留原扫描排序。

变量语法 {{productName}}，预处理和预览共用，代码/OOXML/资源路径不替换。未定义变量使用已声明默认值或保留字面语法，warning 定位后继续；不以空串吞掉内容。值只作文本，不递归执行或注入控制标记。documentVersion 从确认修订记录派生，不建立第二份手工版本。

### D4：建项有三个明确入口

规范包起步创建章节骨架；Word 路径复用预检/样式映射/保真门禁；Markdown 路径从文件列表按顺序导入正文及资源并选底模，生成正式 `project.yml` 和章节树。模板填充仍提供即时出稿入口，不偷偷转为项目。

三入口都默认自动匹配/降级创建可编辑项目，保真 finding 集中给修复入口；可选资源或规则问题不让用户重新走建项向导。

项目概览显示文档版本、最新检查是否过期、改动、待复核、最新交付与下一步动作。可定位到问题/章节/评审/输出。计数来源于现有服务，不另建一份真假不同的状态表；变更后旧检查报告显示过期。

### D5：规则、术语进入版本控制

规范包提供缺省，项目 quality/rules.yml 与 quality/terms.yml 明确整体覆盖，空列表关闭可选规则；内容结构优先按 V2.7 自动修复，安全写入边界保持。兼容旧 .state/quality_rules.json 与 TermStore，迁移一次留备份；只增加配置来源解析，不复制检查器。

设置页按基本/规范与样式/变量/规则/门禁组织，原子保存，实时校验，只读禁用；修改后已生成检查报告置为过期。

规则/术语不可解析时原文件保留，运行时回退上次有效/内置配置并集中提示；非法可选项跳过，编辑和出稿继续。能安全产出的结构修复按 V2.7 兜底，只有安全写入边界不能关闭。

### D6：评审针对内容版本

扩展现有 ReviewComment，保存 `reviewId`、章节定位（路径/标题锚点）、`contentHash`、`baselineId`、来源包 id 和状态。首版以评审范围的正文归一化 hash 识别修改：仅路径重命名通过重构映射保留定位；正文变化则旧通过/已解决记录转为待复核；定位失效进入失效状态。V2.9 再迁移为稳定条目引用。

状态：待修改→待复核→通过；失效意见保留原意见与证据，用户重新绑定后待复核。机器不把一次提交或一次保存直接标“通过”。修订记录预填改动章节与提交主题，由作者编辑确认追加，文档版本和应用版本独立。

待修改/待复核在概览和产物报告显示，默认不阻止出稿；只有显式严格交付或选定规范的严格策略才要求清零。无法获取 Git 信息用本地内容改动记录预填，不把 Git 当作必需前置。

提交消息显式包含 `Fixes R-012` 时，在已确认当前项目意见 ID 后记录提交号并转待复核；不存在或跨项目意见 ID 给提示，不创建伪意见，不直接通过发布门禁。

HTML 评审包使用现有导出服务，包含自足资源、只读前后对照、意见表单和本地 JSON 下载，离线可用，无外部脚本/上传。JSON 携带 schema/project/package/reviewId/hash；回流按稳定来源 id 幂等，旧版本意见进入待复核，异项目/损坏文件不写入。现有 Word 评审单继续使用。

### D7：重导入先计划再应用

reimport.plan 返回差异/来源 hash，异步 UI 供勾选。apply(selected) 自动刷新外部变动项，脏编辑器/冲突项保留本地并跳过，其余已选且未变项经 ContentWriter 一次事务应用；显示已处理/待处理，个别冲突不停止整批。实际写入失败回滚本次已应用范围。删除仍软删除，计划不在正文区创建 .theirs.md。

### D8：协作冲突必须明确选择

复用 `vcs_changes` 与改动面板，为 Markdown 冲突展示 base/ours/theirs 和结果编辑；保存结果前校验原冲突与工作树 hash，经未保存保护及 ContentWriter 记录。只在用户确认后标为 resolved，全部完成后提示合并提交，不能自动推送或自动宣布内容正确。二进制文件展示保留本地/采用远端/外部处理入口；SVN 暂保持检测和外部工具指引，不假装支持完整三方操作。

## Risks / Trade-offs

- [schema 升级损坏或旧应用回写] → 完整备份、hash 验证、未知版本只读；迁移失败完整回滚。
- [规范包升级影响已有内容] → 固定版本，显式预览与选择，不自动套用新骨架。
- [章节范围较粗导致多余复核] → 首版可解释保守判断，V2.9 稳定条目降低误触发。
- [项目概览扫描过慢] → 复用索引和缓存、后台读取、显示过期状态，主线程不遍历全项目。

## Migration Plan

先实现 schema/规范解析，再新增建项与设置，最后接入版本化评审和重导入。每次数据迁移有版本、备份位置、前后 hash；迁移后若用户继续编辑，回退必须先保留当前副本，不能自动覆盖。V2.7 项目保持可用；新版评审字段缺省为未知版本待复核，不丢旧台账。

## 验收标准

- A28-1：三个脱敏规范包创建可出稿项目，复制到另一机器无绝对路径依赖。
- A28-2：v1 可继续构建，升级失败不损文件；缺章节/重复清单/未定义变量默认兜底出稿，预览/检查/构建一致，严格模式另测。
- A28-3：新成员按三种入口完成建项，概览可到达阻断问题、意见与交付历史。
- A28-4：规则共享/覆盖/只读有确定结果；坏可选配置回退并继续，修订记录是版本唯一来源。
- A28-5：同一意见包导入两次不重复；正文修改使通过意见待复核；异项目包拒绝。
- A28-6：重导入个别冲突跳过而其余已选项继续；外部变动/取消/写入失败不覆盖未确认内容，待处理列表明确。
- A28-7：真实 Git 两副本冲突可查看三方并选择解决；取消/外部变动不覆盖，二进制与 SVN 明确边界。

## Open Questions

无阻止开发的产品决策。公司规范细则由本地导入包承载，不需要把生产文件或品牌写入公开默认资源；团队试点结果在验收记录中保留。
