## ADDED Requirements

### Requirement: 意见绑定内容版本
系统 SHALL 为评审意见保存稳定意见 ID、项目/章节定位、内容 hash、基线与来源，提供待修改、待复核、通过和失效状态；通过必须由用户复核确认。

#### Scenario: 待复核期间出稿
- **WHEN** 项目有待修改/待复核意见而用户未主动启用严格交付
- **THEN** 正常生成文档，在结果页集中提示意见数量并可定位，不自动改成通过，也不阻止普通出稿

#### Scenario: 已通过内容再次修改
- **WHEN** 已通过意见的关联正文内容变化
- **THEN** 意见转为待复核并显示原版本与当前差异，旧证据保留

#### Scenario: 只重命名或定位丢失
- **WHEN** 内容仅经受控重命名或关联目标被删除
- **THEN** 前者按映射保留定位与语义状态，后者标失效并保留原意见，允许人工重新绑定

#### Scenario: 提交关联意见
- **WHEN** 当前项目提交消息显式引用已有意见 ID，例如 Fixes R-012
- **THEN** 系统记录提交号并将意见转待复核，不自动标通过；无效或异项目引用仅提示，不生成伪意见

### Requirement: 离线评审包幂等回流
系统 SHALL 导出包含资源、前后对照、意见表单和本地 JSON 下载的自足 HTML 包，无网络依赖；回流 MUST 校验 schema/project/package/review ID 和内容版本，同时兼容现有 Word 评审单。

#### Scenario: 重复导入同一意见包
- **WHEN** 同一意见 JSON 被导入两次
- **THEN** 按来源 ID 幂等更新，台账不新增重复意见

#### Scenario: 旧版或异项目意见
- **WHEN** JSON 内容 hash 已过期或 projectId 不匹配
- **THEN** 前者进入待复核并说明版本差异，后者拒绝写入当前台账

### Requirement: 修订事实预填
系统 SHALL 预填改动章节和可获取的提交主题，并允许作者编辑后原子追加修订记录；无 Git 时从本地变更事实预填，不自动将提交主题当作已确认修订说明。

#### Scenario: 作者确认修订
- **WHEN** 用户修改建议摘要和版本后确认
- **THEN** 系统追加有效修订行并刷新索引和版本，取消不写入

### Requirement: 重导入先预览再应用
系统 SHALL 异步计算差异供选择应用；来源变动自动刷新、脏内容/冲突项跳过，其余已选且未变项继续。系统 MUST 保留跳过项的本地内容，实际写入失败回滚本次应用范围，结果列已处理/待处理。

#### Scenario: 选择部分改动
- **WHEN** 用户仅勾选部分重导入变化
- **THEN** 只应用所选内容，未选与冲突内容保留，删除进入回收站

#### Scenario: 预览后外部修改
- **WHEN** 本地文件在差异预览后发生修改
- **THEN** 自动刷新变动项并跳过冲突/脏内容，其余已选且未变项继续应用，集中列待处理；取消/实际写入失败不破坏当前内容

### Requirement: Markdown Git 冲突明确解决
系统 SHALL 显示 Git Markdown 冲突的 base/ours/theirs 与结果编辑，用户确认并通过工作树校验后才标为 resolved；二进制与 SVN 的未支持操作必须给出明确外部处理指引。

#### Scenario: 确认三方结果
- **WHEN** 用户保存并确认冲突结果且原冲突未被外部改变
- **THEN** 内容有恢复快照并更新为已解决，全部解决后可引导提交，不自动推送

#### Scenario: 冲突期间取消或外部变动
- **WHEN** 用户取消或原冲突/工作树内容已变
- **THEN** 不覆盖原内容、不标解决，提供刷新或外部处理入口
