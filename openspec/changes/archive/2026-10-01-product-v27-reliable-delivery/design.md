## Context

当前 `scripts/build_docx.py` 是正式项目/模板填充共用内核，但模板填充有额外预处理；`markdown_word.py` 与 `review_docx.py` 独立表达。编辑器存在 WebEngine/内置两条预览路径，冻结包排除 WebEngine。前版交付 `ContentWriter` 多版本恢复和可访问的交付历史。

## Goals / Non-Goals

**Goals:** 实现跨入口一致表达并优先跑通出稿；问题有定位和兜底；严格交付可选；无 Word 能得到可用文档及机器可读结果。执行 `docs/product-flow-fallback-policy.md`，不增加逐项确认或通用策略引擎。

**Non-Goals:** 自研分页引擎、任意 Mermaid 图种、复杂表所见即所得编辑、公式/Draw.io/PlantUML、Manifest v2、远程正式化及全内核目录搬迁。

## Decisions

### D1：公共结构层先行，逐入口接入

在 `doc_tool/domain` 放可复用块模型/解析器，在 `doc_tool/kernel_shared/docx_blocks.py` 放 OOXML 输出辅助，避免继续增加第五份正则渲染。块记录源文件、起止行、种类、属性；现有 `process_markdown` 渐进接入，保留标题/复杂表/列表兼容。评审稿和模板填充复用代码块、题注和图像逻辑；普通 HTML/Word 互转接入可共享的块数据，并以支持矩阵说明 Office HTML 适配差异。

代码块使用单格浅底容器，保留缩进、Tab、空行、反引号和中英文；长块允许分页。未闭合围栏默认在当前输入末尾补闭合并 warning；只修复解析结果，不改源码。模板填充移除去缩进分支，原始输入、资产和模板不被预处理改写。

复杂表继续用 TABLE 标记和原始 XML，生成可检索只读影子与来源记录。原 XML 可用时输出原表而不重复影子；资源缺失默认用合法影子或说明占位继续，并标明替代/缺失，不冒充原表保真。严格模式可要求原资源完整。

### D2：构建预处理在项目临时目录进行

新增 `PreparedSource` 和 `STAGE_PREPARE`，生成块/引用注册表和临时图片。复用 `mermaid.render`，V2.7 首批保证 `flowchart`、`sequenceDiagram` 的已声明子集离线出图；其余图种即使本机 mmdc 可用也不自动被承诺支持。缓存键使用源码、渲染器版本、尺寸/主题参数的 SHA-256；所有产物有来源记录。

CLI 的 Qt 栅格化运行于有 `QGuiApplication` 的专用进程或线程桥接，GUI 避免在不允许的线程使用 QPixmap。超时清理本任务进程后，默认先找同源码/参数的有效缓存，仍不可用则输出源码说明并 warning，其他内容继续；不使用过期异源码图。用户取消才结束本任务；严格模式将无法出图列为交付问题但仍保留可读参考稿。

### D3：题注与引用有稳定语法

图：`![说明](assets/figure.png){#fig-login}`；表：表前 `Table: 参数表 {#tbl-params}`；引用：`@fig-login` / `@tbl-params`。标识稳定，显示编号分别按全文顺序生成，支持范围内输出 SEQ/REF、书签和可读缓存值。重复标识只在输出层分配唯一名，歧义/不存在引用保留原文或可读“引用待确认”文本，不生成已知错误域；默认 warning 继续，严格模式可要求修复。预览与构建共享注册表，不猜测歧义对象。

### D4：横向节显式开闭

支持 landscape/end/PAGEBREAK 标记。默认未闭合横向节在当前输入末尾关闭，嵌套只保留第一层，重复开启/孤立结束忽略并定位 warning；方向不能泄漏到下章。以模板节属性复制 sectPr，恢复方向、页边距和页眉页脚；表格按版心限宽。严格模式可要求源标记完整，导入复杂分节保留说明。

### D5：预览统一为内置路径

基于已有内置 HTML/SVG 渲染更新块支持，删除或停用 WebEngine 分支及对应打包资源。避免约 120 MB 的新增运行环境及企业终端额外进程兼容负担。预览承担结构、引用和内容核对；精确分页以真实 Word 为准，产品文案与主规范一致。

### D6：默认带提醒交付，严格检查显式选择

管线顺序：源检查 → 修订准备 → 内容预处理 → 构建 → 前校验 → Word 刷新 → 后校验 → 终审 → 原子发布/历史。

复用已有 gates/Issue/AuditReport，未显式选择严格策略时缺省尽力完成，不强制写配置。缺图/渲染/引用/标记问题采用上述兜底并 warning；真实域错误优先恢复静态可读文本，做不到时保留可打开参考稿标待处理。只有不可解析的整体输入、损坏且无法产生可打开产物、破坏性写入无安全替代属于执行 error。TODO/TBD 仅检查作者正文并 warning，表格超宽/空段同级。严格策略显式启用后按约定完整性/保真/评审规则决定正式登记。

默认 warning 自动继续，不要求放行理由或额外确认，结果集中记录实际处理。无 Word/刷新失败保留 DOCX 及可读缓存值，标待刷新，提供后续刷新入口。正式登记或必需记录失败时回滚正式文件/元数据，但把新 DOCX 保留到安全独立输出目录，当前结果可打开并标登记待完成；任务成功产出与正式登记结果分别说明。

### D7：统一 CLI 报告

`check --project <dir> --output text|json|sarif --fail-on error|warning [--build] [--strict]`；build/template-fill 复用已有策略选项或新增 --strict，先核对 help。默认 fail-on error，兜底 warning 返回 0；显式 --strict 或 --fail-on warning 才提高检查要求。退出码 1=无可用方案/严格检查未满足，2=参数或运行失败。JSON 沿用 schemaVersion/command/projectId/status/issues/stages/artifacts/exitCode，报告带提醒/待刷新/部分完成及实际产物，stdout 为单一结构化文档，日志 stderr。

## Risks / Trade-offs

- [不同输出路径一次替换回归大] → 按代码块→Mermaid→题注→节依次接入，共享契约夹具测试各入口。
- [Word 域检测误判代码示例] → 扫描具体域/段落上下文并保留定位，代码内容中的错误字符串不单独判发布失败。
- [复杂原始 OOXML 无法完全重建] → 保真支持矩阵与导入 finding 保留，不隐藏降级。
- [动态预处理掩盖实际源码] → 每个块/图片/引用记录 SourceLocation，报告定位原 `.md`。

## Migration Plan

保留 v1 schema，新 `gates` 是可选字段；缺省兼容已有项目，写入遵循未知扩展字段保留策略。先接入公共模块，不强行搬迁脚本内核；旧脚本/CLI 保持可调用。新增报告旧应用忽略，V2.6.x 历史读取缺省兼容。发布 V2.7.0 时统一版本源、说明和支持矩阵。

## 验收标准

- A27-1：项目、模板填充、评审稿相同代码块保留相同文本、缩进与空行；普通互转声明并测试支持差异。
- A27-2：支持图离线正常输出；渲染故障自动用有效缓存/源码继续并 warning，取消不污染原文件，严格模式另测。
- A27-3：跨章节题注引用在重排后指向正确对象；重复/缺失标识有文件行号；Word 刷新后编号正确。
- A27-4：横向页前后方向/页眉页脚正确；未闭合/嵌套默认安全闭合并出稿，源行提示，严格模式另测。
- A27-5：GUI 与 CLI 对同一夹具得到同等严重度/阻断结果；JSON/SARIF 可解析且 stdout 无杂文。
- A27-6：三个脱敏文档样本完成导入、修改、检查、诊断稿、真实 Word 正式稿与视觉核对，问题按支持矩阵分类。
