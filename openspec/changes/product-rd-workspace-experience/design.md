## Context

参见 [proposal](proposal.md)。已有工作区、概览、设置、稳定条目、显式关系、矩阵、影响和版本集合实现；V2.9 归档报告仍明确部分 GUI 未接通。当前核心场景是单文档，企业研发团队需要额外的跨文档视角。本包补界面及适配，并尊重正在开发的 CORE 有效内容/出稿接口。

## Goals / Non-Goals

**Goals:** 接通“创建研发工作区 → 维护成员 → 声明条目/建立关系 → 查缺漏/影响 → 复核 → 形成版本集合”的最短路径。无成员关系时普通编辑和导出直接可用；用户能知道某个结果对应哪些文件、内容与缺失项。

**Non-Goals:** 实时多人协作、账号权限平台、强制审批、自动猜测关系、第二套基线/评审状态、持久批处理队列。Git、Word 和覆盖率阈值不作为日常工作的统一前置条件。

## Decisions

### 1. 文档与工作区两个上下文

主窗口保留文档工作台；增加可选工作区页，集中展示成员、概览、矩阵、影响、集合五个视图，避免不断增加常驻 Dock。设置作为当前项目操作，按基本信息/样式/变量/术语/规则分组渐进展示；门禁保持高级选项。与“替换现有编辑器”相比，这种增量集成能复用目前已可用流程。

入口接受已有工作区路径或从当前项目创建；创建后显式调用现有保存服务。添加项目时提供引用已有路径及复制入工作区两种清晰动作，复制遵守已有新 projectId 语义。缺失成员保持清单条目，给出重新定位/移除操作；其他成员仍可查看和出稿。角色是元数据，不强迫转成旧专用项目类型。

### 2. 适配现有模型，统一来源定位

薄适配层只把已有服务返回值转为界面行、操作结果和位置数据；不复制覆盖率算法。使用 projectId + itemId 定位条目，编号只负责展示。跨项目跳转通过已有项目窗口管理器打开/激活成员，再定位真实路径和行；定位失效显示原始记录，允许重新扫描。

RD-A 建立小型真实工程样例，先核对 V2.9 的两项 GUI 失败：高 schema 测试固定替换 schema 1 可能已过时，应复现后修正夹具；Mermaid 状态要分开语法有效、渲染失败和源码兜底。不以“环境问题”为由直接删断言，也不把未复现推断写成产品已修复。

### 3. 内容、关系与复核保持各自写入边界

声明/复制条目修改当前编辑缓冲，使用一个撤销单元；沿用 item_actions 对 ID 的语义。关系编辑器检索双端真实条目并显示项目、章节、摘要与类型。若选中的条目只存在于未保存缓冲，可预览并保留关系草稿，提供“保存这两端并建立”；仅保存受影响文件，不隐式保存整个工作区。重复关系保持幂等。

矩阵和影响视图必须标明已保存内容或 CORE 捕获来源；缓冲预览能继续看，不能悄悄改变磁盘状态。复核通过调用现有版本化记录服务，绑定已保存受影响条目的实际当前摘要。未保存改动可查看差异及保留复核草稿，保存对应章节后完成复核；复核前后内容变化则保留待复核状态和原因。新关联不等于已通过复核。

### 4. 集合页复用捕获和恢复服务

集合列表、详情、差异、包导出与“恢复为副本”分别调用 collection/collection_ops。恢复只生成新目录，显示已恢复、缺失、校验不符的分类；不覆盖当前工作区。当前捕获依赖 CORE 时使用其不可变来源及统一输出接口，否则可先交付已有集合的浏览/比较/导出/恢复。

成员出稿使用普通 TaskRunner 协调，同轮 Word 调用串行，结果清单逐成员记录真实 OutputState；失败成员保留待处理，其余成员结果立即可用。V3.2 再提供持久队列和跨运行续跑，本包不提前维护第二份队列状态。取消保留已完成产物，不将未完成成员标记完成。

### 5. 默认流程与验收

已有本地服务离线执行；高级功能无配置时显示清晰空状态。关系、规范和覆盖缺漏提示不阻止普通导出。分组设置复用 load_settings/save_settings，只提交当前分组，保留原有效配置，字段错误就地显示。

关键验收：单文档无需工作区；三成员关系闭环；无需求分母显示 N/A；孤立条目可定位；缺一个成员保留另外两个可用结果；无 Git/无 Word；未保存条目、过期复核、双窗来源跳转、部分恢复；1280×720 逻辑窗口与键盘可达。

## Risks / Trade-offs

- [旧 ReviewStore 与版本化记录结构不同] → 用适配器展示来源和状态；不迁移未知字段，不凭界面点击伪造通过。
- [工作区跨目录及移动] → 沿用现有路径模型，重新定位成员后刷新 ID 索引；旧记录仍可查看。
- [CORE 尚在执行] → 把新增捕获/出稿动作作为直接依赖，先交付其他视图，不重写 CORE。
- [GUI 集成容易被单元服务测试掩盖] → 自动测试真实入口/来源跳转/写入，并单列真实 Word 及桌面试点。

## Migration Plan

新入口按批次加入，不重置 V2 已归档任务。优先只读视图，随后增加窄写入动作；已有项目不需全量迁移。退回旧界面时底层文件及服务仍能读取，本包界面偏好可删除重置。

## Open Questions

真实跨屏缩放和企业 Word 模板视觉验证需在实际环境记录，不能用服务测试冒充完成。窗口跳转复用现有 WindowRegistry，实施时确认其接口；若不足，仅补定位适配。
