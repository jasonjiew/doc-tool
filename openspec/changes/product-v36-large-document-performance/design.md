## Context

参见 [proposal](proposal.md)。当前已有 TaskRunner、章节解析、搜索、Mermaid 缓存、分页矩阵模型；CORE 正在统一有效内容捕获，V3.0 将扩展装配解析。优化必须围绕实际瓶颈，不能靠缓存改变覆盖率或出稿含义。

## Goals / Non-Goals

**Goals:** 大项目打开、切换、搜索和预览可交互；减少热路径重复解析；派生缓存坏了仍可完整读取；给出可复现的冷/热耗时、内存和正确性对照。

**Non-Goals:** 换数据库平台、云检索、第二套语义搜索、持久交付队列、增量修改 Word XML 后直接标正式成功、按未经测量的固定秒数作全机器承诺。

## Decisions

### 1. 同机基准先行

建立小/中/大样例：50、300、1,000 章节，并包含普通表格、图片和显式条目关系。记录机器/环境/输入 hash、冷启动/热启动、章节首屏、预览、检索首批/总结果、源检查、完整出稿各阶段及内存。日志只记计数/摘要/时长，不含正文。

36-A 确定主要瓶颈和优化目标。默认验收目标：未修改热路径解析次数较基准至少减少 70%；优化后的中/大样例目标热路径 p95 耗时至少改善 30%，小样例 p95 不恶化超过 10%；同机每种场景至少 5 次测量，报告样本量与离散程度，不能外推为通用 SLA。后台任务界面取消请求在不超过 1 秒内获确认；Word 后端实际退出单列。若原目标路径无瓶颈，明确记录而不制造无意义缓存，应选已测出瓶颈的路径并写明目标调整理由。

### 2. 文件级派生索引及可验证失效

复用现有逻辑索引对象，增加可选持久缓存。键包括 projectId、规范化路径、内容摘要、解析器版本及影响结果的配置/规范包/装配指纹；关系变化另行失效关系派生视图。mtime/size 仅作为初筛，不能成为正确性来源。新增/删除/移动/同字节数内容改变需正确失效；无损缓存读取失败、版本未知或不匹配直接读取源码重建。

原子写缓存，配容量清理；缓存不能成为条目 ID、关系、评审或版本集合的权威存储。使用直接解析结果对照缓存结果，重复执行须一致。相比统一数据库重构，此方案可局部落地并保留无缓存兜底。

### 3. 有效内容捕获与增量视图

每个查询固定 captureId；已保存文件可命中持久缓存，未保存缓冲按其真实摘要建立本轮内存索引，不能混用磁盘旧内容。同一轮预览/检查/导出引用同一捕获，后续编辑产生新请求。V3.0 装配内容需含模块版本、槽位实例及变量指纹；未实施时先验证普通内容，后补集成任务。

所有后台读取返回 requestGeneration + projectId + captureId，界面只接受当前请求的结果。保存/外部修改/切项目触发新的代次；过期结果可入同摘要缓存，不能更新当前界面。写入型操作继续校验真实来源摘要，不能从旧视图直接覆盖内容。

### 4. 分页和渐进展示

先提供章节列表、当前章节与首批命中，后台加载其余列表；搜索/问题/矩阵使用分页数据，完整结果数在扫描完成后给出，扫描中写“已找到”而非假总数。预览先处理当前章节；只有经过正确性验证后才做块级复用，目录/锚点/表格布局相关变动需整章重建。

失败或取消可保留明确标识的已获得结果，给重试/直接扫描；不能将部分扫描报告成完整无问题。出稿仍经 CORE 的完整装配、Word 阶段和 OutputState；本版缓存主要优化源阶段，不绕过正式 Word 更新。

## Risks / Trade-offs

- [错误复用产生旧内容] → 内容/配置指纹、代次标记、无缓存对照；正确性优先于命中率。
- [缓存增加磁盘与内存占用] → 容量与最后使用清理、按页模型、取消及时释放派生对象。
- [时间噪声造成虚假提升] → 同机输入、至少 5 次、报告分布；仅评价真实瓶颈。
- [后台线程调用 Qt 控件或 Word] → UI 变更回主线程；Word 沿用串行后端，单列不可中断阶段。

## Migration Plan

缓存新增版本标记，默认可删除重建；用户可清理缓存并直接扫描。分批替换重路径调用，保留旧直接读取路径作为兜底。项目内容及清单格式不因性能优化迁移。

## Open Questions

准确瓶颈、目标机器规格和最佳缓存容量在 36-A 基准后确定；不得提前宣称全部阶段加速或固定支持某一页数。真实 Word 长文档耗时与源阶段性能分别报告。
