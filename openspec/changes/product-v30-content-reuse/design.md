## Goals / Non-Goals

**Goals:** 公共正文带资源复用、版本固定、升级可比较，产品变体可从同源内容出稿；默认缺项兜底，来源清楚。

**Non-Goals:** 在线知识平台、任意脚本/表达式、跨电脑实时引用、自动升级所有项目、project schema 3。遵循 `docs/product-flow-fallback-policy.md`，正常出稿不增加逐项确认。

## Decisions

### D1：模块随项目固定，库只负责选取与发布版本

模块 manifest schema 1 含 moduleId、version、title、tags、description、入口 Markdown、资源相对路径/hashes、文本 inputs 和来源。模块为正文加所需图片/表 XML，不内置 Word 底模。用户库可配置本地目录；项目使用时复制到 `reuse/modules/<id>/<version>/`，版本不可原地覆盖，相同版本不同 hash 另存候选新版本并提示。选库/包导入是明确操作，不后台读取共享盘的最新内容。

提取当前章时读取已保存内容或明确选中的缓冲区快照，保留来源状态；从 V2.6 的资源引用工具收集被引用资产。库以文本索引提供名称/标签/正文查找，故障直接允许手工选择本地模块目录；不增加数据库前置。

### D2：一次展开供所有入口使用

项目 `reuse/assembly.yml` schema 1 记录 slotId、宿主章节、moduleId/version、参数、headingOffset；正文插入 `<!-- DOC-REUSE: slot=<uuid> -->`。slotId 决定实例，引用模式只读查看来源，复制编辑模式展开后变为普通正文并保留来源说明。

slot 标记是实例位置的主要依据，宿主路径用于定位提示；受控重命名/移动经现有重构服务同步该提示和变体章节配置，实例 ID 保持。手工移动导致提示过期时按真实标记继续展开并提示，不因为旧路径阻断出稿。

新增纯 resolver 在既有 Mermaid 预处理之前生成 resolved 文本、资源映射、SourceLocation、warnings、依赖 hashes；预览、Word、HTML、检查和追踪索引调用同一 resolver。图片按模块来源改写到合法本地资源，不重新实现 Markdown/OOXML 渲染。仅模块间已固定引用可嵌套，首版深度 5；循环/缺失/非法项显示说明占位，其他内容继续。有效本地缓存优先，不能用不同版本缓存冒充当前模块。

### D3：参数和版本升级可解释

模块参数复用文本变量机制，以 `module.<name>` 命名避免覆盖项目变量，只有声明键可填写；代码/资源路径不替换，不执行表达式。缺参数使用模块默认值或保留字面值并 warning。headingOffset 仅改变输出标题层级（1～6 截断并提示），不修改源模块。

升级展示正文/资源/参数差异与受影响 slot，用户选定后一次更新固定版本和配置。未选实例继续原版本。复制编辑的正文不会被模块升级替换。失败保留原快照；个别无效候选跳过，合法已选升级仍可完成。

### D4：复用条目身份和影响

默认模块内容不自动加入需求分母。用户选择“纳入追踪”时，将模块 DOC-ITEM 转为该 slot 的项目实例 UUID，并在 `reuse/instances.yml` 持久化 `(slotId, originItemId)→instanceItemId`。相同 slot 重建/位置变化不换 ID；重复插入新 slot 分配新实例。升级保持可匹配来源条目身份，新增条目新 ID，删除条目留悬空待处理。实例原始条目和模块版本作为证据，不将两个项目复用同模块当作已建立关联。

影响服务增加固定模块依赖来源，只有采用新模块版本或实际参数/资源变化才触发对应实例待复核；共享库出现新版本仅提示可升级，不产生正文变更。

### D5：变体是有效内容配置

`variants.yml` schema 1 保存 variantId/name、基于现有章节相对路径的 include/exclude、变量覆盖、slot 版本/参数覆盖。首版只支持显式列表，不支持脚本或任意布尔表达式。无配置使用默认项目，坏可选项回退项目值；明确指定不存在的变体时显示可选项，GUI 可使用默认，CLI 参数失败不偷偷构建别的型号。

有效顺序=项目顺序筛选后，应用该变体变量/模块选择，再统一展开/编号。输出按 variantId 独立目录/文件名，报告记录项目版本、variantId、有效章节/模块/hashes。追踪视图明确选择范围，覆盖率分母只算变体包含且明确纳入的需求；范围外关联显示未纳入，不计成覆盖。

## Risks / Trade-offs

- [模块升级造成多文档误改] → 固定项目快照，选择实例升级，复制编辑内容保持独立。
- [复用 ID 冲突] → slot 实例映射、明确追踪纳入和来源证据，原始 ID 不直接当宿主 ID。
- [展开与预览不一致] → 统一 resolver/来源位置，复用现有渲染器和夹具。
- [旧应用忽略新标记] → 提供展开为普通正文的新项目副本，说明新功能项目需要新应用；无复用旧项目照常使用。

## Migration Plan

仅选择本版功能时写 sidecar，不更改 project schema 1/2。含新标记项目可导出已展开的普通正文副本供旧应用读取，复用 V2.9 新副本身份映射。升级前后记录固定模块清单，回退通过原快照/ContentWriter，不覆写用户后续编辑。版本源在最终收尾按当时最高版本确定。

## 验收标准

- A30-1：两个项目复用同一模块及图片，断网/换目录仍出稿；升级库不改变固定项目。
- A30-2：同一展开结果在预览/Word/HTML/检查中内容、参数、层级和题注一致，定位回到模块源。
- A30-3：缺模块/资源/参数、循环和坏库配置默认占位/回退后继续；严格模式单测。
- A30-4：相同 slot 实例 ID 稳定，新 slot 新 ID；采用新版本仅影响对应实例，不自动增加分母。
- A30-5：两变体章节/变量/模块有实际差异，输出互不覆盖，矩阵分母按范围解释。
- A30-6：v1/v2 无复用项目回归通过，展开副本可独立构建，取消/失败保留原正文。
