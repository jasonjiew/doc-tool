## Context

以本次实施后复核为基准：RD/V3.4/V3.5/V3.6 共 80/84 项已勾选，4 项真实桌面/Word/IME 试点保留未完成。工具栏、片段事务、规范包草稿/冻结/样例已修正，后续不可按旧提示词从 0 重做。现有主窗口、导航、TaskDock、命令注册、CORE 和 RD 服务是唯一业务入口。

## Goals / Non-Goals

**Goals:** 常用动作容易找到；操作有反馈；从结果回到修改位置时上下文不丢；默认单文档流程不依赖研发工作区。团队首次完成“打开→改一处→定位问题→导出→打开成果”只需学习一条路径。

**Non-Goals:** 更换 UI 技术栈、统一业务引擎重写、强制向导/Git/模型/评审、实时多人编辑、自动发布。

## Decisions

### 1. 先收敛入口，复用真实动作

首页保留“继续上次工作”为第一动作，最近项目按可用/迁移位置/缺失分类。项目条保持导入、查看问题、导出，高级能力进入当前项目的操作菜单和命令面板。选择复用现有 action registry，避免另外维护一份菜单能力表；文案采用“规范包”“研发工作区”“版本集合”，技术摘要进入详情/提示。

### 2. 页面状态属于工作位置

沿用导航/会话服务，保存 projectId、relPath、光标/滚动位置、页面和筛选；跳转携带真实来源，不以显示编号认身份。编辑器活缓冲优先于磁盘；只恢复视图，不对文件自动应用历史内容。先在现有对话框与页面间实现返回，暂不把全部 RD 页签重构成新主壳。

### 3. 主动作稳定，溢出动作可找回

编辑器保留保存、预览/阅读和常用格式入口，次要格式/文件动作按实际 fontMetrics、布局宽度进入“更多”。输入和信息列表用滚动/分页，任务和结果区可收起；大 ID、长路径放详情并可复制。采用现有 QSS tokens，避免每个对话框私有主题；1024×640 和 1280×720 下文字完整、主动作不越界，1920 下恢复布局。

### 4. 状态必须带下一步

| 状态 | 用户看到 | 可执行动作 |
|---|---|---|
| 空项目/无结果 | 原因与一个建议 | 创建/导入、清除筛选 |
| 加载 | 实际阶段与已处理数 | 继续其他文档操作、请求取消 |
| 部分完成 | 已可用成果在上，剩余项在下 | 打开成果、补失败格式 |
| 来源变化 | 原成果可打开、当前已变化 | 补原轮、按最新生成新轮 |
| 失败 | 可读错误与保留事实 | 重试、复制诊断、回到相关输入 |

现有 TaskRunner 与 TaskDock 负责运行；通知靠近按钮/面板，批量警告汇总到详情。取消请求在 1 秒内有文字确认，但后端退出仍以真实终态为准；不提前宣称任务完成。

### 5. 先做有限一致性，再扩大范围

37-A 固定入口/状态/视觉对照表与实际截图；B 实施入口；C 导航；D 状态/键盘/布局；E 闭环验证和交接。每批有可用成果，无关实机依赖单列。事件处理和销毁生命周期需验证，避免返回上一个已销毁编辑器。

## Risks / Trade-offs

- [动作集中后用户找不到原入口] → 保留现有快捷键，原菜单向统一动作转发，提示里给出位置。
- [恢复上下文误恢复旧正文] → 会话只保存位置/筛选；草稿仍用原 AutoSaveStore 的身份规则。
- [窄窗口多控件相互挤压] → 按实际宽度重排，验证文字宽度、相邻矩形和主按钮范围，不能只断言几何非零。
- [界面取消与 Word 实际退出不同步] → 分开标示取消已请求、任务已停止。

## Migration Plan

不升级项目 schema。新增用户级视图状态可丢弃、坏记录回退默认；没有新设置仍能走现有流程。按批次增量合并，回退仅移除新视图配置，不改项目正文/关系/规范包。
