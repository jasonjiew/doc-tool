## Why

当前内部桌面工具已经具备完整的项目、校验和 Word 合并能力，但高频操作仍主要隐藏在菜单中，空状态、任务结果和错误处理偏技术化，导致团队成员难以快速判断“现在能做什么、任务做到哪一步、完成后去哪里取文件”。需要在不更换 tkinter/ttk、不扩大产品边界的前提下，将主窗口优化为紧凑、直接、低培训成本的内部工作台。

## What Changes

- 将未打开项目的主窗口改为明确的空状态工作区，直接提供“新建项目”“打开项目”和最近项目入口。
- 在已打开项目的首屏增加高频操作区，直接提供正式合并、诊断构建、项目校验及内容、输出、报告等快捷入口，同时保留现有菜单和快捷键。
- 将项目摘要增强为可执行状态摘要，明确显示当前项目是否可写、是否具备正式合并条件，以及操作不可用的原因。
- 将长任务展示为可理解的阶段进度，继续复用现有后台任务、安全取消和确定性进度能力。
- 增加持久的任务结果区域：成功时提供打开产物、所在目录和校验报告等后续操作；失败时分层显示原因、处理建议和可展开的技术详情。
- 将事件日志改为默认紧凑、可展开/折叠的辅助区域，保留待读提示、复制和打开日志目录能力。
- 统一内部工具所需的有限字体层级、间距、按钮层级和成功/警告/失败语义色，不引入深色主题、动画或新的 UI 框架。
- 补充 GUI 状态矩阵、任务结果、日志折叠和关键人工操作路径的测试与验收清单。

## Capabilities

### New Capabilities

- `internal-ui-workbench`: 规定内部桌面工具的空状态、高频工作台操作、项目可执行状态、阶段进度、结果后续操作、分层错误和可折叠日志体验。

### Modified Capabilities

无。当前仓库尚无已同步到 `openspec/specs/` 的基线规格；本变更在不改变文档构建、校验、Word 自动化和安全取消语义的前提下，为现有桌面工作流增加独立的内部工作台能力规格。

## Impact

- 主要受影响代码：`doc_tool/ui/main_window.py`、`doc_tool/ui/styles.py`，以及必要时拆出的轻量 UI 组件。
- 关联代码：`doc_tool/ui/task_bridge.py`、`doc_tool/ui/wizard.py`、`doc_tool/ui/about_dialog.py`、`doc_tool/application/project_service.py`；优先复用现有状态、最近项目、窗口持久化、任务事件和输出路径能力。
- 测试影响：扩展 `scripts/tests/test_gui_services.py`，并更新桌面应用人工操作检查清单。
- 打包影响：UI 修改完成后需要重新运行现有 PyInstaller/Inno Setup 构建流水线；不增加运行时依赖，不改变项目数据格式和安装位置。
- 兼容性：保留现有菜单、快捷键、CLI 和项目结构，无破坏性变更。
