## Context

本变更面向企业研发文档作者，优化“导入 → 调整章节/正文 → 预览 → 导出 → 接收 Word 修改后再次导入”。当前工作树有其他会话实施 V2.6～V2.9，执行前核对接口，保留已完成行为与任务勾选。

已核对的基础与差额：

| 环节 | 当前基础 | 本次补齐 |
|---|---|---|
| 导入 | wizard 已有拖拽、后台预检、样式映射/大纲、阶段进度与结果；import_first_time 已有原件副本/暂存发布/往返报告 | 默认非阻塞策略贯穿 GUI 与服务，无标题不强迫映射；范围选择/映射预设/文件批次 |
| 复杂内容 | fidelity 已报告公式、脚注、修订等；原件保存在 original/source.docx；复杂表格有既有资源机制 | 明确原件位置、正文占位和可查处理记录，不把“原件留存”说成“已可编辑” |
| 重导入 | 已有 preview/plan/choices、冲突项跳过和历史写入 | 接上导入结果与来源入口，减少重新选文件和重复配置 |
| 编辑/预览 | ContentWriter、撤销、章节调整、图片修复、PreparedSource 和块模型已存在 | 明确当前缓冲/保存版本、共同快照与范围，避免看的是新文、导的是旧文 |
| 导出 | pipeline 生成 Word；convert 处理任意文件；readonly_html 支持全项目/当前章；PDF/HTML 有评审服务 | 一个项目出稿入口、任意章节范围、多格式共同来源及仅补失败格式 |
| Word 版式 | 底模/样式映射、复杂表格、图片/题注/字段刷新已有链路 | 普通图片/表格有限适配，章级横向与分页显式设置，沿用模板优先 |

源码证据按 2026-10-01 的读取记录：wizard 的预检页仍要求勾选复杂内容风险，映射页仍要求一级标题；ImportRequest 默认 ignore_roundtrip_block=False；HTML 默认保存版本。这些是本变更的集成差额，不能只改按钮文案。

## Goals / Non-Goals

**Goals:** 默认给出可用项目和产物；常规导入源已选择后最多两次主要提交即可开始编辑，已打开项目快速导出并打开结果最多两次主要操作；用户清楚哪些内容进入此次出稿；保存原始材料与复杂内容出处；减少重复参数和跨窗口操作；失败后只补缺失结果。操作数按 U-1/U-4 的有效输入/默认路径口径验收。

**Non-Goals:** 首版不新增 OCR/PDF 可编辑建项、不承诺所有 OOXML 可编辑或原样回写、不自动处理修订接受/拒绝、不新增排版引擎、持久任务队列或服务器。任意文件格式互转继续使用现有工具；高版本只读项目遵守现有兼容范围。章节拆分/合并、图片修复、片段等已有功能只接入口和快照，不重复实现。

## Decisions

### D1. 区分用户目的，复用已有用例

首页/文件菜单提供“导入文档”“新建文档”和最近文档“继续编辑”。导入自动识别 Word/Markdown后真实调用对应服务，新建复用通用模板/规范建项；临时格式转换与模板填充保留在更多工具。旧菜单/快捷方式转到同一用例；导入当前项目的外部 Word 使用既有 ReimportService，不误走首次建项。main_window 的部分建项入口当前仍显示说明后转到同一向导，须以实际产物证明适配完成。

首版接管格式为 DOCX，DOC 复用 ensure_docx_source。没有 Word 时 DOC 标记“待转换”，保留原输入并继续批次其它 DOCX，不假装读取成功。Markdown 多文件按用户确认顺序建立一份项目；Word 多文件按一文件一项目建立多个项目，首版不合并多份 Word 的封面/目录/页眉。

### D2. 导入计划先展示结果，默认策略和严格策略分离

增加轻量 IntakePlan（拟议接口，执行时适配现有模型）：sourceHash、documentType、headingDecisions、orderedSelectedSections、profileId、policy、preservationFindings、plannedTarget。核心服务接受明确策略，旧 ignore_roundtrip_block/require_exact_roundtrip 通过适配转换，不能成为 UI 隐藏状态。

默认流程：标准标题直接给章节树；缺标题提供“按单章导入”，标题样式/outline 信息作为候选，编号/字号等弱信号只在用户主动调整时作为建议。跳级在计划中压平/补结构节点，原标题文本及正文顺序保留，变化可预览。空映射不是失败；无法辨认正文边界时默认接管全部可读正文，封面/目录移入底模须有明确范围，避免把首个标题前正文吞掉。

用户可以选择导入章节及父子范围，保留祖先结构与依赖资源。空选中时内联提示选择范围；正常选择无需额外确认。Word 标题来源位置使用部件/段落或表格序号，不伪造页码；导入后对照原件、修改大纲和合并/拆分调用现有编辑服务。

BLOCK 仍可作为内容损失严重程度，但默认不等于禁止建项。只要源包可安全解析、可发布有效项目、原件与必要记录已保存，保留正文/占位并集中显示“待完善”。严格模式按清楚的阈值拒绝发布新项目。包/XML无法解析、源不可读、输出无可写路径或无法形成有效项目才使该输入失败。不能简单 catch 所有异常后宣告成功。

试构建失败时先用通用底模/合法资源占位进行一次有界重试；仍无法生成有效项目则失败并留原件/诊断位置。保真差异报告生成失败属于“对照未完成”，默认不毁掉已验证可用项目，严格模式按其契约处理；结构校验与有效 DOCX 包校验继续必要。

### D3. 导入映射预设和文件批次保持轻量

导入预设保存名称、样式角色映射、标题层级和入口设置，存用户配置；项目导入记录保存实际采用的决定。匹配根据样式 ID/名称及指纹，模糊匹配只作候选，失效项回自动/单章。不要与 template_fill_presets 的填充配方混为一份；可共享存储工具。

后台批次先串行，每文件独立事务，项目名称冲突默认新增后缀。成功立即可打开；失败/待转换项目可选择重试；取消停止未开始项，完成项目保留。当前会话的批次恢复即可，持久队列留给 V3.2。

### D4. 原件留存与正文可见缺口共同构成保真兜底

复用 original/source.docx，并新增可选 original/import-record.json（schema 1）：sourceSha256、sourceFile、actualPolicy、selectedSections、headingDecisions、findings、unavailableComparisons。findings 记录 sourcePart、elementIndex、feature、handling、editable、retainedPath、targetChapter/line（能映射时）与说明。

支持子集继续正常转成正文/原样复杂表格。公式、脚注、文本框等尚不可编辑的对象：能确定读取的文本提取为明确的参考文本；不能读取的用带来源标识的可见占位，并列原件查阅入口。现有文本/结构中可保存的图表预览只在可验证存在时作为附件，不要求安装额外转换器。批注、修订、脚注保存在原件里，不自动接受修订或把原件中的内容判断为当前正文。

首版不将未知 OOXML 自动粘回最终 DOCX，避免引用错位或重复内容。原件留存、文本降级、可编辑保留三种状态分别表达。占位默认进入 Word/HTML/PDF，并可从源码包查到对应原件；移除占位作为明确编辑行为，不清除来源账本。重导入产生新原件版本记录，复用已有差异/备份逻辑。

### D5. 有效内容快照独立于变更徽标基线

新增 EffectiveSnapshot，区别于 content/snapshot.py 的 ContentSnapshot（后者负责变更基线）。快照包含 captureId、capturedAt、scope、sourceMode、orderedChapters、text/asset/template/config hashes、locations、warnings 和私有工作目录。先解析项目章节顺序与选择范围，再在 UI 线程捕获对应编辑器缓冲，在工作线程拷贝资源并生成不可变输入。

统一出稿入口默认“当前内容”，按钮附近显示未保存章节数量；也可选“已保存版本”或主动“保存全部后出稿”。捕获缓冲不自动保存源文件、不清空脏标记；保存失败时可明确继续采用当前缓冲，不悄悄换成旧盘上版本。既有 HTML 入口仍保留其默认保存版本行为，通过适配明确传 sourceMode。

捕获后编辑不改变此轮结果；结果显示时间/范围/来源与“源已更新”信息。只读已支持 schema 的项目使用用户选择的可写外部目录出稿；未知高版本项目不绕过原兼容限制。资源在实际读取时固定 bytes/hash，发现变化对该资源重新读一次并记录，持续不可读改占位，避免无限等待。

PreparedSource 在快照上统一处理变量、图和题注。构建/HTML/检查使用同一对象；V3.0 到来后插入其 resolver，当前不以模块库为前置。正常预览和导出共享语义，编辑实时预览仍可去抖；新编辑导致预览旧快照时明确刷新。缓存 key 包含源 bytes、映射、范围、解析版本和渲染配置，禁用缓存必须能完整走通。

### D6. 一次出稿多格式，各格式独立保留

拟议 ExportRequest：captureId、formats、destination、outputName、layoutProfile、refreshPreference、policy。格式 DOCX/HTML/PDF/source-zip 可多选；范围为全项目、当前章、勾选章节（按项目顺序，不按点击顺序）。标题祖先用于导航；依赖选外章节的交叉引用显示未纳入范围，不偷偷加正文；图表编号依据有效范围。

UI 提供快速主按钮与可展开的导出设置。首用为整份/当前内容/Word/有效默认目录；成功后仅复用格式、有效目录和兼容排版设置。普通快速导出不隐式继承上次部分范围、保存版本、严格模式或覆盖行为；当前章/选章是有明确摘要的独立动作。结果列显示格式、实际路径、可读/待刷新/待转换/失败/取消，技术元数据在详情。

Word 复用现有内核与 OutputState。快照临时项目承接管线中修订/状态写入，原项目正文/版本/评审不因缓冲出稿而自动改变；构建历史登记捕获来源。正式标志仍只由实际刷新与后校验给出，不将“可读”包装成正式成功。

内核生成可读 DOCX后，先形成稳定可读副本及相应非正式状态，通过阶段事件开放结果操作，再后台串行刷新/转换。不得把正被 COM写入的临时文件当作可打开产物。刷新完成后索引增加实际更新稿与hash，保留已开放的副本；Word慢或附加格式失败不让用户一直等全部结束。格式结果需支持已可用artifact与仍处理中阶段并存，沿用现有状态而不新增正式认定。

PDF 优先从此轮有效 DOCX 经现有 convert 生成；Word 不可用/转换失败保留 DOCX/HTML，PDF 标记待转换并可随后重试。已有 reportlab 评审 PDF 可以作为用户明确选择的“结构参考 PDF”，标明 backend 与近似版式，不用它替代 Word 版式 PDF。HTML 复用离线资源包，不需要 Word。

导出索引 export-result.json（schema 1）记录 captureId、范围/hashes、各格式 path/hash/status/backend/warnings 与失败尝试；它是聚合索引，不能另行认定正式状态。重试 PDF 使用留存的同轮 DOCX，重试 HTML 使用同轮快照；需要重新捕获时生成新的 captureId 并标示，不混入旧轮成功项。取消保留完成格式；输出冲突采用新文件名，文件锁仅让对应格式改名或失败。原有正式文档和 state 不被失败尝试覆盖。

### D7. 排版策略范围有限且可追查

底模默认优先，新增“模板原样/正文自适应”预设。普通图片按当前节正文宽度等比缩放，不放大小图、不裁切。普通表格提供等宽/按比例列宽，重复表头，并有跨页行是否允许的设置；合并单元格复杂表格默认原样，需单独支持测试后才纳入自动策略。

横向是用户显式选择的章级设置，写 section break 并保持页眉/页脚继承；只展示宽表建议，不自动把整份文档横向。分页默认沿用模板，提供明确的章前分页开关；首版不做自动全文“空白页清理”。超宽且仍不能容纳的内容保留并定位提醒，不隐藏列、不任意缩到不可读字号。

源码包固定为 ZIP：按范围保留普通 Markdown、依赖资产、底模、必要项目设置、source-map/export-result 与选择包含的原件；排除凭据、.git、缓存、用户配置和无关历史。默认给可再打开的项目副本，旧项目识别方式不变；V3 引用存在时调用其展开副本，缺该能力则清楚列缺项而不宣称自足。包内 path 必须相对安全；缺资源占位和清单说明；解压到新目录可读取并再次构建。

### D8. 入口与机器报告渐进整合

CLI 只增加与本用例对应的明确操作；先核对现有 argparse/help，不重新定义 template-fill --output（DOCX 路径）或全局输出格式。拟议 project-export 使用 --formats、--scope/--chapters、--destination、--source-mode 和报告开关；CLI 无缓冲时明确拒绝请求 current-buffer，或要求显式输入快照文件，默认 saved。

批次/格式状态采用单一机器报告，默认有可用项目/产物可返回成功并列出部分失败；显式严格模式违反阈值返回非零，完全无可用结果返回失败。沿用现有稳定退出码/错误模型；新增语法和退出约定在实施时用 help 和契约测试固定。进度使用现有 TaskRunner：当前文件/章节、阶段、完成数，取消有效；无法估计时显示阶段，不捏造 ETA。

### D9. 默认值、结果与恢复有明确易用性契约

完整交互与验收见 [实用性与易用性要求](../../../docs/product-core-usability-contract.md)，编号 U-1～9 并入现有40项。采用渐进呈现：常规页给内容摘要、少量可改字段和一个主动作，高级页才显示映射/严格/排版/源码选项。相比每次展示全部能力，这一设计减少日常选择，同时保留原有精细设置入口。

导入名称/位置从已有可信元数据、文件名和有效默认目录补齐，编号可空；Word默认源格式、Markdown默认通用模板。单份从首页成功后进入编辑，摘要留在工作区；已有工作区发起时不自动切走脏内容。最近项目/会话、编辑工具栏、图片粘贴、草稿与撤销沿用现有服务，只补入口与状态，不建设新的编辑器。

结果先提供可读文件与目录按钮，再归并同类问题；默认最多3个有直接行动价值的问题，完整事实和自动处理放详情。问题行连接现有资源修复、章节定位、原件、Word刷新、PDF重试和目录选择；缺依赖的动作给相应下一步，不弹空对话框。自动回退输出位置先用已知有效目录，再回应用既有默认用户目录并显示实际位置，所有输入和设置保留。

界面中使用“当前内容”“原件”“目录待刷新”等措辞，不展示 captureId/hash/schema/backend 等内部概念为必选项。点击开始/取消立即有状态且防重复，编辑可继续；1280×720逻辑窗口主操作可达，高DPI与Tab/已有快捷键检查纳入H。先修布局与入口，复杂可视化表格/富文本引擎和埋点平台不进入本包。

## Risks / Trade-offs

- [默认不阻断会被误认为完全保真] → 原件/文本降级/可编辑状态分别展示，正文可见缺口，结果先给可用路径再列待完善项。
- [快照出稿触发原管线修订写入] → 写入隔离到快照工作目录；验证原件/源树/版本/脏缓冲与评审状态不被隐式修改。
- [多个入口重复解析或配置失配] → 单一 IntakePlan/EffectiveSnapshot、hash 完整缓存 key 和旧入口适配，不先重构整 UI。
- [有模板表格或 section 的版式退化] → 模板原样为默认，普通表格范围有限，章级横向显式，复杂表格继续原样。
- [重试使用后来内容导致版本混合] → 保存同轮输入、DOCX 和 hashes；新捕获创建新轮，无法取到原快照时说明重新生成。
- [导出某章不等于完整项目正式发布] → 显示范围/祖先/缺失引用，OutputState 与评审版本事实复用既有定义，不借部分出稿自动推进全项目评审。

## Migration Plan

默认按 CORE-A→H 实施；优先主流程时按 A→B→C→E→F→D→G→H。CORE-A/B/C 先消除导入主流程阻塞并留可查原件，CORE-E/F 先形成快速 Word的完整路径，再补 D/G 与多格式/选章，H对每个已实现路径及时留验证和说明。首个可用阶段不要求全部高级能力，但尚未完成任务保留未勾选，不能称整个change完成。新增 sidecar 全可选，缺少时旧路径可用；不修改 schema/version 源直到实际交付收尾。旧入口先接适配，再考虑隐藏重复入口。

回退只撤去新入口/可选策略，原项目/原件/已生成成果保留；配置损坏回默认，新模式的快照不写回源。更新独立 CORE 台账，不改 V2 并发实施台账。Word 实机/冻结环境缺失单列待验收，其余自动和离屏检查继续。
