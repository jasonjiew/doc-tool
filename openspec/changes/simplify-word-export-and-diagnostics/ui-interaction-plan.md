# Doc Tool UI、交互与样式整合方案

日期：2026-10-29。主线：**导入 Word → 拆成 Markdown → AI 修改 → 确认导出设置 → 合回 Word → 打开结果**。

本方案把六项交互修正与用户新确认的样式优化合在一起，供执行 AI 和验收者对照。行为以本 change 的 `specs/` 为准，唯一实施清单为 [tasks.md](tasks.md)，执行顺序为 7—12 → 14—15 → 13，已完成项及证据保留。功能落点见 [design.md D7](design.md#d7-六项最小修正的执行设计)，样式参数和落点见 [D8](design.md#d8-与六项修正一并执行的样式设计)。

源码核对基准为 `5c46b1b` 加当前工作区；执行中的代码已有部分调整。本方案描述目标交互，不将源码存在、任务勾选或示意图当成运行验收通过。本文所有界面示意均为示意，名称、数量和路径不代表真实业务结果。

## 2. 主页面按钮

仅示意本轮涉及的原有区域；未画出的现有控件不构成删除要求。

```text
顶部项目条（原位置）
文档名 · 类型 · 版本 · 当前状态
                          [导出 Word…] [成果] [检查 F5] [更多 ▾]

编辑器工具栏（原位置）
[标题 ▾] [B] [I] 其余现有常用格式… [表格] [图片] [保存] [更多 ▾]

章节树、标签、Markdown 正文及按需预览：沿用现有布局
```

### 2.1 顶部动作

- **导出 Word…**：沿用主要按钮样式。一次点击打开现有导出设置，不直接生成或保存全部正文。
- **成果**：沿用已有名称与计数，找回当前项目的导出结果。零成果时显示现有空态，说明从哪里开始。
- **检查 F5**：沿用次级动作；空间不足时按已有溢出规则收纳，F5 继续可用。
- **更多**：导出设置/其它格式、快速构建、正式出稿固定在这里，其它原有项目动作按当前规则保留。同一动作只出现一次。

窗口变宽、恢复任务可用性、切换主题或项目，都不把固定收纳动作搬回顶部。窄窗口优先保障导出 Word 和成果可达，复用原布局机制。

### 2.2 编辑器动作

常用格式顺序、图片/普通表格与保存保持现状；仅将已经收纳的表格网格、粘贴为表格、Mermaid、批量转图、片段、本地历史、回滚和外部打开固定放入原更多菜单。常用动作因空间不足进入该菜单时，与固定条目去重。

更多菜单仍使用原功能及只读/撤销规则，一次点击只执行一次。顶部、编辑器、结果区的更多各自只放该区域动作，避免额外嵌套层级；提示可说明“更多文档操作”“更多编辑操作”“更多成果操作”。不根据光标位置动态重建一套工具栏。

## 3. 导出设置：先确认，再生成

复用现有设置对话框及字段，不增加向导页。示意中的布局重点是默认值、来源说明和始终可达的提交区，具体字段顺序沿用现有实现。

```text
导出设置

文件名     [自动名称，可修改]
保存位置   [当前有效目录                         ] [选择目录…]
导出范围   [整份文档 ▾]
内容来源   [当前编辑内容（含未保存修改） ▾]
           将包含 2 章未保存修改；源文件保持不变。

格式       Word 默认勾选；其它格式沿用现有选项
           沿用项目原格式，实际输出名称在本页可见

▸ 高级设置

                                      [取消] [开始生成]
```

交互规则：

1. 目录、命名、整份范围和来源使用已确认的默认策略，默认有效即可直接开始。自动名称可通过原预览显示，不重做命名逻辑。
2. 参数错误在原字段或现有错误区提示，保留已填内容。开始/取消位于滚动内容之外，1024×640 下仍可访问。
3. 文档属性、目录页码和排版细节沿用高级折叠区，普通状态不要求理解域代码或内部后端。
4. 点击开始时按本次参数核对输入并提交一次；没有额外配置确认或普通完成弹窗。
5. 取消或 Esc 返回此前编辑处，不创建任务、捕获或失败记录，不保存正文或清除脏标记。
6. 按钮、菜单、Ctrl+E、结果里的“按当前内容生成”和更改位置，都进入同一设置。旧结果带入可恢复参数，实际范围与来源必须可见。
7. “重试本次内容”继续原捕获和已确认设置，直接重试，不重复打开设置；其提示说明“使用上次导出的内容，之后的修改不纳入”。

## 4. 内容冲突：只在必要时选择

外部文件变化不等于一定发生冲突。无冲突继续普通设置流程；窗口没有未保存修改时，采用实际文件最新内容，不要求先切换标签或逐章保存。

只有本次范围内的未保存窗口内容与外部文件分叉，或来源无法核实时，才在原设置的内容来源区域提示：

```text
内容来源   [请选择本次导出的内容 ▾]

检测到 1 章同时存在窗口修改和外部文件修改：章节 A
请选择本次采用的来源；两份原内容均保留。

  当前编辑窗口内容 —— 外部文件中的不同修改不纳入
  已保存文件最新内容 —— 本次范围内的窗口未保存修改不纳入
```

- 复用原来源下拉、说明和错误区，不另弹冲突确认，不做逐章问答或自动合并。
- 未明确选择时保留表单并提示原因，不能继续使用一个未经确认的默认项。选择后摘要说明实际采用什么、哪些修改未纳入。
- 文件不可读或来源未知，明确写“无法核实”，不伪装成“没有变化”。没有可靠作者信息时只说“外部修改”，不宣称一定由 AI 完成。
- 来源确认后到捕获前又变化，则说明内容再次变化并保持原输入。用户可以返回原参数设置核对，系统不自动循环重试。

## 5. 生成、成功与失败

沿用右侧任务/成果区域。正文仍可编辑；后台事件保持编辑焦点和用户已有侧栏偏好，已完成结果可从成果找回。

### 5.1 生成中

```text
正在生成 Word
当前阶段：校验文档
已用时间：00:18

▸ 日志
                                      [取消]
```

阶段与时间来自实际执行，继续使用原任务进度能力。取消后及时显示“正在取消…”并防重复，实际停止沿原安全边界；关闭面板不等于取消任务。开始后的新编辑不混入已经捕获的本轮内容。

### 5.2 已有可用 Word

```text
Word 已生成
文件：本次真实输出名称.docx
位置：本次真实输出目录

[打开 Word] [更多 ▾]
```

如果目录/页码待刷新，标题或说明明确“可读稿，目录/页码待刷新”，仍可打开稳定文件。PDF 等附加格式失败时分别说明，不撤回已有 Word；正式状态沿用实际登记事实。

更多中保留适用的原操作，例如打开位置、复制路径、重新导出与诊断；不重复摆放主动作，不自动启动 Word。长路径可省略显示，但原提示、复制和打开操作取得完整真实路径。

### 5.3 无可用 Word 或任务未完成

```text
本次导出未完成
原因：<本次真实短原因>
阶段：<实际失败阶段>
位置：<可核实的原章节与行号；未知则说明无法定位>

[本次适用的主要动作] [更多 ▾]
```

| 实际结果 | 唯一主要动作 | 次级信息 |
| --- | --- | --- |
| 有可打开 Word，含待刷新或附加格式失败 | 打开 Word | 保留真实待办，恢复动作放更多 |
| 无 Word，有可信源问题位置 | 定位问题 | 原因、诊断和返回编辑路径 |
| 无 Word，已明确输出位置不可用 | 更改导出位置… | 进入同一预填设置，再确认生成 |
| 无 Word，已确认适用重试且原输入可恢复 | 重试本次内容 | 明示沿用上次内容 |
| 原输入失效，需要采用最新内容 | 按当前内容生成 | 进入设置，旧结果保留 |
| 原因未知或缺少可信恢复依据 | 复制诊断 | 说明限制，其它仍适用操作进入更多 |

主要动作的选取沿 [design.md D7.5](design.md#d75-诊断接线与一个主要动作)，不能只凭“failed”就默认推荐重试。没有可信源位置不猜行号；不把临时目录路径当原文件位置。

结果卡片从顶部排布，原因能换行，技术细节按需查看；避免原因落在大块空白中央。诊断使用现有 Markdown 投影，从更多复制或打开真实保存记录；没有保存时说明当前仅可复制，不让用户寻找不存在的日志。

## 6. F5、焦点与键盘

| 操作 | 用户看到的行为 |
| --- | --- |
| F5、顶部检查、对应检查菜单 | 在现有格式检查面板显示当前内容结果及实际范围；未执行不显示通过 |
| 检查时有未保存修改 | 修改参与检查，正文、修订记录、项目版本和脏标记保持 |
| 既有自动校验联动 | 更新现有检查事实，保持用户面板偏好，不套用主动 F5 的展开行为 |
| Ctrl+E | 打开一次同一设置，确认前不导出 |
| Ctrl+S | 沿用当前章保存语义，不被导出或检查替代 |
| Esc | 关闭当前设置或临时层，回到原焦点；不误取消后台任务 |
| 定位问题后返回 | 复用已有后退/位置恢复，回到此前章节、光标和滚动位置 |

主动作使用当前主题主要按钮样式；次级按钮和更多采用同一区域较轻层级。成功、失败、待刷新同时有文字说明，不能只用颜色区别。所有提示在现有控件呈现；本轮按下节与设计 D8 统一局部间距及层级，复用现有主题和字体常量。

## 7. 样式怎样落到现有界面

目标是更清楚、更紧凑，让用户看到“现在是什么状态、下一步点哪里”。具体数值以设计 D8.2 为准；本节只描述效果，不建立另一套视觉参数。

| 区域 | 样式落地 | 需要保留的交互 |
| --- | --- | --- |
| 顶部项目条 | 原蓝色导出按钮为唯一填充主动作；成果、检查和更多使用中性轻样式，统一必要间距；项目身份信息可读 | 主按钮先打开设置，收纳动作不因窗口变宽返回 |
| 编辑工具栏 | 常用格式保持原顺序和紧凑尺度，保存及更多清楚可达，焦点边框可见 | 不增加新工具栏、菜单层级或光标驱动布局 |
| 导出设置 | 标签对齐，输入值、来源说明、模板摘要分层；组内紧凑、组间留少量空间；开始突出，取消次级 | 单页、预填、一次确认；高级区滚动但提交区固定 |
| 表单错误 | 错误使用当前主题语义色＋文字；仅已知字段加错误边框；修正后清除，不整页红色 | 保留所有输入；来源冲突仍只在原来源区选择 |
| 成果/失败结果 | 顶部标题与正文级短原因，随后阶段/位置和唯一主要动作＋更多；明细自然高度，完整异常折叠 | 依真实事实决定动作，待刷新和部分成功不被颜色掩盖 |
| 长文字与路径 | 原因换行；路径可在原控件查看完整值，显示省略不影响复制诊断 | 不强制撑宽窗口，不删技术事实或新增查看向导 |

不新增外层工作台卡片、渐变、阴影、装饰插画、动画或主题管理页。现有字体和 4/8/12/20 间距可复用即复用，不为统一风格重写 Qt 控件或业务类。必要修改集中在现有 QSS 与本轮控件布局/属性。

结果阅读示意（颜色与尺寸依现有主题实现）：

```text
本次导出未完成                       ← 区域标题
未找到本次引用的图片。               ← 正文级短原因，允许换行
阶段：构建文档                       ← 次级信息
位置：可核实的原章节与行号

[定位问题] [更多 ▾]                  ← 唯一主动作，按真实状态变化
▸ 技术详情                           ← 原有详情/诊断入口

剩余空间自然留在内容之后
```

以上为排版示意，失败内容与动作仍由 CF-04 决定，不要求制造该错误或增加新的诊断控件。已满足这些规则的区域只取证，不反复调整。

## 8. 验收与交接

正常操作预算仍为 **打开导出设置 → 确认开始 → 打开 Word，共三次主要操作**；不计系统文件选择器内部操作及用户主动细调。来源冲突属于例外，只在确有分叉或未知时增加明确来源选择。已显示失败卡片复制诊断最多两次操作；可核实问题定位及返回各一次。

| 需验收的交互 | 检查方式 |
| --- | --- |
| 固定收纳稳定 | 1024×640、1280×720、较宽窗口反复缩放，开关预览/侧栏、切换主题与任务状态，检查动作不回到工具栏且菜单无重复 |
| 一次设置一次提交 | 真实点击按钮/菜单，并实际按 Ctrl+E；取消后零提交，再确认后一次提交 |
| 失败能直接处理 | 真实服务错误传到卡片、定位和 Markdown；未知原因时复制实际诊断，不手工填视图充当链路验证 |
| 来源选择明确 | 仅窗口改、仅外部改、双方冲突、来源未知和确认后再变化分别验证，两份原输入保留 |
| 检查反馈可见 | 收起工具面板后按 F5，看到真实检查结果，源与版本不被写回 |
| 文字和关键动作可读 | 长中文名称、长原因与路径、深浅主题下不遮挡保存/导出/开始/取消；以能正常显示中文的环境验收 |
| 样式层级与布局一致 | 对照同尺寸深浅主题截图，检查每区域至多一个填充主动作、错误与焦点可辨、短结果靠上且长内容不把主动作挤出可达区域 |
