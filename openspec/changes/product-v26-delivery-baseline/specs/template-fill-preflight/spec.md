## ADDED Requirements

### Requirement: 只读生成预检
系统 SHALL 在填充前生成输入顺序、大纲、图表数量、底模/映射状态、输出冲突和已知表达降级摘要；预检 MUST 不调用 Word、不写 DOCX、不修改输入/底模。

#### Scenario: 预览多份 Markdown
- **WHEN** 用户选择底模和三份 Markdown 后查看生成摘要
- **THEN** 显示列表顺序及大纲、资源、警告；修改列表顺序后摘要更新，原文件保持不变

### Requirement: 分级预检与自动兜底
系统 SHALL 默认缺图占位、无效映射自动匹配、部分缺输入跳过、不可用底模回退已有有效底模/通用底模；输出冲突改用安全新路径。系统 MUST 记录实际替代/跳过项及源位置；仅无可用输入/底模或无法安全产出时停止对应生成，严格交付由用户显式选择。

#### Scenario: 图片缺失
- **WHEN** 输入引用必需图片但文件不存在
- **THEN** 默认以说明占位继续生成，结果为带提醒完成并给源位置，无需逐项确认；严格模式才按完整性规则拒绝正式登记

#### Scenario: 缺失部分输入与输出同名
- **WHEN** 一份输入缺失而其余可读，且所选输出会覆盖源文件或已有文件
- **THEN** 默认跳过缺失输入并生成安全新文件名，保留有效输入顺序，报告部分完成与实际输出路径

#### Scenario: 底模与映射失效
- **WHEN** 底模不可解析或预设映射在当前底模中不存在
- **THEN** 尝试已有可用底模/通用底模并自动匹配标准样式，报告替代；所有底模均不可用时才停止生成

#### Scenario: 预检后外部修改
- **WHEN** Markdown 或底模在预检后改变
- **THEN** 自动更新计划并固定本次实际输入，继续生成并记录快照信息，不反复要求用户重新预检

### Requirement: GUI 与 CLI 预检同源
系统 SHALL 让既有 template-fill GUI/CLI 调用同一计划服务，支持 `--dry-run --report-format text|json` 与显式严格策略，保留 `--output` 路径语义；dry-run 不生成产物。退出码 MUST 为 0=有可用方案/结果（含 warning）、1=无可用方案或严格策略未满足、2=参数/运行失败。

#### Scenario: 命令行 dry-run
- **WHEN** 对同一组输入调用 template-fill --dry-run
- **THEN** 报告与 GUI 的顺序、阻断和降级事实一致，没有新产物，JSON 选择时可单独解析 stdout

### Requirement: 任务阶段与取消真实
系统 SHALL 显示解析/扫描文件/装配/可选刷新等真实阶段和可用定位/重试动作，不能伪造未知进度或 ETA；取消 MUST 保留原输出并清理本任务临时文件。

#### Scenario: Word 不可用或刷新失败
- **WHEN** 已成功装配 DOCX 但 Word 刷新不能完成
- **THEN** 保留可打开 DOCX，报告待刷新和后续刷新入口，不撤销已生成结果或要求重新生成正文

#### Scenario: 取消生成
- **WHEN** 用户在可取消阶段取消任务
- **THEN** 任务记录为取消而非成功，已有产物保留，输入不改写
