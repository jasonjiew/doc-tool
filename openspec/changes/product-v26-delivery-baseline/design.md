## Context

基准：2026-09-30，HEAD `bbfc71a`，APP_VERSION 2.6.0，project schema 1。现有 `ContentWriter` 已有原子写、`.bak`、软删除及回滚；`BuildHistoryStore` 已有归档、列表与差异方法；模板填充剩余真实底模人工验收。实施前重新核查 HEAD，不把此快照视为永久事实。

## Goals / Non-Goals

**Goals:** 在 schema 1 上完成可维护的 V2.6.x，提供日常创作与快速离线出稿收益；暴露交付历史；让重复保存、删除和恢复不会静默丢数据；建立后续版本验收证据。

**Non-Goals:** 新排版能力、规范包、跨文档追溯、AI、整项目恢复、自动下载或发布安装包。

2026-09-30 扩展范围：预设/预检、大纲统计、研发片段、图片引用批量辅助、只读 HTML 包。已有单条修复、片段 CRUD、底模记忆与 HTML 服务保持复用；不能将其重写当作扩展完成。

执行原则：`docs/product-flow-fallback-policy.md`。默认优先生成可用结果，自动修复/降级集中在结果页提示；没有必要的逐项确认，不要求 warning 放行理由。严格交付显式选择；取消、只读与防止破坏用户内容的边界仍有效。

## Decisions

### D1：基线证据与版本状态分开

新增 `docs/release/v2.6-baseline.md`，逐功能记录代码入口、可达入口、测试命令/结果和真实样本状态。历史报告只提供线索，不能直接复用旧的“通过”结论。验收记录区分“已实现”“自动验收通过”“实机验收通过”“待环境”，不能只用一个完成勾选代替。

### D2：复用写入器，增量扩展历史

所有保存/替换/重构后的正文写入仍经 `ContentWriter`，新增项目内 `.state/local_history/<path-key>/<snapshot-id>/` 与索引，记录原相对路径、时间、hash、来源操作、字节数。优先持久化旧内容快照，再原子替换正文；多版本快照失败但已有本次旧内容 `.bak` 恢复点时继续保存并提示历史降级。只有覆盖现存正文且没有任何可靠旧内容恢复点时才停止该覆盖。索引写失败但快照已落盘可后续重建，不把索引故障变成保存失败。

每文件默认保留最近 20 份且该文件历史总量目标上限为 50 MiB，写入成功后淘汰最旧快照，至少保留最新恢复点和恢复前快照；单份必要快照已超上限时允许临时超限并报告体积，不能跳过备份。正在写入/恢复的项不可淘汰。项目打开和读取不产生历史。历史索引损坏允许按快照元数据重建，不把原正文作为可删除缓存。

### D3：回收站保存每次删除

现有 `<trash>/<rel_path>` 会覆盖同路径旧删除，应改为 `<trash>/<operation-id>/<rel_path>` 并兼容读取旧 `trashPath`。删除记录含正文/资源类型和原位置。恢复以一次写入事务完成，目标已存在先展示差异，用户选择恢复为副本或覆盖；覆盖前保留当前文件快照。只读项目可以查看历史，禁用恢复和删除。

不自动级联清空引用图片；资源恢复经既有项目路径包含校验，禁止从任意绝对路径恢复到项目外。

### D4：交付历史先提供只读浏览

输出区域/命令面板打开交付历史对话框，调用已存在的 `list_entries/get/diff/text_diff`，显示文档版本、时间、应用版本、产物与检查摘要。两个历史版本比较按已归档章节内容，不重新构建。旧历史缺少字段显示“未记录”，损坏条目显示错误且不阻断其余记录。

### D5：输出状态统一语义

正式登记沿用现有刷新/后校验判定，但普通生成不绑定正式登记成败：无 Word/刷新失败保留可读稿标待刷新，给后续刷新入口。诊断/部分结果状态明确，模板填充不冒充项目正式历史；结果先显示可用文件，用户可继续编辑/检查/出稿。

### D6：分发安全核对作为基线任务

核查证书与密码文件是否处于仓库/公开导出范围，若有暴露修复引用与扫描规则，迁到外部配置位置并验证签名流程；保留现有发布门禁。不得把签名私钥内容写入报告。已修复项通过证据结项，不重复迁移。

### D7：填充预设与最近任务是用户配置

在应用现有用户配置根保存 `template-fill-recipes.json`（schema 1）与 `template-fill-jobs.json`。recipeId/名称、底模路径/hash、样式映射、清理旧正文/刷新选项、输出目录建议；预设不内置 Markdown 正文或团队业务规则。旧 last_template 仍可读取，首次只作为未命名的上次设置，不强制覆盖用户选择。

最近任务最多 20 条，记录 jobId、时间、输入文件顺序与 hashes、预设/底模 hash、设置、实际输出、状态、报告路径，包含带提醒完成/待刷新/部分完成。选择“再次生成”回填对话框，启动后生成；输入变化自动刷新摘要，同名输出默认生成新文件。底模 hash 变化时重新枚举，保留仍有效映射，其余按既有名称/标准标题及正文样式匹配兜底，不强制重选。坏配置隔离并回退上次有效值/内置默认；任务记录写入失败不撤销已生成文件，当前结果页仍可打开产物。

### D8：生成前预检提供事实，不复制发布终审

新增纯服务 `plan_template_fill()`，复用底模解析、Markdown 结构与资源解析，返回文件顺序、标题大纲、图片/表数量、已知降级、输出冲突与 Issue(path,line,severity,message,action)。预检不调用 Word、不装配正式 DOCX、不清理底模原文件；预览清理范围仅说明内核既有行为。

默认缺失部分输入跳过，缺图用带源位置的占位说明，映射无效自动匹配；底模不可用尝试已有有效底模记忆/应用通用底模，无可用输入或底模才停止。输出指向源文件/被占用时改用新输出路径，不覆盖源文件。所有替代/跳过写入摘要，默认不要求确认每条 warning。V2.7 的题注/终审规则未实现时报告未执行。提交前输入变化自动刷新计划一次并固定实际使用的输入快照，继续生成，不反复要求用户预检。

GUI 与既有 template-fill CLI 同源，新增 `--dry-run --report-format text|json` 和显式严格模式选项（实施先核对 help，优先复用已有策略选项），保留 `--output` 路径语义。默认 dry-run 0=有可行方案，1=无方案或严格策略未满足，2=参数/运行失败；warning/兜底仍返回 0，报告包含实际底模、输出路径、跳过项与结果完整性。

阶段状态包括解析底模/扫描第 N 个文件/装配/可选刷新/完成；仅有可靠计数时显示数量。Word 不可用/刷新失败保留 DOCX，标待刷新并给后续刷新入口，其他章节继续。取消沿用 TaskRunner，保留原输出并清理本任务临时文件；结果页先给打开产物，再集中提示降级/跳过/未执行和定位/重试动作。

### D9：大纲和统计基于当前编辑缓冲

复用 Markdown 结构工具，读取当前编辑器缓冲而非已保存索引。代码围栏内伪标题忽略，真实标题按层级/源行显示，可过滤、点击跳转并突出当前所在标题；复用既有行定位，不另建项目章节树。

统计去抖刷新：原始字符数（含空白）、选区字符数、非代码正文 CJK 字符数、ASCII 字母/数字/下划线 token 数、标题/表/图数量。UI 明确计数定义，不将中英文混合数宣称为统一准确“词数”。HTML 标记和控制注释不算正文文字，合法代码示例不算 TODO 待办。仅当前章统计为必做，项目合计不成为全库同步扫描负担。

### D10：研发片段复用现有占位符

复用 SnippetStore/SnippetDialog/expand_placeholders，加入通用示例：功能与验收要点、接口字段表、异常/边界说明、修订说明、流程/时序图源码骨架。这些是可编辑正文片段，不承诺 V2.7 的 Mermaid 正式出图已存在。

内置库与用户库分层，内置可复制后编辑，升级不覆盖用户条目。支持触发词/描述搜索和 UTF-8 JSON schema 1 库交换（trigger、description、body）；导入先校验和预览，重名选择跳过/重命名/替换，一次原子保存。无脚本执行/文件 INCLUDE/项目变量替换；插入通过编辑器撤销栈和既有 Tab 占位符，只读禁止插入。导出仅选定文本片段。

### D11：图片批量辅助沿用引用与事务

在现有资源面板增加资源→被引用章节/行、尺寸/体积、相同字节 hash 重复候选。仅相同文件名不能推断同一图片；没有旧 hash 的缺失资源由用户选择正确目标，系统不自动猜测替换。

按缺失目标分组，选择新图片→导入到项目资产目录或使用现有项目资源→显示所有受影响位置和前后引用→选择应用。保留 alt/尺寸后缀及同一行其他内容，使用解析出的具体引用范围。应用前自动刷新外部变动项，脏编辑器/冲突项先保留并跳过，其余已选且未变项经 ContentWriter 事务应用；无需为个别冲突终止全部修复。实际写入失败回滚本次正文和新资源，结果列已处理/待处理；取消不写文件，重复候选不自动删除。

### D12：只读 HTML 是一次内容快照

接入现有 `export/pdf_html.py::export_html` 和 `preview.render_markdown_html`，新增包装层支持单章/整项目、现有扫描顺序、章节锚点、图片路径复制/重写与输出清单。输出 `output/preview/<snapshot-id>/index.html`、本地 assets 与 manifest（应用/文档版本、时间、来源 hashes、警告）。不依赖网络、Word、mmdc或 WebEngine，不增加第三份 Markdown 渲染器。

导出入口明示默认采用已保存内容，有脏编辑器时提供可选“保存后导出”，不强制答确认弹窗；结果注明未包含的未保存编辑。当前不支持表达回退成可读原文，复杂表优先只读影子或说明。缺图/非法路径跳过资源复制并显示占位，包仍可打开，标带提醒/部分完成及对应章节。

目录与资源都经过包含校验，不复制整个 assets 目录或 `.state` 以防无关文件进入快照。原始 HTML/恶意脚本用既有安全渲染约束并补验证；无上传、表单、评论回流或正式页码。本版静态预览包供阅读，V2.8 再复用包装能力生成带版本/意见表单的评审包。

## Risks / Trade-offs

- [企业透明加密导致文件替换失败] → 沿用现有原子写与错误处理，验证写/删/恢复失败不会破坏正文。
- [多份历史增加磁盘使用] → 有界保留策略；回收站清理由用户操作，不按打开次数自动清空。
- [历史不是完整项目快照] → 界面明确章节恢复范围，整项目资源完整快照由 V2.9 处理。
- [没有真实 Word/安装器环境] → 完成可自动验证部分，实机项标待验收，不伪造通过。
- [扩展与后三版重复] → 预设限本机、片段限正文、HTML 限只读；规范/审批/追溯不前移。
- [批量修复或预检过期] → 输入 hash、差异计划、未保存保护与正文/新资源回滚，拒绝旧计划覆盖。
- [大纲统计拖慢输入] → 去抖、当前章计算及按实际长文样本检查，主线程不扫描全项目。

## Migration Plan

1. 只添加可兼容历史数据，不改 schema 1；首次删除/保存按新格式写。
2. 旧 `.bak`、草稿、trashPath、构建历史保留读取，迁移不批量覆盖用户文件。
3. 回退旧应用后新历史只读保留，正文仍可使用；副本恢复通过现有未保存保护。
4. 在全量测试和版本文件核对后拟定 2.6.x 下一个补丁号，实施末期统一更新，不回退到 2.6.0。
5. 新配置仅位于用户目录，新增预览/报告仅位于输出目录；已有 project.yml 不写新 schema 字段。近期任务失败不影响打开旧项目。
6. 原任务 1～6 的编号保留。新增 7～12 插在原 5/6 整版验收前执行：26-A→B→C→D→G→H→I→J→K→L→E→F。

## 验收标准

- A26-1：同一章节连续保存三次，能选择任意保存前版本，并在恢复后再恢复当前内容。
- A26-2：同路径删除、重建、再次删除，两份删除记录都可找到并安全恢复。
- A26-3：交付历史中打开产物、比较两版章节；空历史/缺失文件/损坏条目有可理解状态。
- A26-4：未保存、只读、外部占用、恢复目标冲突、资源越界均不静默覆盖。
- A26-5：普通底模、自定义样式底模、完整旧正文底模各一份通过离线自动场景；真实 Word/冻结包验收单列证据。
- A26-6：两份预设可切换；底模改动自动保留有效映射并匹配缺项；坏配置可继续，最近任务回填顺序，同名输出默认副本。
- A26-7：缺图占位、样式兜底、部分缺输入、无 Word 和预检后变化均得到可用结果及统一说明；GUI/CLI 默认 warning 返回成功，无输入/底模才停止，严格模式另测。
- A26-8：未保存标题出现在大纲，代码中的 # 不出现；点击准确定位，选区和正文统计按公开计数规则一致。
- A26-9：内置片段可插入并一次撤销；Tab 占位符工作，库导入重名可预览选择，损坏导入不覆盖旧库。
- A26-10：同一缺图可选择性修复且 alt/尺寸保留；个别来源变动跳过并继续合法项，实际写入失败/取消不破坏内容或留下无用新资源。
- A26-11：单章/整项目包断网可读；默认导出已保存内容无必答确认，缺图片/不支持块占位后继续，状态真实，schema 不变。
